# কলম — VS Code এক্সটেনশন

`.ক` ফাইলের জন্য সিনট্যাক্স হাইলাইটিং, আর `kolom-lsp` (`crates/kolom-lsp`) দিয়ে লাইভ ত্রুটি (diagnostics) — টাইপ করার সাথে সাথে lex→parse→module-resolve→sema চালিয়ে সরাসরি এডিটরে দেখায়। hover/go-to-definition এখনো নেই (`docs/roadmap.md`-এ পরবর্তী ধাপ হিসেবে তালিকাভুক্ত)।

## যা কভার করে

- সব ৪০টি কীওয়ার্ড (ঘোষণা, কন্ট্রোল ফ্লো, লজিক্যাল অপারেটর, টাইপ নাম, UI উইজেট) — `crates/kolom-lexer`-এর `KEYWORDS`-এর সাথে হাতে মিলিয়ে
- সংখ্যা লিটারেল (বাংলা `০-৯` ও ASCII `0-9`, দশমিকসহ)
- লেখা ও ক্যারেক্টার লিটারেল, এসকেপ সিকোয়েন্স (`\n \t \r \\ \" \' \u{...}`) সহ
- কমেন্ট (`//`, `/* */`)
- ফাংশন/স্ট্রাক্ট ডিক্লারেশন ও কল — `ফাংশন`/`তথ্য`-এর পরের নাম, এবং `(` -এর আগের যেকোনো আইডেন্টিফায়ার
- **লাইভ ত্রুটি (LSP)** — ফাইল খোলা, বদলানো, সেভ করা, বন্ধ করার সাথে সাথে `kolom-lsp` চলে diagnostics পাঠায়

**গুরুত্বপূর্ণ টেকনিক্যাল নোট:** বাংলা লেখায় কম্বাইনিং vowel sign (matra, যেমন ি, ে, া) ও বিরাম চিহ্ন (্) ইউনিকোডে `\p{L}` (Letter) ক্যাটাগরিতে পড়ে **না** — সেগুলো `\p{Mn}`/`\p{Mc}` (Mark)। শুধু `\p{L}` দিয়ে "শব্দ শেষ কোথায়" ঠিক করলে "ঠিকানা"-র মতো শব্দ ভুলভাবে "ঠ" + "িকানা"-এ ভেঙে যায়, আর ভেতরের "না" আলাদা কীওয়ার্ড হিসেবে ভুল রঙ পায়। তাই এই গ্রামারে identifier-boundary-এর প্রতিটি lookaround-এ `\p{L}\p{Mn}\p{Mc}\p{Nd}` ব্যবহার করা হয়েছে, শুধু `\p{L}` নয়। বাস্তব উদাহরণ (`examples/`) দিয়ে vscode-textmate/vscode-oniguruma-এর real tokenizer চালিয়ে এটি ধরা পড়েছিল ও ফিক্স করা হয়েছে — গ্রামার লিখে না দেখেই বিশ্বাস করা হয়নি।

## `kolom-lsp` কীভাবে খোঁজা হয়

সেটিংস `kolom.lspPath` খালি রাখলে এই ক্রমে খোঁজা হয় —

1. `kolom.lspPath` সেটিং, দেওয়া থাকলে
2. PATH-এ যে `kolom`/`kolom.exe` প্রথম পাওয়া যায়, তার ঠিক পাশে `kolom-lsp`/`kolom-lsp.exe` (`scripts/make-sysroot.sh` ঠিক এভাবেই দুটো বাইনারি একসাথে বান্ডল করে)
3. খালি নাম `kolom-lsp`/`kolom-lsp.exe`, যাতে PATH নিজে খুঁজে নিতে পারে

কিছু না পাওয়া গেলে বা চালানো ব্যর্থ হলে সিনট্যাক্স হাইলাইটিং স্বাভাবিকভাবেই কাজ করে — শুধু লাইভ ত্রুটি বন্ধ থাকে, আর VS Code-এ একটি স্পষ্ট এরর নোটিফিকেশন দেখায়।

## লোকাল টেস্ট

```console
cd editors/vscode
npm install
npm run compile
npx @vscode/vsce package --allow-missing-repository --skip-license
code --install-extension kolom-0.2.0.vsix
```

`.ক` ফাইল খুললে VS Code স্বয়ংক্রিয়ভাবে হাইলাইট করবে, আর `kolom-lsp` পাওয়া গেলে লাইভ ত্রুটিও দেখাবে। PATH-এ `kolom` না থাকলে ওয়ার্কস্পেস `.vscode/settings.json`-এ `"kolom.lspPath"` সরাসরি বসিয়ে দিন (Windows পাথে `/` ব্যবহার করাই নিরাপদ, `\` JSON এস্কেপ হিসেবে পড়া হতে পারে)।

## যাচাই

গ্রামার: `examples/`-এর ৮টি প্রোগ্রামের বিপরীতে vscode-textmate (VS Code নিজে যে টোকেনাইজার ব্যবহার করে) দিয়ে সরাসরি চালিয়ে যাচাই করা — স্ক্রিনশট দিয়ে "দেখতে ঠিক লাগছে" ধরনের যাচাই নয়, বরং প্রতিটি টোকেনের প্রকৃত scope মিলিয়ে।

LSP ক্লায়েন্ট: একটি real VS Code ইনস্ট্যান্সে প্যাকেজ করে ইনস্টল করে, ভুল ও সঠিক দুটো প্রোগ্রাম খুলে ম্যানুয়ালি যাচাই করা — ভুল প্রোগ্রামে ঠিক জায়গায় স্কুইগল ও lightbulb, সঠিক প্রোগ্রামে কিছুই না।

কোনো স্বয়ংক্রিয় টেস্ট এখনো `cargo test`-এর সাথে যুক্ত নয় (এই এক্সটেনশন কলম-এর Rust workspace-এর অংশ নয়), তাই গ্রামার বা ক্লায়েন্ট কোড বদলালে ম্যানুয়ালি আবার যাচাই করা প্রয়োজন।
