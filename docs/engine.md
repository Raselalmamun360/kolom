# কলম UI ও গ্রাফিক্স ইঞ্জিন (Kolom UI & Graphics Engine)

**সংস্করণ:** 1.0 Draft
**অবস্থা:** Draft

---

## ১. উদ্দেশ্য

এই ডকুমেন্ট কলম-এর নেটিভ UI ফ্রেমওয়ার্ক ও গ্রাফিক্স ইঞ্জিন নির্ধারণ করে: উইজেট, স্টেট, লেআউট, রেন্ডারিং, এবং ইভেন্ট সিস্টেম।

এটি ভাষার সিনট্যাক্স (`language.md`, `grammer.md`) বা কম্পাইলারের অভ্যন্তরীণ কাঠামো (`compiler.md`) নির্ধারণ করে **না**।

---

## ২. ওভারভিউ — ডিক্লারেটিভ মডেল (Flutter-অনুপ্রাণিত)

কলম-এর UI মডেল Flutter থেকে অনুপ্রাণিত — **ডিক্লারেটিভ (declarative)** ও উইজেট-ট্রি-ভিত্তিক —

- UI কখনো ধাপে ধাপে "তৈরি/পরিবর্তন" করা হয় না; প্রতিবার UI-এর **বর্তমান অবস্থার বর্ণনা (configuration)** দেওয়া হয়।
- `অ্যাপ` এন্ট্রির `ডিসপ্লে` ব্লক হলো উইজেট ট্রির মূল বর্ণনা; উইজেটগুলোর নেস্টিং (composition) থেকে গঠিত।
- স্টেট পরিবর্তন হলে ফ্রেমওয়ার্ক `ডিসপ্লে` বর্ণনাটি পুনরায় মূল্যায়ন (rebuild) করে, পুরোনো ট্রির সাথে তুলনা (diff) করে, এবং ন্যূনতম পরিবর্তন রেন্ডার করে।

```kolom
অ্যাপ {

    ডিসপ্লে {

        টেক্সট("স্বাগতম")

        বাটন("শুরু")

        ইনপুট()

    }

}
```

রোডম্যাপ জুড়ে ডেলিভারি ধাপে ধাপে হবে (দেখুন `roadmap.md`) —

- **সংস্করণ ০.৪** — উইন্ডো সিস্টেম, টেক্সট রেন্ডারিং, বেসিক উইজেট
- **সংস্করণ ০.৫** — লেআউট ইঞ্জিন, স্টেট ও রি-বিল্ড সাইকেল, ইভেন্ট সিস্টেম, মাউস, কীবোর্ড
- **সংস্করণ ০.৮** — অ্যানিমেশন, ক্যানভাস, ছবি, ফন্ট

## ৩. উইন্ডো সিস্টেম (সংস্করণ ০.৪)

দায়িত্ব:

- প্রতিটি `অ্যাপ` এন্ট্রি পয়েন্টের জন্য একটি নেটিভ OS উইন্ডো তৈরি ও পরিচালনা করা
- রেন্ডার লুপ নিয়ন্ত্রণ করা এবং রেন্ডারিং ব্যাকএন্ডে ফ্রেম হস্তান্তর করা

---

## ৪. উইজেট (সংস্করণ ০.৪ থেকে)

সংরক্ষিত উইজেট কীওয়ার্ড, `language.md` §১৬ অনুযায়ী —

| কীওয়ার্ড | উদ্দেশ্য |
|---------|---------|
| `ডিসপ্লে` | একটি অ্যাপের রুট UI কন্টেইনার |
| `টেক্সট` | টেক্সট লেবেল |
| `বাটন` | বাটন |
| `ইনপুট` | টেক্সট ইনপুট ফিল্ড |
| `ছবি` | ছবি |
| `সারি` | রো (সারি) লেআউট |
| `কলাম` | কলাম লেআউট |
| `কার্ড` | কার্ড কন্টেইনার |
| `ডায়ালগ` | ডায়ালগ/মোডাল |
| `স্ক্রল` | স্ক্রলযোগ্য কন্টেইনার |

নীতি:

- **কম্পোজিশন (Composition)** — জটিল UI ছোট উইজেটের নেস্টিং থেকে তৈরি; কোনো inheritance নেই।
- লিফ উইজেট (`টেক্সট`, `বাটন`, `ইনপুট`, `ছবি`) আর্গুমেন্ট নেয়; কন্টেইনার (`সারি`, `কলাম`, `কার্ড`, `ডায়ালগ`, `স্ক্রল`) অতিরিক্তভাবে নেস্টেড উইজেটের একটি `Block` নেয় (`grammer.md` §১৫.১)।

## ৫. স্টেট ও রি-বিল্ড (সংস্করণ ০.৫ — বাস্তবায়িত)

- UI স্টেট টপ-লেভেল `শেয়ার` সেলে থাকে (`language.md` §২১): `ধ্রুবক গণনা: শেয়ার সংখ্যা = শেয়ার_করো(০)`; পড়া `মান(x)`, লেখা `বসাও(x, v)`।
- হ্যান্ডলার = শূন্য-প্যারামিটার টপ-লেভেল ফাংশন, `বাটন("লেখা", ফাংশন_নাম)`-এর দ্বিতীয় আর্গুমেন্টে বাঁধা।
- ক্লিকের পরে ফ্রেমওয়ার্ক: হ্যান্ডলার চালায় → `ডিসপ্লে` ব্লক সম্পূর্ণ পুনঃমূল্যায়ন (উইজেট ট্রি নতুন করে নির্মাণ) → repaint। এটিই Flutter-এর setState-চক্রের কলম-রূপ।
- `ইনপুট` ফিল্ড নিজে এডিটযোগ্য (ফোকাস + কীবোর্ড); রি-বিল্ডে ইনপুট-বাফার রিসেট হয় — স্থায়ী ইনপুট-মান ভবিষ্যৎ বাইন্ডিং সিনট্যাক্সের কাজ।

---

## ৬. লেআউট ইঞ্জিন (সংস্করণ ০.৫)

দায়িত্ব:

- `সারি` (অনুভূমিক flex) ও `কলাম` (উল্লম্ব flex) কম্পোজিশন থেকে উইজেটের আকার ও অবস্থান নির্ধারণ করা
- কন্টেন্ট-চালিত সাইজিং (টেক্সট, ছবি) এবং কন্টেইনার সীমাবদ্ধতা সমর্থন করা

---

## ৭. ইভেন্ট সিস্টেম (সংস্করণ ০.৫)

দায়িত্ব:

- পয়েন্টারের নিচে থাকা উইজেটে মাউস ইভেন্ট (ক্লিক, হোভার, ড্র্যাগ) পাঠানো
- ফোকাসে থাকা উইজেটে কীবোর্ড ইভেন্ট (কী প্রেস, টেক্সট ইনপুট) পাঠানো
- কলম কোড থেকে বাইন্ড করার জন্য একটি কলব্যাক/হ্যান্ডলার মেকানিজম প্রদান করা

যে স্টেট একাধিক কলব্যাক বা উইজেট থেকে অ্যাক্সেস করা প্রয়োজন (যেমন একটি কাউন্টার, একাধিক বাটনের হ্যান্ডলার শেয়ার করে), সেটি `শেয়ার Type`-এ রাখা উচিত (`language.md` §২২.৪) — কলম-এর ওনারশিপ মডেলে সাধারণ (নন-শেয়ার্ড) ভ্যালু একাধিক দীর্ঘস্থায়ী মালিকের মধ্যে ভাগ করা যায় না।

## ৮. রেন্ডারিং ব্যাকএন্ড

দায়িত্ব:

- টেক্সট রেন্ডারিং (সংস্করণ ০.৪): ফন্ট লোডিং ও গ্লিফ র‍্যাস্টারাইজেশন। বাংলা একটি জটিল স্ক্রিপ্ট — তাই **শেপিং (shaping)** আবশ্যক: যুক্তাক্ষর, কার/চন্দ্রবিন্দু-সহ মাত্রার অবস্থান ও রিঅর্ডারিং সঠিকভাবে সমর্থন করতে হবে (HarfBuzz-জাতীয় শেপিং ইঞ্জিন)
- ক্যানভাস ও ছবি (সংস্করণ ০.৮): স্বাধীন 2D ড্রয়িং ও ছবি প্রদর্শন
- ফন্ট (সংস্করণ ০.৮): সিস্টেম ডিফল্টের বাইরে কাস্টম ফন্ট লোডিং
- অ্যানিমেশন (সংস্করণ ০.৮): উইজেটের জন্য সময়-চালিত প্রপার্টি ইন্টারপোলেশন

## ১১. বাস্তবায়ন সিদ্ধান্ত — প্রাথমিক ডেস্কটপ ব্যাকএন্ড

সিদ্ধান্ত (v0.4): **Windows-first** — Win32 + GDI, টেক্সট শেপিংয়ে Uniscribe (রানটাইমে `LoadLibrary("usp10.dll")` — কোনো ইমপোর্ট লাইব্রেরি লাগে না)।

কারণ —

- শূন্য এক্সটার্নাল ডিপেন্ডেন্সি: `windows-sys` দিয়ে সরাসরি user32/gdi32/usp10 সিস্টেম DLL-এর বাইন্ডিং, কোনো C টুলচেইন ছাড়াই (রানটাইম এখন `crates/kolom-runtime`-এ একবার কম্পাইল হওয়া Rust কোড, `compiler.md` §৭.১)
- SSA_FALLBACK-সহ বাংলা যুক্তাক্ষর/মাত্রা সঠিকভাবে শেপ হয়
- X11/Wayland ও macOS ব্যাকএন্ড সংস্করণ ০.৬-এ; উইজেট/লেআউট স্তর ব্যাকএন্ড-নিরপেক্ষ

v0.5 বাস্তবায়ন বিবরণ —

- **উইজেট ট্রি**: প্রতিটি রি-বিল্ডে `ডিসপ্লে` ব্লক পুনঃমূল্যায়ন করে নতুন ট্রি; লেআউট+পেইন্ট এক রিকার্সিভ পাসে, প্রতিটি নোডের RECT হিট-টেস্টের জন্য সংরক্ষিত
- **লেআউট**: রুট = উল্লম্ব কলাম; `সারি` = সম-প্রস্থ অনুভূমিক বিভাজন, `কলাম` = উল্লম্ব স্তূপ; কন্টেন্ট-চালিত সাইজিং v0.6+
- **ইনপুট**: ক্লিকে ফোকাস, WM_CHAR-এ এডিট (ব্যাকস্পেসসহ); রি-বিল্ডে বাফার রিসেট (§৫)
- **টেস্টিং হুক**: `KLOM_UI_AUTOCLOSE_MS` + `KLOM_UI_SCRIPT_CLICKS="0,1"` — headless ক্লিক-সিমুলেশন
