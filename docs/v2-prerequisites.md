# কলম v2.0 (সেলফ-হোস্টেড টুলচেইন) — প্রি-রিকুইজিট পরিকল্পনা

এই ডকুমেন্ট বলে — **v2.0 (সেলফ-হোস্টিং) শুরু করার আগে** বর্তমান Rust কম্পাইলারেই (v1.x) কী কী শেষ করে রাখা দরকার, যাতে সেলফ-হোস্টেড কম্পাইলার লেখা শুরু হওয়ার পর ভাষা বা ABI বদলাতে গিয়ে কাজ আবার লিখতে না হয়। `roadmap.md` §১৪-এর সাথে পড়ুন — এখানে সেই সেকশনের প্রিরিকুইজিট বিস্তারিতভাবে বর্ণনা করা হয়েছে।

**নীতি** — প্রতিটা আইটেম v1.x-এর মধ্যেই, Rust কম্পাইলারের ছয়টা ক্রেট জুড়ে (`kolom-lexer` → `kolom-syntax` → `kolom-sema` → `kolom-interp` → `kolom-codegen-cranelift` → `kolom-runtime`) যোগ করা হবে। লক্ষ্য: v2.0 শুরু হওয়ার সময় ভাষা ও ABI স্থির থাকবে।

## ১. এনাম / সাম-টাইপ (ADT)

**অবস্থা:** ✅ ইন্টারপ্রেটেড (`কলম চালাও`)-এ বাস্তবায়িত — `এনাম` ঘোষণা, ভ্যারিয়েন্ট কনস্ট্রাক্টর, `শেয়ার`-এর মাধ্যমে রিকার্সিভ এনাম (AST-ধাঁচের), আর exhaustiveness-checked `মিলাও` এক্সপ্রেশন সবই কাজ করে (§২ দেখুন — দুটো একসাথে যোগ হয়েছে)। বিস্তারিত ব্যবহারকারী-স্তরের ডকুমেন্টেশন `language.md` §২৩.১-এ। ⏳ **নেটিভ কোডজেন (`কলম বিল্ড`) এখনো বাকি** — `EnumLayout`/ট্যাগড-ইউনিয়ন মেমরি লেআউট, ট্যাগ-সুইচ-ভিত্তিক `মিলাও` লোয়ারিং, ও ডিসক্রিমিন্যান্ট-অ্যাওয়্যার ড্রপ জেনারেশন `kolom-codegen-cranelift`-এ যোগ করা বাকি (আপাতত `মিলাও`/এনাম-নির্মাণ নেটিভ বিল্ডে স্পষ্ট কম্পাইল-টাইম ত্রুটি দেয়, ক্র্যাশ করে না)।

**কেন** — AST নোড (`Expr`, `Stmt`, `Type`) রিপ্রেজেন্ট করার একমাত্র স্বাভাবিক উপায়। এখনকার `তথ্য`+ম্যানুয়াল-ট্যাগ পদ্ধতিতে কম্পাইলার লিখলে ভুল ট্যাগ-চেক একটা রানটাইম বাগ হয়ে ছড়িয়ে থাকবে সারা কোডবেসে।

**প্রস্তাবিত সিনট্যাক্স** (তথ্যর constructor-স্টাইলের সাথে সামঞ্জস্যপূর্ণ) —

```kolom
এনাম আকৃতি {
    বৃত্ত(দশমিক),
    আয়তক্ষেত্র(দশমিক, দশমিক),
    বিন্দু
}
```

- ভ্যারিয়ান্টে পজিশনাল পেলোড (তথ্যর মতো), পেলোড-বিহীন ভ্যারিয়ান্টও বৈধ (`বিন্দু`)।
- মেমরি: রিকার্সিভ এনাম (যেমন `Expr` নিজেই `Expr`-ধারণ করা, AST-র জন্য অপরিহার্য) `শেয়ার` দিয়ে — `language.md` §২৩-এর নোড/লিংকড-লিস্ট নিয়মের মতোই।

**স্পর্শ করবে** — lexer (নতুন কীওয়ার্ড), syntax (নতুন ঘোষণা + কনস্ট্রাক্টর-কল পার্সিং, তথ্যর সাথে শেয়ার করা কোড), sema (ভ্যারিয়ান্ট টাইপচেক, tag রেজোলিউশন), interp+codegen (ট্যাগড-ইউনিয়ন লেআউট/ডিসপ্যাচ, RC/ownership নিয়ম তথ্যর প্যাটার্ন অনুসরণ করে)।

## ২. প্যাটার্ন ম্যাচিং

**অবস্থা:** ✅ এনাম-ভ্যারিয়েন্ট ম্যাচিং হিসেবে বাস্তবায়িত (§১ দেখুন) — ইন্টারপ্রেটেড মোডে। এই ডকুমেন্টে প্রস্তাবিত সিনট্যাক্সই (`মিলাও ... { pattern => expr }`) হুবহু বাস্তবায়িত হয়েছে, exhaustiveness checking সহ। সাধারণীকৃত প্যাটার্ন ম্যাচিং (লিটারেল প্যাটার্ন, অ্যারে-ডিস্ট্রাকচারিং, গার্ড) এখনো বাইরে — শুধু এনাম-ভ্যারিয়েন্ট প্যাটার্ন সমর্থিত।

**কেন** — AST ওয়াকিং, প্রতিটা visitor-এর মূল ভিত্তি। এনামের সাথে একসাথে ডিজাইন করা জরুরি — একটা ছাড়া আরেকটার দরকারই পড়ে না।

**প্রস্তাবিত সিনট্যাক্স** —

```kolom
ধরি ক্ষেত্রফল = মিলাও আকৃতি {
    বৃত্ত(ব্যাসার্ধ) => গণিত.পাই * ব্যাসার্ধ * ব্যাসার্ধ,
    আয়তক্ষেত্র(দৈর্ঘ্য, প্রস্থ) => দৈর্ঘ্য * প্রস্থ,
    বিন্দু => ০,
}
```

- `মিলাও` একটা এক্সপ্রেশন (রিটার্ন-ভ্যালু আছে) — `যদি/অন্যথায়` এক্সপ্রেশনের মতো একই প্যাটার্নে।
- **exhaustiveness checking sema-তে বাধ্যতামূলক** — একটা ভ্যারিয়ান্ট মিস করলে কম্পাইল-টাইম এরর। এটা ownership-checker-এর মতোই কঠোরতায় রাখা উচিত, কারণ কম্পাইলার লেখার সময় exhaustiveness-এর অভাবই সবচেয়ে বেশি সাইলেন্ট বাগ তৈরি করে।

**স্পর্শ করবে** — একই ছয় ক্রেট; sema-তে সবচেয়ে বেশি কাজ (exhaustiveness algorithm)।

## ৩. প্রথম-শ্রেণির ফাংশন / ক্লোজার

**অবস্থা:** ⚠️ আংশিক — ইন্টারপ্রেটেড মোডে ফাংশন-*রেফারেন্স* বাস্তবায়িত (`Value::Func(Rc<FuncDecl>)`, ইতিমধ্যে-ঘোষিত `ফাংশন`-এর নামের পয়েন্টার হিসেবে): ভ্যারিয়েবলে রাখা, প্যারামিটার/রিটার্ন-টাইপ হিসেবে পাস করা, অ্যারেতে রাখা, আর ভ্যারিয়েবলের মাধ্যমে পরোক্ষ কল — সবই কাজ করে, টেবিল-ড্রিভেন ডিসপ্যাচ যাচাই করা হয়েছে। ফাংশন-টাইপ সিনট্যাক্স `(টাইপ, ...) -> টাইপ`। ব্যবহারকারী-স্তরের ডকুমেন্টেশন `language.md` §১১.১-এ, যেখানে অ্যারে-অফ-ফাংশন টাইপ-অ্যানোটেশনের একটা পরিচিত পার্সিং-অস্পষ্টতাও নথিভুক্ত (ইনফারেন্স দিয়ে এড়ানো যায়)। ❌ **এখনো নেই: সত্যিকারের ক্লোজার** — অ্যানোনিমাস ফাংশন লিটারেল বা এনক্লোজিং-স্কোপ ক্যাপচার কোনোটাই সমর্থিত না; এর জন্য ইন্টারপ্রেটারের স্কোপ রিপ্রেজেন্টেশন (`Vec<Scope>`, নন-শেয়ার্ড) `Rc<RefCell<Scope>>`-এ রিফ্যাক্টর করা দরকার হবে যাতে একটা ক্লোজার তার তৈরির সময়কার এনক্লোজিং স্কোপ ফাংশনটা রিটার্ন হয়ে যাওয়ার পরেও ধরে রাখতে পারে — এটা একটা আলাদা, বড় ফলো-আপ। ⏳ নেটিভ কোডজেন বাকি (§১-এর মতোই — গ্রেসফুলি ব্যর্থ হয়, প্যানিক করে না)।

**কেন** — টেবিল-ড্রিভেন ডিসপ্যাচ (যেমন টোকেন-টাইপ → পার্স-ফাংশন ম্যাপিং), visitor callback।

**প্রস্তাবিত সিনট্যাক্স** —

```kolom
ধরি বর্গ: (সংখ্যা) -> সংখ্যা = ফাংশন(x: সংখ্যা) -> সংখ্যা { রিটার্ন x * x }
লেখো(লেখায়(বর্গ(৫)))
```

- ফাংশন-টাইপ `(প্যারাম-টাইপ...) -> রিটার্ন-টাইপ` — টাইপ-অ্যানোটেশনে ব্যবহারযোগ্য।
- ক্লোজার ক্যাপচার: শুরুতে শুধু **by-share ক্যাপচার** (তথ্যর `শেয়ার` মেকানিজম পুনর্ব্যবহার) — by-move ক্যাপচার পরের সংস্করণে, স্কোপ ছোট রাখতে।

**স্পর্শ করবে** — runtime-এ সবচেয়ে বেশি প্রভাব (ফাংশন-পয়েন্টার + ক্যাপচারড-এনভায়রনমেন্ট রিপ্রেজেন্টেশন — Cranelift কোডজেনে closure-as-struct লোয়ারিং)।

## ৪. জেনারিক্স

**অবস্থা:** ⚠️ আংশিক (টাইপ-ইরেজার-ভিত্তিক) — ইন্টারপ্রেটেড মোডে `তথ্য<T>`/`এনাম<T>`/`ফাংশন<T>` সবই বাস্তবায়িত, আর্গুমেন্ট থেকে টাইপ-ইনফারেন্স সহ (`বাক্স(৪২)` থেকে `T = সংখ্যা` অনুমিত, এক্সপ্লিসিট instantiation সিনট্যাক্স নেই — ইচ্ছাকৃতভাবে, কারণ `<`/`>` এক্সপ্রেশন-পজিশনে তুলনা অপারেটরের সাথে সংঘর্ষ করত)। একটা generic struct + generic enum (Option-ধাঁচের `বিকল্প<T>`) + generic function (array param সহ) একসাথে টেস্ট করা হয়েছে (golden test `53_generics`)। ব্যবহারকারী-স্তরের ডকুমেন্টেশন `language.md` §২৩.২-এ।

**⚠️ সাউন্ড নয় — টাইপ-ইরেজার, মনোমরফাইজেশন নয়।** এই প্রি-রিকুইজিট ডকের নিচের "প্রস্তাবিত সিনট্যাক্স" অংশে Rust-স্টাইল মনোমরফাইজেশনের কথা বলা ছিল (প্রতি-instantiation কোড-জেনারেশন) — বাস্তবায়ন সেই পথে যায়নি, সরল টাইপ-ইরেজার বেছে নেওয়া হয়েছে: জেনারিক ডিক্লারেশনের বডি একবারই চেক হয়, `T`-এর প্রতিটা occurrence `Ty::Unknown` (পোয়িজনড, সবকিছুর সাথে unify হয়) হিসেবে resolve হয়। ফল: কনটেইনার/ফাংশনের কাঠামো (arity, রিকার্সিভ গঠন) চেক হয়, কিন্তু পেলোডের প্রকৃত টাইপ ক্রস-চেক হয় না — `বাক্স<সংখ্যা>`-তে ভুলবশত `লেখা` বসালেও কম্পাইল-টাইম ত্রুটি ধরা পড়বে না। কারণ: মনোমরফাইজেশনের জন্য মূলত নেটিভ কোডজেন-লেভেল কাজ দরকার (প্রতি-instantiation আলাদা কোড) যেটা এখনো বাকি (নিচে দেখুন); ইন্টারপ্রেটেড মোডে যেহেতু রানটাইমে টাইপ-নিরপেক্ষ (`তথ্য` এমনিতেই `Value::Map`-এ রিপ্রেজেন্টেড), সাউন্ড জেনারিক্সের জন্য মনোমরফাইজেশনের আসল প্রয়োজনটাই মূলত নেটিভ কোডজেনে, যেখানে এখনো ধরাই হয়নি।

⏳ নেটিভ কোডজেন বাকি (§১/§৩-এর মতোই — গ্রেসফুলি ব্যর্থ হয় "অজানা struct 'T'" দিয়ে, প্যানিক করে না)। মনোমরফাইজেশন-ভিত্তিক (সাউন্ড) জেনারিক্স তখনই আসল অর্থ পাবে যখন নেটিভ কোডজেন যোগ হবে — প্রতিটা concrete instantiation-এর জন্য আলাদা স্ট্রাক্ট-লেআউট/কোড জেনারেট করে।

**কেন** — টাইপ-নিরাপদ কন্টেইনার (টোকেন-লিস্ট, সিম্বল-টেবিল)। এটা ছাড়া কম্পাইলার নিজেই "AnyValue" ধরনের আনটাইপড অ্যারে দিয়ে লেখা লাগবে — একটা কম্পাইলারের জন্য বিশেষভাবে বিপজ্জনক, কারণ এটা নিজেই টাইপ-সেফটির উদাহরণ হওয়া দরকার।

**প্রস্তাবিত সিনট্যাক্স** —

```kolom
তথ্য বাক্স<T> { মান: T }
এনাম বিকল্প<T> { কিছু(T), কিছুই_না }
ফাংশন প্রথম<T>(তালিকা: T[]) -> বিকল্প<T> { ... }
```

- **স্কোপ ছোট রাখুন**: শুধু মনোমরফাইজেশন (Rust-স্টাইল, প্রতি-instantiation কোড জেনারেট)। ট্রেইট-বাউন্ড/ইন্টারফেস-জেনারিক্স v2.0-এর বাইরে রাখুন — সেটা `language.md` §১৯-এ আলাদা, বড় ফিচার হিসেবেই তালিকাভুক্ত।

**স্পর্শ করবে** — sema (টাইপ-প্যারামিটার রেজোলিউশন), codegen (মনোমরফাইজেশন পাস — প্রতিটা concrete instantiation-এর জন্য আলাদা কোড)।

## ৫. এক্সটার্ন / FFI — কলম থেকে Rust ফাংশন কল

**অবস্থা:** ✅ নেটিভ কোডজেনে বাস্তবায়িত (এখানে ব্যতিক্রম — §১/§৩/§৪ ইন্টারপ্রেটেড-ফার্স্ট ছিল, এটা কোডজেন-ফার্স্ট, কারণ C ABI extern কল Cranelift-এর নিজস্ব `declare_import` মেকানিজমের সাথে স্বাভাবিকভাবেই মেলে — ইন্টারপ্রেটারের কোনো C ABI মার্শালিং লেয়ার নেই বলে সেখানে বাস্তবায়ন করাটা এই স্কোপে অনেক বেশি কাজ হতো)। `এক্সটার্ন "C" { ফাংশন name(টাইপ প্যারাম, ...) -> টাইপ }` — বডি-বিহীন সিগনেচার, sema `self.funcs`-এর একই টেবিলে রেজিস্টার করে (তাই কল-সাইটে কোনো স্পেশাল-কেসিং লাগে না, সাধারণ ফাংশন-কলের মতোই arity/টাইপ-চেক হয়), কোডজেনে `Linkage::Import`-এ ডিক্লেয়ার হয়ে ordinary `FuncInfo`-র মতোই `gen.funcs`-এ ঢোকে — `lower_call` কোনো পরিবর্তন ছাড়াই কাজ করে, যেহেতু Cranelift-এর `call` ইনস্ট্রাকশন Local/Import উভয় লিংকেজেই একইভাবে কাজ করে।

**যাচাই করা হয়েছে বাস্তব লিংকিং দিয়ে** — একটা ইতিমধ্যে-লিংকড kolom-runtime সিম্বল (`kl_math_factorial`) `এক্সটার্ন` দিয়ে ঘোষণা করে natively বিল্ড করে চালিয়ে সঠিক ফল পাওয়া গেছে (`build_standalone.rs`-এ `build_extern_ffi_links_and_calls_real_symbol` টেস্ট — নিছক টাইপ-চেক নয়, আসল লিংকার-লেভেল প্রমাণ)। ইন্টারপ্রেটারে একই প্রোগ্রাম চালালে স্পষ্ট, নির্দিষ্ট ত্রুটি দেয় ("শুধু নেটিভ কম্পাইলে কল করা যায়") — সাধারণ "অজানা ফাংশন" নয়। শুধু `"C"` ABI সমর্থিত, ভুল ABI বা নাম-সংঘর্ষে পরিষ্কার sema ত্রুটি। কোনো ডায়নামিক লাইব্রেরি লোডিং (dlopen/DLL) নেই — যা ইতিমধ্যে স্ট্যাটিকালি লিংকড, শুধু তার সিম্বলই কল করা যায়। ব্যবহারকারী-স্তরের ডকুমেন্টেশন `language.md` §১১.২-এ, একটা নিরাপত্তা নোট সহ (ঘোষিত সিগনেচার আসল নেটিভ ফাংশনের সাথে মেলে কিনা কম্পাইলার যাচাই করে না — Rust-এর `unsafe extern`-এর মতোই ব্যবহারকারীর দায়িত্ব)।

**কেন** — v2.0-এর "প্র্যাগম্যাটিক" ধাপে কলমে-লেখা ফ্রন্টএন্ডকে Cranelift/rust-lld শিম কল করতে হবে। মেকানিজম ইতিমধ্যেই প্রমাণিত — stdlib-এর প্রতিটা ফাংশন এখনই `kolom-runtime`-এ `#[no_mangle] extern "C"` হিসেবে লেখা এবং কলম কোড থেকে কল হচ্ছে। এখন শুধু এটা **ইউজার-লেভেলে উন্মুক্ত** করতে হবে (এখন এটা compiler-internal, শুধু বিল্ট-ইন stdlib মডিউলের জন্য স্পেশাল-কেসড)।

**প্রস্তাবিত সিনট্যাক্স** —

```kolom
এক্সটার্ন "C" {
    ফাংশন kl_cg_compile(সোর্স: লেখা) -> সংখ্যা
    ফাংশন kl_link(অবজেক্ট_পাথ: লেখা, আউটপুট_পাথ: লেখা) -> সংখ্যা
}
```

- ABI: C ABI (Rust-এর `extern "C"` এর সাথে সরাসরি মেলে — নতুন কোনো ABI ডিজাইন করা লাগবে না)।
- টাইপ-ম্যাপিং টেবিল দরকার sema-তে: `লেখা ↔ kl_str`, `সংখ্যা ↔ i64`, `দশমিক ↔ f64` ইত্যাদি — এগুলো runtime-এ ইতিমধ্যেই সংজ্ঞায়িত (`kolom-runtime/src/lib.rs`), শুধু sema-কে সেগুলো ইউজার-ঘোষিত extern ফাংশনে চেক করাতে শেখাতে হবে।
- **নিরাপত্তা নোট**: `এক্সটার্ন` ব্লক ownership-checker-এর আওতার বাইরে (Rust-এর `unsafe`-এর মতো) — এটা ডকুমেন্টেশনে স্পষ্ট করে লিখুন, যাতে ভবিষ্যতে কনট্রিবিউটররা ভুল না বোঝেন।

**স্পর্শ করবে** — syntax (নতুন ঘোষণা-ফর্ম), sema (টাইপ-ম্যাপিং যাচাই), codegen (সরাসরি C-কলিং-কনভেনশন কল এমিট), CLI/linker (extern-লিংকড সিম্বল রেজোলভ করা বিল্ড-টাইমে)।

## ৬. স্পেসিফিকেশন ফিচার-ফ্রিজ

**অবস্থা:** ✅ **বন্ধ — ফ্রিজ ঘোষিত ২০২৬-০৯-০৮** (ট্যাগ `v1.5-frozen`)। উইন্ডো শুরু হয়েছিল ২০২৬-০৯-০১-এ (checkpoint `v2-prereqs-lang-complete`-এর পর), অর্থাৎ ক্যালেন্ডারে ৮ দিন চলেছে — মূল পরিকল্পনার ২–৩ সপ্তাহ নয়। **এটা একটা সচেতন সিদ্ধান্ত, সময় পেরোনো নয়**, তাই রেকর্ডে স্পষ্ট থাকল: উইন্ডোর উদ্দেশ্য ছিল ভাষা স্থির কি না তা প্রমাণ করা, আর দুটো পাসে মোট ১১টা আসল বাগ/সংঘর্ষ ধরা পড়ে ফিক্স হয়েছে — যার সবগুলোই বাগফিক্স বা সীমাবদ্ধতা-শিথিলকরণ, একটাও নতুন সিনট্যাক্স নয়, তাই উইন্ডো রিসেট হয়নি। দ্বিতীয় পাসের প্রতিটা আবিষ্কার এসেছে **আসল টার্গেট-প্রোগ্রামটা লিখে** (একটা দুই-মডিউল টোকেন-মডেল + লেক্সার), চুপচাপ অপেক্ষা করে নয় — বাকি ক্যালেন্ডার-সময়টা তাই M1 (লেক্সার পোর্ট) করতে ব্যয় করাই বেশি কার্যকর, কারণ পোর্ট করাই বাগ বার করে।

কোড-সাইড ডকুমেন্টেশন অংশ সম্পূর্ণ।

- `language.md`/`grammer.md`/`compiler.md`-এ প্রতিটা নতুন ফিচার ডকুমেন্ট করুন। ✅ তিনটাই সম্পূর্ণ — `language.md` (§১১.১, §১১.২, §২৩.১, §২৩.২), `grammer.md`-এর ফরমাল EBNF (§৯.১, §১০.৩, §১০.৬–১০.৮, §১১.১, §১১.৭–১১.৮, §১৩.৩ — প্লাস দুটো stale "future feature" রেফারেন্স ফিক্স), আর `compiler.md`-এর §৯.১–৯.৪ (কম্পাইলার-আর্কিটেকচার লেভেলে — sema-র টাইপ-ইরেজার ডিজাইন, `unify()`-এর রিকার্সিভ-জেনারেলাইজেশন, ইন্টারপ্রেটারের `Value::Enum` discriminant প্রয়োজনীয়তা, `এক্সটার্ন`-এর কোডজেন-ফার্স্ট যুক্তি, ও এনামের ডিজাইন-করা-কিন্তু-অবাস্তবায়িত নেটিভ ট্যাগড-ইউনিয়ন লেআউট)।
- **স্টেবিলাইজেশন পাসে যা ধরা পড়েছে ও ফিক্স হয়েছে** (ভাষার সিনট্যাক্স/সিমান্টিক্স বদলায়নি, শুধু বাগফিক্স) —
  1. **স্ট্যাক ওভারফ্লো ক্র্যাশ — দুই ব্যাকএন্ডেই।** ইন্টারপ্রেটারে: একটা সাধারণ রিকার্সিভ ফাংশন ডিবাগ-বিল্ডে মাত্র ~৫০ ফ্রেমেই ক্র্যাশ করত (undefined behavior, ধরার-যোগ্য এরর না)। `কলম চালাও`/`কলম পাতা` এখন ইন্টারপ্রেটার একটা ৫১২MB স্ট্যাক-সহ ডেডিকেটেড থ্রেডে চালায় (~২০০-৪০০x গভীরতর রিকার্শন সহ্য করে)। **নেটিভ কোডজেনেও পাওয়া গেছে (পরের অডিট রাউন্ডে)** — একটা natively-compiled প্রোগ্রাম PE-র ডিফল্ট স্ট্যাক-রিজার্ভে (~1MB) মাত্র ~১৫,০০০-২৫,০০০ ফ্রেমেই সাইলেন্টলি ক্র্যাশ করত (`STATUS_STACK_OVERFLOW`, কোনো বার্তা ছাড়াই — নেটিভ কোডে ইন্টারপ্রেটারের মতো guard-page হ্যান্ডলার নেই)। এটা v2.0-এর জন্য বিশেষভাবে গুরুত্বপূর্ণ ছিল ধরা, কারণ সেলফ-হোস্টেড কম্পাইলার শেষ পর্যন্ত **নেটিভ** কম্পাইল হয়ে চলবে (সেটাই সেলফ-হোস্টিং-এর মূল উদ্দেশ্য), আর নিজের সোর্স parse/AST-walk করার সময় ঠিক এই প্যাটার্নের রিকার্শনই করবে। ফিক্স: `kolom-codegen-cranelift/src/link.rs`-এ Windows link কমান্ডে `--stack 67108864` (৬৪MB রিজার্ভ) যোগ — হাতে-যাচাই করা ১০,০০,০০০ ফ্রেম পর্যন্ত (আগের ~15,000-25,000-এর তুলনায় ~৪০-৬৫x), স্থায়ী রিগ্রেশন-টেস্ট `build_deep_recursion_does_not_overflow_native_stack`-এ ১,০০,০০০ ফ্রেমে লক করা। Linux/Android টার্গেট ছোঁয়া হয়নি — ওগুলোয় স্ট্যাক-সাইজ সাধারণত OS ulimit দিয়ে নিয়ন্ত্রিত, ইতিমধ্যেই অনেক বেশি উদার (~8MB ডিফল্ট), আর PE-স্টাইল link-টাইম রিজার্ভ-ফিল্ডের সরাসরি সমতুল্য নেই।
  2. **`মিলাও`-তে unreachable arm** — `_`-এর পরের যেকোনো শাখা (আরেকটা `_` সহ) নীরবে গ্রহণ করা হতো, কখনো না চালিয়েই। এখন sema ত্রুটি।
  3. **ফ্লেকি টেস্ট** — `console_examples_agree_between_backends` (লাইভ টাইমস্ট্যাম্প তুলনা করত দুটো সাবপ্রসেসের মধ্যে, সেকেন্ড-বাউন্ডারি ক্রস করলে ব্যর্থ হতো) — টাইমস্ট্যাম্প লাইন তুলনার আগে ব্ল্যাংক-আউট করে ফিক্স করা হয়েছে।
  4. **`অক্ষর` (char) অর্ডারিং একেবারেই ছিল না** — `==`/`!=` কাজ করত, কিন্তু `<`/`>`/`<=`/`>=` না ("তুলনায় সংখ্যা বা লেখা প্রত্যাশিত")। এটা একটা সত্যিকারের ব্লকার হতো একটা কলমে-লেখা লেক্সারের জন্য — `kolom-lexer`-এর নিজস্ব `is_bangla_block`/`is_ident_start`/digit-classification সবই ঠিক এই কৌশলে লেখা (`c >= '\u{0980}' && c <= '\u{09FF}'`-স্টাইল রেঞ্জ-চেক)। sema-তে `Ty::Ch`-এর জন্য Rust-এর `char: Ord`-এর মতোই অর্ডিনাল (Unicode scalar value অনুযায়ী) তুলনা যোগ, ইন্টারপ্রেটারে মিলিয়ে (golden test `57_char_ordering`)। **নেটিভ কোডজেন ছোঁয়া হয়নি** — `অক্ষর` টাইপ ইতিমধ্যেই নেটিভ কোডজেনে সম্পূর্ণভাবে অসমর্থিত (এমনকি একটা char *লিটারেল*ও কম্পাইল হয় না — `"এই ধরনের literal এখনো সমর্থিত নয়"`), এই সেশনের বাকি ফিচারগুলোর চেয়েও পুরনো ও বড় একটা প্রি-এক্সিস্টিং গ্যাপ, v2.0-প্রিরিকুইজিটের স্কোপের বাইরে — যদি কখনো একটা কলমে-লেখা লেক্সার নেটিভ কম্পাইল করতে হয়, `অক্ষর`-এর সম্পূর্ণ নেটিভ সাপোর্ট (literal, সব অপারেটর, string থেকে char এক্সট্র্যাকশন) তখন আলাদাভাবে দরকার হবে।
  5. **অ্যারে-বিল্ডিং O(n²) — আর তারপর একটা নিজের-হাতে-বানানো মেমরি-করাপশন বাগ।** `arr = arr + [item]` (লিস্ট বানানোর একমাত্র আগের উপায়) প্রতিবার পুরো অ্যারে কপি করে — মেপে দেখা গেছে ৪০,০০০ এলিমেন্টে ~১৩ সেকেন্ড, পরিষ্কার O(n²)। একটা সেলফ-হোস্টেড লেক্সারের টোকেন-লিস্ট/পার্সারের AST-নোড-লিস্টের জন্য এটা অব্যবহারযোগ্য। **ফিক্স হিসেবে নতুন `যোগ_করো(arr, item)` builtin যোগ করার প্রথম চেষ্টা নিজেই একটা রিয়েল বাগ ছিল** — `kolom-runtime`-এর বিদ্যমান `kl_arr_push` fixed-capacity (কলার-গ্যারান্টিড `len < cap`, শুধু array-লিটারেল বানাতে ব্যবহৃত, কখনো grow করে না) পুনর্ব্যবহার করেছিলাম এই ভুল ধারণায় যে এটা already general-purpose — ৩টা পুশ "কাজ করেছিল" (undefined behavior যেটা ছোট overwrite-এ বেঁচে যায়), ১০,০০০-এ `STATUS_HEAP_CORRUPTION`-এ ক্র্যাশ করেছে। ফিক্স: নতুন `kl_arr_push_grow` রানটাইম ফাংশন (আসল amortized-doubling growth, Rust-এর `Vec::push`-এর মতোই), যেটা (সম্ভাব্য-বদলে-যাওয়া) পয়েন্টার রিটার্ন করে যা কোডজেন `def_var` দিয়ে ভ্যারিয়েবলে ফিরিয়ে লেখে — ঠিক `lower_assign`-এর ম্যাপ ইনডেক্স-অ্যাসাইনমেন্ট কেসে যেভাবে ইতিমধ্যেই করা হয় (map insert-ও রিলোকেট করতে পারে)। ২,০০,০০০ heap-backed (`লেখা`) এলিমেন্টে যাচাই করা — ইন্টারপ্রেটেড ও নেটিভ দুই ব্যাকএন্ডেই, ০.০১ সেকেন্ডের কম, স্থায়ী রিগ্রেশন-টেস্ট `build_array_push_grows_correctly_at_scale`-এ লক করা। ৪০,০০০ এলিমেন্টে আগে ~১৩s, এখন ~০.০০২s — প্রায় ৬৫০০x।
- **স্টেবিলাইজেশন উইন্ডোর দ্বিতীয় পাস — ২০২৬-০৯-০৮** (একইভাবে: কোনো নতুন সিনট্যাক্স নয়, সব বাগফিক্স বা সীমাবদ্ধতা-শিথিলকরণ)। পদ্ধতি ছিল একটাই — **self-hosting-plan.md §৬-এর ধাপ ২–৩ আসলেই লিখে ফেলা** (একটা টোকেন-মডেল, তারপর একটা দুই-মডিউল লেক্সার যা কীওয়ার্ড-ম্যাপ, স্প্যান, স্ট্রিং-লিটারেল ও ডায়াগনস্টিক-রিকভারি সহ চলে) আর যা যা ভাঙে তা ফিক্স করা। চেকলিস্ট পড়ে একটাও ধরা পড়ত না —
  6. **`এনাম` একটা `তথ্য`-র ফিল্ড-টাইপ হতে পারত না।** `enum_names` সংগ্রহের পাসটা স্ট্রাক্ট-ফিল্ডের টাইপ রিজলভ করার *পরে* চলত, তাই `resolve_type` কখনো এনামগুলো দেখতে পেত না — অর্থাৎ `তথ্য টোকেন { ধরন: টোকেন_ধরন }`, প্ল্যানের একেবারে প্রথম সেলফ-হোস্টেড ডিক্লারেশনটাই, "অজানা টাইপ" ত্রুটি দিত, আর ম্যানুয়াল `সংখ্যা`-ট্যাগ ছাড়া কোনো workaround ছিল না — ঠিক সেই জিনিস যা এড়াতে §১-এ এনাম যোগ করা হয়েছিল। দুটো নাম-পাসই এখন যেকোনো বডি-পাসের আগে শেষ হয়। অসীম-আকার চেকার আগে থেকেই `inline_members` দিয়ে struct↔enum পার হতো, তাই নতুন প্রান্তেও ঠিক কাজ করে (fixture `60`)।
  7. **নাম ছাড়া কোনো ফাংশন-মান কল করা যেত না।** কল-রেজোলিউশন `Option<String>` ধরে রাখত আর যেকোনো ইনডেক্স-সাফিক্স সেটা মুছে দিত, তাই `টেবিল[০](x)` — প্ল্যানের চাওয়া টোকেন-ধরন → পার্স-ফাংশন ডিসপ্যাচ টেবিল — আর `d.f(x)` দুটোই "কলযোগ্য ফাংশন নয়" বলত। নাম না থাকলে এখন *টাইপ* দেখে ডিসপ্যাচ হয়; arity ও per-argument চেক সেই পথেই চলে।
  8. **জেনেরিক এনামের পেলোড-বাইন্ডিং-এ ফিল্ড-অ্যাক্সেস মডিউল-পাথ ধরে নেওয়া হতো** — `o: বিকল্প<টোকেন>`-এ `মিলাও o { কিছু(v) => v.শুরু }` বলত "মডিউল 'v' ইম্পোর্ট করা হয়নি"। `Ty::Enum` ডিজাইন অনুযায়ীই টাইপ-আর্গুমেন্ট বহন করে না, তাই `T` এখানে উদ্ধার করা যায় না — ফিক্স হলো রিডটা *প্রত্যাখ্যান করা বন্ধ* করা। লোকাল বাইন্ডিং এখন তিনটে Qualified সাইটেই মডিউল-নামকে হারায়। সাথে দুটো ফলো-অন, নইলে প্যাটার্নটা ব্যবহারযোগ্য হতো না: `ধরি x = <erased>` আর "খালি অ্যারের টাইপ" বলে না (শুধু আসল খালি-অ্যারে লিটারেলই `expr` থেকে `None` দেয়), আর যে `মিলাও`-এর প্রথম শাখা erased, সে পরের কংক্রিট শাখা থেকে টাইপ নেয়।
  9. **বন্ধনী-বিহীন `তথ্য`/ভ্যারিয়েন্ট-নাম রানটাইম পর্যন্ত বেঁচে যেত।** `ধরি b = লাল` (কনস্ট্রাক্টর, `()` ছাড়া) `Unknown` হিসেবে টাইপ-চেক পার হয়ে যেত, আর ওই লাইনটা চললে তবেই "অঘোষিত ভ্যারিয়েবল" দিয়ে মরত; সাধারণ অজানা নাম আগে থেকেই কম্পাইল-টাইম ত্রুটি ছিল। কনস্ট্রাক্টর-*কল* `ExprKind::Postfix` হিসেবে পার্স হয় আর ওই arm-এ কখনো পৌঁছায় না, তাই ওখানে পৌঁছানো মানেই বন্ধনী নেই। এটাই ঠিক সেই ব্যর্থতার ধরন যা রুখতে এনাম যোগ করা হয়েছিল।
  10. **UI উইজেট-নামগুলো গ্লোবালি সংরক্ষিত ছিল** — `টেক্সট`, `বাটন`, `ইনপুট`, `ছবি`, `সারি`, `কলাম`, `কার্ড`, `ডায়ালগ`, `স্ক্রল`, `ক্যানভাস`। এগুলো সাধারণ বাংলা বিশেষ্য, আর `self-hosting-plan.md` §২ UI-কে বুটস্ট্র্যাপ-সাবসেটের বাইরে রাখে — অর্থাৎ v2.0 যে প্রোগ্রামটা লেখার জন্যই, তার কাছে এটা পুরোপুরি খরচ: একটা `ডায়াগনস্টিক`-এর ফিল্ডের নাম `কলাম` রাখা যেত না। এখন **কনটেক্সচুয়াল** — পার্সার `display_depth` ধরে, আর শুধু `ডিসপ্লে` ব্লকের ভেতরেই এগুলো উইজেট। `ডিসপ্লে` নিজে সংরক্ষিতই থাকল। একই সংঘর্ষের দ্বিতীয় অর্ধেক: প্রিমিটিভ-টাইপ কীওয়ার্ড `তথ্য`-র ফিল্ড-নাম হিসেবে প্রত্যাখ্যাত হতো, অথচ `.লেখা` ফিল্ড-*অ্যাক্সেস* আগে থেকেই সেটা মানত — চারটে মেম্বার-পজিশনই এখন এক হেল্পার দিয়ে যায়। **নোট:** নামগুলো `KEYWORDS` ছাড়ায় সেগুলো NFC-টেবিলও ছেড়েছে, অথচ গ্যারান্টিটা এখন আগের চেয়ে *বেশি* দরকার — পার্সার NFC-নরমালাইজড আইডেন্টিফায়ার-টেক্সটকে `WIDGETS`-এর সাথে মেলায়, তাই নরমালাইজ না হওয়া precomposed `ডায়ালগ` জোরে ব্যর্থ না হয়ে নীরবে সাধারণ কল হয়ে যেত; `kolom-syntax` এখন নিজের টেবিল দুটোর NFC-তা assert করে।
  11. **একই নামে একটা `তথ্য` ও একটা `এনাম` নীরবে গ্রহণ করা হতো।** `resolve_type` আগে `struct_names` দেখে, তাই `তথ্য`-টা প্রতিটা টাইপ-পজিশনে জিতত আর `এনাম`-টা এমন একটা টাইপ হয়ে থাকত যার নাম লেখা যেত না, অথচ তার ভ্যারিয়েন্টগুলো দিব্যি মান বানাত। দুটো একই-নামের `তথ্য` বা দুটো একই-নামের `এনাম` আগে থেকেই ত্রুটি — এটা সেই একই সংঘর্ষ, দুই টেবিলের মাঝখানে।
- **ইচ্ছাকৃতভাবে ফ্রিজের আগে ফিক্স করা হয়নি** (প্রতিটার জন্য কারণ) —
  - **এনাম-ভ্যারিয়েন্টের নাম একটাই গ্লোবাল নেমস্পেসে** — দুটো এনাম একই ভ্যারিয়েন্ট-নাম রাখতে পারে না, তাই কম্পাইলারের `টোকেন_ধরন` ও `এক্সপ্র_ধরন` দুটোতেই `নাম` রাখা যাবে না; প্রিফিক্স দিয়ে কাজ চালাতে হবে (`টো_নাম`, `এক্স_নাম`)। **ফ্রিজের আগে দরকার নেই, কারণ এটা পরে শিথিল করা backward-compatible** — qualified কনস্ট্রাকশন (`টোকেন_ধরন.নাম`) যোগ করলে গ্লোবালি-অনন্য নামে লেখা পুরনো সোর্স বৈধই থাকে, কোনো rework লাগে না। M2-এর পর ঠিক কতটা ভোগায় দেখে সিদ্ধান্ত নিন।
  - **চেইনড ফিল্ড-অ্যাসাইনমেন্ট পার্স হয় না** — `m.খ.ক = ৪২` ব্যর্থ (LValue একটাই `.field` নেয়); পড়া (`m.খ.ক`) ঠিক আছে। সাধারণ আইডেন্টিফায়ারেও ব্যর্থ, তাই প্রি-এক্সিস্টিং। Workaround: ভেতরের স্ট্রাক্ট একটা ভ্যারিয়েবলে বেঁধে বদলান (ইন্টারপ্রেটারে স্ট্রাক্ট রেফারেন্স-সদৃশ)।
  - **নেটিভ কোডজেনের বার্তা অস্পষ্ট** — এই ফিক্সগুলোর পর যেসব প্রোগ্রাম sema পার হয় সেগুলো `কলম বিল্ড`-এ `অজানা struct 'টোকেন_ধরন'` পায়, `মিলাও`-এর মতো "এখনো নেটিভে সমর্থিত নয়" নয়। পরিষ্কারভাবে ব্যর্থ হয়, ক্র্যাশ করে না; ঠিক করতে `emit.rs`-এ একটা enum-টেবিল লাগবে, যা §১-এর মুলতুবি নেটিভ enum কোডজেনেরই অংশ।
  - **`কলম বিল্ড`-এর temp ডিরেক্টরি PID-ভিত্তিক** (`kolom-build-<pid>`, `main.rs:252`) — সমান্তরাল বিল্ডে PID পুনর্ব্যবহার হলে একটা বিল্ড আরেকটার আউটপুট ডিরেক্টরি মুছে দিতে পারে; `console_examples_agree_between_backends` এই সেশনে একবার এভাবেই ফ্লেক করেছে (একা চালালে ও পরের প্রতিটা রানে পাস)। বিল্ড-টুলিং-এর বাগ, ভাষার নয়।
- কমপক্ষে ২–৩ সপ্তাহ "স্টেবিলাইজেশন উইন্ডো" রাখুন। ⚠️ ৮ দিনে বন্ধ করা হয়েছে — উপরের অবস্থা-অনুচ্ছেদে যুক্তি ও ঝুঁকি লেখা আছে।
- উইন্ডো শেষে draft ট্যাগ সরিয়ে "স্ট্যাবল" ঘোষণা করুন, একটা গিট ট্যাগ (যেমন `v1.5-frozen`) দিয়ে চিহ্নিত করুন। ✅ `v1.5-frozen` (২০২৬-০৯-০৮)।

## ৭. ডিফারেনশিয়াল-টেস্ট হারনেস

**অবস্থা:** ✅ বাস্তবায়িত। `kolom lex <file>` (আগে থেকেই ছিল) আর নতুন `kolom ast <file>` — দুটোই ডিটারমিনিস্টিক, সম্পূর্ণ (Rust-এর derive করা `Debug` ফরম্যাটে) টোকেন-স্ট্রিম/AST ডাম্প দেয়, তাই diff-যোগ্য। `scripts/diff-dump.sh <kolom-exe-A> [kolom-exe-B] [golden-dir]` — দুটো `kolom` বাইনারির মধ্যে প্রতিটা golden fixture-এর `lex`+`ast` ডাম্প তুলনা করে; `A`/`B` একই বাইনারি দিলে self-consistency স্মোক-টেস্ট (এখনই চালানো যায়, ৬৬টা fixture-এ ০ মিসম্যাচ দিয়ে যাচাই করা হয়েছে), আর v2.0 শুরু হলে `B`-তে সেলফ-হোস্টেড লেক্সার/পার্সারের বাইনারি বসালেই আসল ডিফারেনশিয়াল-টেস্ট হয়ে যায়। টাইপ-অ্যানোটেটেড AST ডাম্প (`--dump types`-জাতীয়) এখনো নেই — `sema::Types.expr`-এর কী raw pointer (`*const Expr as usize`), যা দুটো ভিন্ন প্রসেস/ইমপ্লিমেন্টেশনের মধ্যে অর্থহীন; position-keyed dump লিখতে একটা নতুন AST-walker দরকার, যেটা এই সেশনের স্কোপের বাইরে রাখা হয়েছে — token+AST ডাম্পই প্রথম ধাপের (লেক্সার/পার্সার সেলফ-হোস্টিং) জন্য যথেষ্ট।

## ৮. বড়-প্রোগ্রাম স্ট্রেস টেস্ট

**অবস্থা:** ✅ বাস্তবায়িত, একটা আসল বাগ ধরা পড়েছে ও ফিক্স হয়েছে। `crates/kolom-cli/tests/golden/55_module_stress/` — ৫টা সিবলিং মডিউল (`main` → `eval` → `ast`, নেস্টেড ইম্পোর্ট সহ; আর `containers`/`dispatch`/`ffi`) একসাথে এনাম/মিলাও (রিকার্সিভ AST + এভালুয়েটর), জেনারিক্স (`বাক্স<T>`/`বিকল্প<T>`), প্রথম-শ্রেণির ফাংশন, ও `এক্সটার্ন "C"` ব্যবহার করে। **বাগ ধরা পড়েছে:** `kolom-cli`-র `resolve_user_modules` শুধু `funcs`/`consts`/`structs` মার্জ করত — একটা ইম্পোর্ট করা মডিউলে ঘোষিত `এনাম`/`এক্সটার্ন` **নীরবে হারিয়ে যেত**। ফিক্স হয়েছে (`enums`/`externs`-ও এখন মার্জ হয়, `enums`-এর জন্য `structs`-এর মতোই ক্রস-ফাইল ডুপ্লিকেট-নাম ত্রুটি সহ)।

**সাইজ নোট:** মূল প্রস্তাব ছিল "৩,০০০+ লাইন, ১০+ ফাইল" — এই মডিউল-স্ট্রেস ফিক্সচারটা ছোট (৫ ফাইল, ~৮০ লাইন) কিন্তু ফিচার-ঘনত্বে বেশি (৪টা v2.0 ফিচারই একসাথে, নেস্টেড ইম্পোর্ট সহ) — এবং এটাই আসল বাগ ধরেছে। আলাদাভাবে, একটা স্ক্রিপ্ট-জেনারেটেড ৩,০০৮-লাইনের প্রোগ্রাম (৩০০টা ফাংশন, স্ট্রাক্ট, কন্ট্রোল-ফ্লো — শুধু নেটিভ-কোডজেন-রেডি ফিচার, যেহেতু এনাম/জেনারিক্স/ফাংশন-ভ্যালু এখনো ইন্টারপ্রেটেড-ওনলি) §৯-এর বেঞ্চমার্কে ব্যবহৃত হয়েছে — নিচে দেখুন। দুটো একসাথে "আকার" (raw স্কেল) ও "গভীরতা" (ফিচার-ইন্টারঅ্যাকশন) দুই ধরনের স্ট্রেসই কভার করে, প্রতিটা এককভাবে ৩,০০০-লাইন+মাল্টি-ফিচার হওয়ার চেয়ে বাস্তবসম্মত সময়ে বেশি সিগন্যাল দিয়েছে।

## ৯. পারফরম্যান্স বেঞ্চমার্ক

**অবস্থা:** ✅ বাস্তবায়িত — কোনো রেড ফ্ল্যাগ পাওয়া যায়নি। ৩,০০৮-লাইনের স্ক্রিপ্ট-জেনারেটেড প্রোগ্রাম (৩০০টা ফাংশন + স্ট্রাক্ট + কন্ট্রোল-ফ্লো, নেটিভ-কোডজেন-রেডি ফিচার শুধু) দিয়ে বেঞ্চমার্ক —

| মোড | Debug বিল্ড | Release বিল্ড |
|---|---|---|
| `কলম চালাও` (ইন্টারপ্রিটেড) | ~০.০৬৩s | ~০.২৩s* |
| `কলম বিল্ড` (নেটিভ) | ~০.৪৩s | ~০.১৫s |

(*রিলিজ ইন্টারপ্রিটেড টাইমিং ডিবাগের চেয়ে বেশি এসেছে — ফাইলসিস্টেম-ক্যাশিং নয়েজ সন্দেহ, দুটোই এত ছোট যে পার্থক্যটা অর্থপূর্ণ না।) নেটিভ কম্পাইল টাইম রিলিজ-বিল্ড `kolom`-এ ৩,০০০+ লাইনের প্রোগ্রামে **১৫০ মিলিসেকেন্ডের নিচে** — সেলফ-হোস্টেড কম্পাইলার বুটস্ট্র্যাপের (নিজেকে নিজে কম্পাইল করা, বহুবার) জন্য কোনো উদ্বেগের কারণ নেই এই স্কেলে। উৎপন্ন নেটিভ বাইনারি চালিয়ে ইন্টারপ্রেটারের সাথে আউটপুট মিলিয়ে যাচাই করা হয়েছে (দুই ব্যাকএন্ডই একমত)।

## ১০. গিট/রিলিজ হাইজিন

**অবস্থা:** ✅ সম্পন্ন (checkpoint অর্থে)। প্রতিটা প্রি-রিকুইজিট (§১, §৩, §৪, §৫, §৭, §৮/§৯) নিজস্ব কমিটে, পুশ করা হয়েছে, প্রতিটার আগে পুরো টেস্ট স্যুট (৩৭+ টেস্ট বাইনারি) সবুজ যাচাই করে। অ্যানোটেটেড ট্যাগ `v2-prereqs-lang-complete` (`origin`-এ পুশড) এই checkpoint-টা চিহ্নিত করে রেখেছে। ✅ **ফ্রিজ ট্যাগ দেওয়া হয়েছে** — অ্যানোটেটেড ট্যাগ `v1.5-frozen` (২০২৬-০৯-০৮) §৬-এর উইন্ডো বন্ধ হওয়ার মুহূর্তটা আলাদা করে চিহ্নিত করে। দুটো ট্যাগের পার্থক্য: `v2-prereqs-lang-complete` = ভাষা-ফিচারগুলো কোড-সাইড সম্পূর্ণ; `v1.5-frozen` = সিনট্যাক্স/সিমান্টিক্স স্থির, এর পরে কলমে-লেখা কম্পাইলার-সোর্স জমতে শুরু করবে। স্টেবিলাইজেশন উইন্ডোর দ্বিতীয় পাসের ছয়টা ফিক্সও নিজস্ব কমিটে, প্রতিটার আগে পুরো স্যুট (৩৮ টেস্ট বাইনারি / ১৩৮ টেস্ট) ও `scripts/diff-dump.sh` (৬৬ fixture, ০ মিসম্যাচ) সবুজ যাচাই করে।
