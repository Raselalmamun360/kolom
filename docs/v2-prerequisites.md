# কলম v2.0 (সেলফ-হোস্টেড টুলচেইন) — প্রি-রিকুইজিট পরিকল্পনা

এই ডকুমেন্ট বলে — **v2.0 (সেলফ-হোস্টিং) শুরু করার আগে** বর্তমান Rust কম্পাইলারেই (v1.x) কী কী শেষ করে রাখা দরকার, যাতে সেলফ-হোস্টেড কম্পাইলার লেখা শুরু হওয়ার পর ভাষা বা ABI বদলাতে গিয়ে কাজ আবার লিখতে না হয়। `roadmap.md` §১৪-এর সাথে পড়ুন — এখানে সেই সেকশনের প্রিরিকুইজিট বিস্তারিতভাবে বর্ণনা করা হয়েছে।

**নীতি** — প্রতিটা আইটেম v1.x-এর মধ্যেই, Rust কম্পাইলারের ছয়টা ক্রেট জুড়ে (`kolom-lexer` → `kolom-syntax` → `kolom-sema` → `kolom-interp` → `kolom-codegen-cranelift` → `kolom-runtime`) যোগ করা হবে। লক্ষ্য: v2.0 শুরু হওয়ার সময় ভাষা ও ABI স্থির থাকবে।

## ১. এনাম / সাম-টাইপ (ADT)

**অবস্থা:** ✅ ইন্টারপ্রেটেড (`কলম চালাও`)-এ বাস্তবায়িত — `এনাম` ঘোষণা, ভ্যারিয়েন্ট কনস্ট্রাক্টর, `শেয়ার`-এর মাধ্যমে রিকার্সিভ এনাম (AST-ধাঁচের), আর exhaustiveness-checked `মিলাও` এক্সপ্রেশন সবই কাজ করে (§২ দেখুন — দুটো একসাথে যোগ হয়েছে)। বিস্তারিত ব্যবহারকারী-স্তরের ডকুমেন্টেশন `language.md` §২৩.১-এ। ⏳ **নেটিভ কোডজেন (`কলম বিল্ড`) এখনো বাকি** — `EnumLayout`/ট্যাগড-ইউনিয়ন মেমরি লেআউট, ট্যাগ-সুইচ-ভিত্তিক `মিলাও` লোয়ারিং, ও ডিসক্রিমিন্যান্ট-অ্যাওয়্যার ড্রপ জেনারেশন `kolom-codegen-cranelift`-এ যোগ করা বাকি (আপাতত `মিলাও`/এনাম-নির্মাণ নেটিভ বিল্ডে স্পষ্ট কম্পাইল-টাইম ত্রুটি দেয়, ক্র্যাশ করে না)।

**কেন** — AST নোড (`Expr`, `Stmt`, `Type`) রিপ্রেজেন্ট করার একমাত্র স্বাভাবিক উপায়। এখনকার `তথ্য`+ম্যানুয়াল-ট্যাগ পদ্ধতিতে কম্পাইলার লিখলে ভুল ট্যাগ-চেক একটা রানটাইম বাগ হয়ে ছড়িয়ে থাকবে সারা কোডবেসে।

**প্রস্তাবিত সিনট্যাক্স** (তথ্যর constructor-স্টাইলের সাথে সামঞ্জস্যপূর্ণ) —

```kolom
এনাম আকৃতি {
    বৃত্ত(দশমিক),
    আয়তক্ষেত্র(দশমিক, দশমিক),
    বিন্দু
}
```

- ভ্যারিয়ান্টে পজিশনাল পেলোড (তথ্যর মতো), পেলোড-বিহীন ভ্যারিয়ান্টও বৈধ (`বিন্দু`)।
- মেমরি: রিকার্সিভ এনাম (যেমন `Expr` নিজেই `Expr`-ধারণ করা, AST-র জন্য অপরিহার্য) `শেয়ার` দিয়ে — `language.md` §২৩-এর নোড/লিংকড-লিস্ট নিয়মের মতোই।

**স্পর্শ করবে** — lexer (নতুন কীওয়ার্ড), syntax (নতুন ঘোষণা + কনস্ট্রাক্টর-কল পার্সিং, তথ্যর সাথে শেয়ার করা কোড), sema (ভ্যারিয়ান্ট টাইপচেক, tag রেজোলিউশন), interp+codegen (ট্যাগড-ইউনিয়ন লেআউট/ডিসপ্যাচ, RC/ownership নিয়ম তথ্যর প্যাটার্ন অনুসরণ করে)।

## ২. প্যাটার্ন ম্যাচিং

**অবস্থা:** ✅ এনাম-ভ্যারিয়েন্ট ম্যাচিং হিসেবে বাস্তবায়িত (§১ দেখুন) — ইন্টারপ্রেটেড মোডে। এই ডকুমেন্টে প্রস্তাবিত সিনট্যাক্সই (`মিলাও ... { pattern => expr }`) হুবহু বাস্তবায়িত হয়েছে, exhaustiveness checking সহ। সাধারণীকৃত প্যাটার্ন ম্যাচিং (লিটারেল প্যাটার্ন, অ্যারে-ডিস্ট্রাকচারিং, গার্ড) এখনো বাইরে — শুধু এনাম-ভ্যারিয়েন্ট প্যাটার্ন সমর্থিত।

**কেন** — AST ওয়াকিং, প্রতিটা visitor-এর মূল ভিত্তি। এনামের সাথে একসাথে ডিজাইন করা জরুরি — একটা ছাড়া আরেকটার দরকারই পড়ে না।

**প্রস্তাবিত সিনট্যাক্স** —

```kolom
ধরি ক্ষেত্রফল = মিলাও আকৃতি {
    বৃত্ত(ব্যাসার্ধ) => গণিত.পাই * ব্যাসার্ধ * ব্যাসার্ধ,
    আয়তক্ষেত্র(দৈর্ঘ্য, প্রস্থ) => দৈর্ঘ্য * প্রস্থ,
    বিন্দু => ০,
}
```

- `মিলাও` একটা এক্সপ্রেশন (রিটার্ন-ভ্যালু আছে) — `যদি/অন্যথায়` এক্সপ্রেশনের মতো একই প্যাটার্নে।
- **exhaustiveness checking sema-তে বাধ্যতামূলক** — একটা ভ্যারিয়ান্ট মিস করলে কম্পাইল-টাইম এরর। এটা ownership-checker-এর মতোই কঠোরতায় রাখা উচিত, কারণ কম্পাইলার লেখার সময় exhaustiveness-এর অভাবই সবচেয়ে বেশি সাইলেন্ট বাগ তৈরি করে।

**স্পর্শ করবে** — একই ছয় ক্রেট; sema-তে সবচেয়ে বেশি কাজ (exhaustiveness algorithm)।

## ৩. প্রথম-শ্রেণির ফাংশন / ক্লোজার

**অবস্থা:** ⚠️ আংশিক — ইন্টারপ্রেটেড মোডে ফাংশন-*রেফারেন্স* বাস্তবায়িত (`Value::Func(Rc<FuncDecl>)`, ইতিমধ্যে-ঘোষিত `ফাংশন`-এর নামের পয়েন্টার হিসেবে): ভ্যারিয়েবলে রাখা, প্যারামিটার/রিটার্ন-টাইপ হিসেবে পাস করা, অ্যারেতে রাখা, আর ভ্যারিয়েবলের মাধ্যমে পরোক্ষ কল — সবই কাজ করে, টেবিল-ড্রিভেন ডিসপ্যাচ যাচাই করা হয়েছে। ফাংশন-টাইপ সিনট্যাক্স `(টাইপ, ...) -> টাইপ`। ব্যবহারকারী-স্তরের ডকুমেন্টেশন `language.md` §১১.১-এ, যেখানে অ্যারে-অফ-ফাংশন টাইপ-অ্যানোটেশনের একটা পরিচিত পার্সিং-অস্পষ্টতাও নথিভুক্ত (ইনফারেন্স দিয়ে এড়ানো যায়)। ❌ **এখনো নেই: সত্যিকারের ক্লোজার** — অ্যানোনিমাস ফাংশন লিটারেল বা এনক্লোজিং-স্কোপ ক্যাপচার কোনোটাই সমর্থিত না; এর জন্য ইন্টারপ্রেটারের স্কোপ রিপ্রেজেন্টেশন (`Vec<Scope>`, নন-শেয়ার্ড) `Rc<RefCell<Scope>>`-এ রিফ্যাক্টর করা দরকার হবে যাতে একটা ক্লোজার তার তৈরির সময়কার এনক্লোজিং স্কোপ ফাংশনটা রিটার্ন হয়ে যাওয়ার পরেও ধরে রাখতে পারে — এটা একটা আলাদা, বড় ফলো-আপ। ⏳ নেটিভ কোডজেন বাকি (§১-এর মতোই — গ্রেসফুলি ব্যর্থ হয়, প্যানিক করে না)।

**কেন** — টেবিল-ড্রিভেন ডিসপ্যাচ (যেমন টোকেন-টাইপ → পার্স-ফাংশন ম্যাপিং), visitor callback।

**প্রস্তাবিত সিনট্যাক্স** —

```kolom
ধরি বর্গ: (সংখ্যা) -> সংখ্যা = ফাংশন(x: সংখ্যা) -> সংখ্যা { রিটার্ন x * x }
লেখো(লেখায়(বর্গ(৫)))
```

- ফাংশন-টাইপ `(প্যারাম-টাইপ...) -> রিটার্ন-টাইপ` — টাইপ-অ্যানোটেশনে ব্যবহারযোগ্য।
- ক্লোজার ক্যাপচার: শুরুতে শুধু **by-share ক্যাপচার** (তথ্যর `শেয়ার` মেকানিজম পুনর্ব্যবহার) — by-move ক্যাপচার পরের সংস্করণে, স্কোপ ছোট রাখতে।

**স্পর্শ করবে** — runtime-এ সবচেয়ে বেশি প্রভাব (ফাংশন-পয়েন্টার + ক্যাপচারড-এনভায়রনমেন্ট রিপ্রেজেন্টেশন — Cranelift কোডজেনে closure-as-struct লোয়ারিং)।

## ৪. জেনারিক্স

**অবস্থা:** ⚠️ আংশিক (টাইপ-ইরেজার-ভিত্তিক) — ইন্টারপ্রেটেড মোডে `তথ্য<T>`/`এনাম<T>`/`ফাংশন<T>` সবই বাস্তবায়িত, আর্গুমেন্ট থেকে টাইপ-ইনফারেন্স সহ (`বাক্স(৪২)` থেকে `T = সংখ্যা` অনুমিত, এক্সপ্লিসিট instantiation সিনট্যাক্স নেই — ইচ্ছাকৃতভাবে, কারণ `<`/`>` এক্সপ্রেশন-পজিশনে তুলনা অপারেটরের সাথে সংঘর্ষ করত)। একটা generic struct + generic enum (Option-ধাঁচের `বিকল্প<T>`) + generic function (array param সহ) একসাথে টেস্ট করা হয়েছে (golden test `53_generics`)। ব্যবহারকারী-স্তরের ডকুমেন্টেশন `language.md` §২৩.২-এ।

**⚠️ সাউন্ড নয় — টাইপ-ইরেজার, মনোমরফাইজেশন নয়।** এই প্রি-রিকুইজিট ডকের নিচের "প্রস্তাবিত সিনট্যাক্স" অংশে Rust-স্টাইল মনোমরফাইজেশনের কথা বলা ছিল (প্রতি-instantiation কোড-জেনারেশন) — বাস্তবায়ন সেই পথে যায়নি, সরল টাইপ-ইরেজার বেছে নেওয়া হয়েছে: জেনারিক ডিক্লারেশনের বডি একবারই চেক হয়, `T`-এর প্রতিটা occurrence `Ty::Unknown` (পোয়িজনড, সবকিছুর সাথে unify হয়) হিসেবে resolve হয়। ফল: কনটেইনার/ফাংশনের কাঠামো (arity, রিকার্সিভ গঠন) চেক হয়, কিন্তু পেলোডের প্রকৃত টাইপ ক্রস-চেক হয় না — `বাক্স<সংখ্যা>`-তে ভুলবশত `লেখা` বসালেও কম্পাইল-টাইম ত্রুটি ধরা পড়বে না। কারণ: মনোমরফাইজেশনের জন্য মূলত নেটিভ কোডজেন-লেভেল কাজ দরকার (প্রতি-instantiation আলাদা কোড) যেটা এখনো বাকি (নিচে দেখুন); ইন্টারপ্রেটেড মোডে যেহেতু রানটাইমে টাইপ-নিরপেক্ষ (`তথ্য` এমনিতেই `Value::Map`-এ রিপ্রেজেন্টেড), সাউন্ড জেনারিক্সের জন্য মনোমরফাইজেশনের আসল প্রয়োজনটাই মূলত নেটিভ কোডজেনে, যেখানে এখনো ধরাই হয়নি।

⏳ নেটিভ কোডজেন বাকি (§১/§৩-এর মতোই — গ্রেসফুলি ব্যর্থ হয় "অজানা struct 'T'" দিয়ে, প্যানিক করে না)। মনোমরফাইজেশন-ভিত্তিক (সাউন্ড) জেনারিক্স তখনই আসল অর্থ পাবে যখন নেটিভ কোডজেন যোগ হবে — প্রতিটা concrete instantiation-এর জন্য আলাদা স্ট্রাক্ট-লেআউট/কোড জেনারেট করে।

**কেন** — টাইপ-নিরাপদ কন্টেইনার (টোকেন-লিস্ট, সিম্বল-টেবিল)। এটা ছাড়া কম্পাইলার নিজেই "AnyValue" ধরনের আনটাইপড অ্যারে দিয়ে লেখা লাগবে — একটা কম্পাইলারের জন্য বিশেষভাবে বিপজ্জনক, কারণ এটা নিজেই টাইপ-সেফটির উদাহরণ হওয়া দরকার।

**প্রস্তাবিত সিনট্যাক্স** —

```kolom
তথ্য বাক্স<T> { মান: T }
এনাম বিকল্প<T> { কিছু(T), কিছুই_না }
ফাংশন প্রথম<T>(তালিকা: T[]) -> বিকল্প<T> { ... }
```

- **স্কোপ ছোট রাখুন**: শুধু মনোমরফাইজেশন (Rust-স্টাইল, প্রতি-instantiation কোড জেনারেট)। ট্রেইট-বাউন্ড/ইন্টারফেস-জেনারিক্স v2.0-এর বাইরে রাখুন — সেটা `language.md` §১৯-এ আলাদা, বড় ফিচার হিসেবেই তালিকাভুক্ত।

**স্পর্শ করবে** — sema (টাইপ-প্যারামিটার রেজোলিউশন), codegen (মনোমরফাইজেশন পাস — প্রতিটা concrete instantiation-এর জন্য আলাদা কোড)।

---

## ৫. এক্সটার্ন / FFI — কলম থেকে Rust ফাংশন কল

**কেন** — v2.0-এর "প্র্যাগম্যাটিক" ধাপে কলমে-লেখা ফ্রন্টএন্ডকে Cranelift/rust-lld শিম কল করতে হবে। মেকানিজম ইতিমধ্যেই প্রমাণিত — stdlib-এর প্রতিটা ফাংশন এখনই `kolom-runtime`-এ `#[no_mangle] extern "C"` হিসেবে লেখা এবং কলম কোড থেকে কল হচ্ছে। এখন শুধু এটা **ইউজার-লেভেলে উন্মুক্ত** করতে হবে (এখন এটা compiler-internal, শুধু বিল্ট-ইন stdlib মডিউলের জন্য স্পেশাল-কেসড)।

**প্রস্তাবিত সিনট্যাক্স** —

```kolom
এক্সটার্ন "C" {
    ফাংশন kl_cg_compile(সোর্স: লেখা) -> সংখ্যা
    ফাংশন kl_link(অবজেক্ট_পাথ: লেখা, আউটপুট_পাথ: লেখা) -> সংখ্যা
}
```

- ABI: C ABI (Rust-এর `extern "C"` এর সাথে সরাসরি মেলে — নতুন কোনো ABI ডিজাইন করা লাগবে না)।
- টাইপ-ম্যাপিং টেবিল দরকার sema-তে: `লেখা ↔ kl_str`, `সংখ্যা ↔ i64`, `দশমিক ↔ f64` ইত্যাদি — এগুলো runtime-এ ইতিমধ্যেই সংজ্ঞায়িত (`kolom-runtime/src/lib.rs`), শুধু sema-কে সেগুলো ইউজার-ঘোষিত extern ফাংশনে চেক করাতে শেখাতে হবে।
- **নিরাপত্তা নোট**: `এক্সটার্ন` ব্লক ownership-checker-এর আওতার বাইরে (Rust-এর `unsafe`-এর মতো) — এটা ডকুমেন্টেশনে স্পষ্ট করে লিখুন, যাতে ভবিষ্যতে কনট্রিবিউটররা ভুল না বোঝেন।

**স্পর্শ করবে** — syntax (নতুন ঘোষণা-ফর্ম), sema (টাইপ-ম্যাপিং যাচাই), codegen (সরাসরি C-কলিং-কনভেনশন কল এমিট), CLI/linker (extern-লিংকড সিম্বল রেজোলভ করা বিল্ড-টাইমে)।

## ৬. স্পেসিফিকেশন ফিচার-ফ্রিজ

১–৫ যোগ হওয়ার পর —

- `language.md`/`grammer.md`/`compiler.md`-এ প্রতিটা নতুন ফিচার ডকুমেন্ট করুন (draft ট্যাগ সহ প্রথমে)।
- কমপক্ষে ২–৩ সপ্তাহ "স্টেবিলাইজেশন উইন্ডো" রাখুন — এই সময় শুধু বাগফিক্স, নতুন সিনট্যাক্স-পরিবর্তন নয়।
- উইন্ডো শেষে draft ট্যাগ সরিয়ে "স্ট্যাবল" ঘোষণা করুন, একটা গিট ট্যাগ (যেমন `v1.5-frozen`) দিয়ে চিহ্নিত করুন — এটাই v2.0 বুটস্ট্র্যাপের রেফারেন্স পয়েন্ট হবে।

## ৭. ডিফারেনশিয়াল-টেস্ট হারনেস

- প্রতিটা কম্পাইলার-স্টেজের (lex → parse → typecheck) জন্য একটা `--dump` মোড যোগ করুন (যদি না থাকে) — টোকেন-স্ট্রিম, AST, টাইপ-অ্যানোটেটেড AST টেক্সট-ফরম্যাটে ডাম্প করার জন্য।
- একটা স্ক্রিপ্ট বানান যা: বর্তমান Rust কম্পাইলার ও (v2.0-এ) নতুন কলম-কম্পোনেন্ট — দুটোর ডাম্প নিয়ে diff করে। কোনো diff থাকলে CI fail।
- বিদ্যমান golden test (`crates/kolom-cli/tests/golden`) + এই ডাম্প-ডিফ — দুটো মিলিয়েই v2.0-এর "oracle" তৈরি হবে।

## ৮. বড়-প্রোগ্রাম স্ট্রেস টেস্ট

- এটা কম্পাইল/রান করে দেখুন — import-সংঘর্ষ, কম্পাইল-টাইম, স্ট্যাক-ডেপথ (রিকার্সিভ AST ওয়াকিং ডিপ রিকার্শনে গেলে) সংক্রান্ত বাগ এখনই ধরা পড়ুক।
