# ১. ভূমিকা

## ১.১ উদ্দেশ্য

এই ডকুমেন্ট **কলম** প্রোগ্রামিং ভাষার ফরমাল গ্রামার (formal grammar) নির্ধারণ করে।

এই গ্রামার স্পেসিফিকেশন ভাষার সিনট্যাক্সের জন্য একমাত্র প্রামাণ্য (authoritative) রেফারেন্স এবং কলম-এর সকল টুলের ভিত্তি, যার মধ্যে রয়েছে —

- কম্পাইলার
- লেক্সার
- পার্সার
- টাইপ চেকার
- ফরম্যাটার
- Language Server (LSP)
- IDE এক্সটেনশন
- ডকুমেন্টেশন টুল

উদাহরণ বা টিউটোরিয়াল যদি এই স্পেসিফিকেশনের সাথে না মেলে, তাহলে **এই গ্রামারই চূড়ান্ত ধরা হবে।**

---

## ১.২ সুযোগ (Scope)

এই ডকুমেন্ট কলম প্রোগ্রামিং ভাষার সিনট্যাকটিক তথ্য নির্ধারণ করে।

এটি নির্ধারণ করে —

- সোর্স ফাইলের তথ্য
- লেক্সিক্যাল গ্রামার
- টোকেন
- সংরক্ষিত কীওয়ার্ড
- আইডেন্টিফায়ার
- লিটারেল
- অপারেটর
- এক্সপ্রেশন
- স্টেটমেন্ট
- ডিক্লারেশন
- মডিউল
- নেটিভ UI সিনট্যাক্স
- Extended Backus–Naur Form (EBNF) ব্যবহার করে সম্পূর্ণ গ্রামার

এই ডকুমেন্ট নিম্নলিখিত বিষয়গুলো নির্ধারণ করে **না** —

- কম্পাইলার বাস্তবায়ন (implementation)
- রানটাইম আচরণ
- মেমরি ম্যানেজমেন্ট
- স্ট্যান্ডার্ড লাইব্রেরি বাস্তবায়ন
- কোড জেনারেশন
- প্ল্যাটফর্ম-নির্দিষ্ট আচরণ

এই বিষয়গুলো তাদের নিজস্ব স্পেসিফিকেশনে আলোচিত হয়েছে।

---

## ১.৩ ডিজাইন লক্ষ্য

কলম গ্রামার নিম্নলিখিত লক্ষ্য মাথায় রেখে ডিজাইন করা হয়েছে —

- **সহজপাঠ্য** — সিনট্যাক্স বাংলাভাষী ডেভেলপারদের কাছে স্বাভাবিক মনে হওয়া উচিত।
- **সামঞ্জস্যপূর্ণ** — একই ধরনের ভাষাগত তথ্য একই গ্রামার নিয়ম অনুসরণ করে।
- **দ্ব্যর্থহীন (Unambiguous)** — প্রতিটি বৈধ প্রোগ্রামের একটিমাত্র ব্যাখ্যা থাকবে।
- **সহজে পার্স করার যোগ্য** — গ্রামারটি কার্যকর কম্পাইলার বাস্তবায়নের জন্য ডিজাইন করা।
- **সম্প্রসারণযোগ্য (Extensible)** — ভবিষ্যতের ফিচার যোগ করার সময় বিদ্যমান সিনট্যাক্স ভাঙা যাবে না।

---

## ১.৪ ভাষার দর্শন

কলম একটি সহজ নীতি অনুসরণ করে —

> **সহজপাঠ্যতা বাড়ায় এমন জায়গায় আধুনিক দৈনন্দিন বাংলা ব্যবহার করো।**

ভাষাটি ইচ্ছাকৃতভাবে এমন শব্দ ব্যবহার করে, যা বাংলাভাষীরা দৈনন্দিন জীবনে ও সফটওয়্যার ডেভেলপমেন্টে স্বাভাবিকভাবে ব্যবহার করেন।

**অ্যাপ**, **ফাংশন**, **ইম্পোর্ট**, এবং **টেক্সট**-এর মতো ইতিমধ্যেই ব্যাপকভাবে পরিচিত কারিগরি শব্দ অস্বাভাবিক অনুবাদ দিয়ে প্রতিস্থাপিত না করে অপরিবর্তিত রাখা হয়েছে।

এই দর্শন ভাষাগত বিশুদ্ধতার চেয়ে সহজপাঠ্যতা, পরিচিতি এবং ডেভেলপার প্রোডাক্টিভিটিকে অগ্রাধিকার দেয়।

---

## ১.৫ কনফরম্যান্স

কোনো বাস্তবায়ন যদি **কলম v1.0** সমর্থনের দাবি করে, তাহলে তাকে এই স্পেসিফিকেশনে নির্ধারিত গ্রামার বাস্তবায়ন করতে হবে।

অতিরিক্ত ভাষাগত ফিচার শুধুমাত্র তখনই প্রদান করা যাবে, যদি সেগুলো এই স্পেসিফিকেশনে নির্ধারিত আচরণ বা সিনট্যাক্স পরিবর্তন না করে।

# ২. গ্রামার নোটেশন

## ২.১ ওভারভিউ

এই স্পেসিফিকেশন কলম প্রোগ্রামিং ভাষার সিনট্যাক্স বর্ণনা করতে **Extended Backus–Naur Form (EBNF)** ব্যবহার করে।

EBNF ভাষার গ্রামার বর্ণনা করার একটি সংক্ষিপ্ত ও নিখুঁত উপায়, যা কম্পাইলার ডেভেলপার ও ভাষা কন্ট্রিবিউটর উভয়ের জন্যই সহজে বোধগম্য।

আলাদাভাবে উল্লেখ না থাকলে, এই ডকুমেন্টের সকল গ্রামার প্রোডাকশন এই অধ্যায়ে নির্ধারিত নোটেশন অনুসরণ করে।

---

## ২.২ গ্রামার রুল

একটি গ্রামার রুল একটি ভাষাগত তথ্যের কাঠামো নির্ধারণ করে।

উদাহরণ:

```ebnf
VariableDeclaration =
    "ধরি"
    Identifier
    [ ":" Type ]
    "="
    Expression ;
```

বাম পাশ গ্রামার রুলটি নির্ধারণ করে।

ডান পাশ সেই টোকেন সিকোয়েন্স নির্ধারণ করে, যা রুলটি সিদ্ধ (satisfy) করে।

---

## ২.৩ EBNF সিম্বল

| সিম্বল | অর্থ | উদাহরণ |
|---------|---------|---------|
| `=` | একটি গ্রামার রুল নির্ধারণ করে | `Expression = ... ;` |
| `;` | একটি গ্রামার রুল শেষ করে | `Statement = ... ;` |
| `|` | বিকল্প (Alternative) | `Letter = BanglaLetter \| EnglishLetter ;` |
| `[]` | ঐচ্ছিক (Optional) এলিমেন্ট | `[ ":" Type ]` |
| `{}` | শূন্য বা তার বেশি পুনরাবৃত্তি | `{ Statement }` |
| `()` | গ্রুপিং | `( Expression )` |
| `""` | লিটারেল কীওয়ার্ড বা সিম্বল | `"অ্যাপ"` |
| `Identifier` | নন-টার্মিনাল | `Identifier` |
| `? ... ?` | স্পেশাল সিকোয়েন্স — যে সিমান্টিক শর্ত বিশুদ্ধ EBNF দিয়ে প্রকাশ করা যায় না, তা প্রোজ দিয়ে বর্ণনা করে | `? any Unicode code point except '"' ?` |

---

## ২.৪ টার্মিনাল সিম্বল

টার্মিনাল সিম্বল কলম সোর্স ফাইলে সত্যিকারের যে টেক্সট দেখা যায়, তা প্রতিনিধিত্ব করে।

উদাহরণ:

```text
অ্যাপ
ধরি
ফাংশন
{
}
(
)
=
+
```

গ্রামার রুলে ব্যবহার করার সময় টার্মিনাল সিম্বল ডাবল কোটের ভেতরে লেখা হয়।

উদাহরণ:

```ebnf
AppDeclaration =
    "অ্যাপ"
    Identifier?
    Block ;
```

---

## ২.৫ নন-টার্মিনাল সিম্বল

নন-টার্মিনাল সিম্বল অন্য গ্রামার রুলকে নির্দেশ করে।

উদাহরণ:

```text
Program
Expression
Statement
Identifier
Type
Block
```

প্রতিটি নন-টার্মিনাল এই স্পেসিফিকেশনে ঠিক একবারই সংজ্ঞায়িত।

---

## ২.৬ ঐচ্ছিক এলিমেন্ট

ঐচ্ছিক এলিমেন্ট স্কোয়ার ব্র্যাকেটের ভেতরে রাখা হয়।

উদাহরণ:

```ebnf
VariableDeclaration =
    "ধরি"
    Identifier
    [ ":" Type ]
    "="
    Expression ;
```

টাইপ অ্যানোটেশন বাদ দেওয়া যেতে পারে।

বৈধ উদাহরণ:

```kolom
ধরি বয়স = ২৫
```

```kolom
ধরি বয়স: সংখ্যা = ২৫
```

---

## ২.৭ পুনরাবৃত্ত এলিমেন্ট

পুনরাবৃত্ত এলিমেন্ট ব্রেসের (braces) ভেতরে রাখা হয়।

উদাহরণ:

```ebnf
Block =
    "{"
    { Statement }
    "}" ;
```

একটি ব্লকে শূন্য বা তার বেশি স্টেটমেন্ট থাকতে পারে।

---

## ২.৮ বিকল্প (Alternatives)

বিকল্পগুলো উল্লম্ব দণ্ড (`|`) দিয়ে আলাদা করা হয়।

উদাহরণ:

```ebnf
BooleanLiteral =
      "সত্য"
    | "মিথ্যা" ;
```

শুধুমাত্র একটি বিকল্প মিলতে পারে।

---

## ২.৯ গ্রামার কনভেনশন

এই স্পেসিফিকেশন নিম্নলিখিত কনভেনশন অনুসরণ করে —

- গ্রামার রুল কেস-সেনসিটিভ।
- সংরক্ষিত কীওয়ার্ড টার্মিনাল সিম্বল হিসেবে লেখা হয়।
- নন-টার্মিনালের নাম PascalCase-এ লেখা হয়।
- গ্রামার রুল সেমিকোলন (`;`) দিয়ে শেষ হয়।
- স্পষ্টভাবে উল্লেখ না থাকলে টোকেনের মাঝে হোয়াইটস্পেস উপেক্ষা করা হয়।
- গ্রামার প্রোডাকশনে লাইন-ব্রেক শুধুই পাঠযোগ্যতার জন্য, এর কোনো সিমান্টিক অর্থ নেই।

---
| ধারণা      | নোটেশন     |   |
| ------------ | ------------ | - |
| সংজ্ঞা (Definition) | `=`          |   |
| রুলের শেষ  | `;`          |   |
| ঐচ্ছিক     | `[ ... ]`    |   |
| শূন্য বা তার বেশি | `{ ... }`    |   |
| বিকল্প | `            | ` |
| গ্রুপিং     | `( ... )`    |   |
| টার্মিনাল     | `"ধরি"`      |   |
| নন-টার্মিনাল | `Expression` |   |


## ২.১০ উদাহরণ

উদাহরণ গ্রামার:

```ebnf
Program =
    { ImportDeclaration }
    { TopLevelDeclaration }
    AppDeclaration ;
```

উদাহরণ সোর্স কোড:

```kolom
ইম্পোর্ট গণিত

ফাংশন যোগ(সংখ্যা ক, সংখ্যা খ) -> সংখ্যা {

    রিটার্ন ক + খ

}

অ্যাপ {

    ধরি ফল = যোগ(১০, ২০)

    লেখো(ফল)

}
```

উপরের উদাহরণটি এই স্পেসিফিকেশনে নির্ধারিত গ্রামার সিদ্ধ করে। প্যারামিটার সবসময় `Type Identifier` ক্রমে লেখা হয় (§১০.৩-এর `Parameter` রুল অনুযায়ী), `Identifier: Type` ক্রমে নয়।
# ৩. লেক্সিক্যাল গ্রামার

## ৩.১ ওভারভিউ

লেক্সিক্যাল গ্রামার নির্ধারণ করে, কীভাবে একটি কলম সোর্স ফাইল টোকেনের সিকোয়েন্সে রূপান্তরিত হয়।

লেক্সার নিম্নলিখিত বিষয়গুলো চিনতে দায়ী —

- সোর্স ক্যারেক্টার
- হোয়াইটস্পেস
- লাইন টার্মিনেটর
- কমেন্ট
- আইডেন্টিফায়ার
- কীওয়ার্ড
- লিটারেল
- অপারেটর
- পাংকচুয়েশন

পার্সার লেক্সার থেকে উৎপন্ন টোকেন স্ট্রিমের উপর কাজ করে।

---

## ৩.২ সোর্স এনকোডিং

সকল কলম সোর্স ফাইল **অবশ্যই** UTF-8 ব্যবহার করে এনকোড করা থাকতে হবে।

UTF-8 একমাত্র সমর্থিত সোর্স এনকোডিং।

এর ফলে কলম সোর্স কোড স্বাধীনভাবে বাংলা ও অন্যান্য ইউনিকোড ক্যারেক্টার মিশ্রিত করতে পারে।

উদাহরণ

```kolom
ধরি নাম = "রহিম"

ধরি version = "1.0"
```

---

## ৩.৩ সোর্স ফাইল এক্সটেনশন

কলম সোর্স ফাইল নিম্নলিখিত এক্সটেনশন ব্যবহার করে —

```text
.ক
```

উদাহরণ

```text
main.ক

গণিত.ক

app.ক
```

---

## ৩.৪ ইউনিকোড সাপোর্ট

কলম একটি ইউনিকোড-ফার্স্ট প্রোগ্রামিং ভাষা।

আইডেন্টিফায়ার, লেখা লিটারেল এবং ক্যারেক্টার লিটারেলে ইউনিকোড ক্যারেক্টার থাকতে পারে।

উদাহরণ

```kolom
ধরি বয়স = ২৫

ধরি π = 3.14159

ধরি username = "rahim"

ধরি শহর = "ঢাকা"
```

ইউনিকোড নরমালাইজেশন বাস্তবায়ন-নির্ভর (implementation-defined)।

কম্পাইলারের উচিত সোর্স টেক্সট ঠিক যেভাবে লেখা হয়েছে সেভাবেই সংরক্ষণ করা।

---

## ৩.৫ হোয়াইটস্পেস

নিম্নলিখিত ক্যারেক্টারগুলোকে হোয়াইটস্পেস হিসেবে গণ্য করা হয়।

| ক্যারেক্টার | বিবরণ |
|------------|-------------|
| স্পেস | U+0020 |
| ট্যাব | U+0009 |
| ফর্ম ফিড | U+000C |

হোয়াইটস্পেস টোকেন আলাদা করে, কিন্তু অন্য কোনো অর্থ বহন করে না।

লেখা লিটারেলের ভেতরে না থাকলে একাধিক হোয়াইটস্পেস ক্যারেক্টারকে একটিমাত্র বিভাজক (separator) হিসেবে গণ্য করা হয়।

উদাহরণ

```kolom
ধরি    বয়স     =      ২৫
```

এটি নিম্নলিখিতটির সমতুল্য —

```kolom
ধরি বয়স = ২৫
```

---

## ৩.৬ লাইন টার্মিনেটর

নিম্নলিখিত লাইন টার্মিনেটরগুলো স্বীকৃত।

| ক্যারেক্টার | নাম |
|------------|------|
| LF | Line Feed (`\n`) |
| CRLF | Carriage Return + Line Feed (`\r\n`) |

কম্পাইলারের উভয় ফরম্যাটই গ্রহণ করা উচিত।

অভ্যন্তরীণভাবে, বাস্তবায়ন লাইন-এন্ডিং নরমালাইজ করতে পারে।

---

## ৩.৭ স্বয়ংক্রিয় স্টেটমেন্ট টার্মিনেশন

কলম-এ সেমিকোলন ব্যবহার করা হয় না।

স্টেটমেন্ট স্বয়ংক্রিয়ভাবে লাইনের শেষে টার্মিনেট হয়, যদি না স্টেটমেন্টটি স্পষ্টভাবে অসম্পূর্ণ থাকে।

উদাহরণ

```kolom
ধরি বয়স = ২৫

ধরি নাম = "রহিম"

লেখো(নাম)
```

একটি স্টেটমেন্ট একাধিক লাইনজুড়ে চলতে থাকে, যদি তা নিম্নলিখিত কোনোটির ভেতরে আবদ্ধ থাকে —

- প্যারেনথেসিস `()`
- ব্র্যাকেট `[]`

ব্রেস `{}` এই তালিকায় নেই — `{}`-এর ভেতরে নিউলাইন স্বাভাবিকভাবেই উৎপন্ন হতে থাকে, কারণ `Block`-এর (§১২.১) ভেতরে সেটিই স্টেটমেন্ট বিভাজক (§১৮.২)।

উদাহরণ

```kolom
ধরি ফল =
    যোগ(
        ১০,
        ২০
    )
```

পুরো ডিক্লারেশনটি একটিমাত্র স্টেটমেন্ট হিসেবে গণ্য হয়।

---

## ৩.৮ কমেন্ট

কলম দুই ধরনের কমেন্ট সমর্থন করে।

### সিঙ্গেল-লাইন কমেন্ট

সিঙ্গেল-লাইন কমেন্ট শুরু হয় —

```text
//
```

`//` থেকে লাইনের শেষ পর্যন্ত সবকিছু উপেক্ষা করা হয়।

উদাহরণ

```kolom
// ব্যবহারকারীর তথ্য

ধরি নাম = "রহিম"
```

---

### মাল্টি-লাইন কমেন্ট

মাল্টি-লাইন কমেন্ট শুরু হয় —

```text
/*
```

এবং শেষ হয় —

```text
*/
```

উদাহরণ

```kolom
/*
এই ফাংশনটি
কর হিসাব করে।
*/
```

নেস্টেড মাল্টি-লাইন কমেন্ট সমর্থিত **নয়**।

## ৩.৯ কেস সেনসিটিভিটি

কীওয়ার্ড কেস-সেনসিটিভ।

আইডেন্টিফায়ার কেস-সেনসিটিভ।

## ৩.১০ টোকেনাইজেশন

লেক্সার সবসময় দীর্ঘতম বৈধ টোকেনটি বেছে নেয়।

উদাহরণ

```text
==
```

এটি একটি একক ইকোয়ালিটি অপারেটর হিসেবে গণ্য হয়,

দুটি পরপর অ্যাসাইনমেন্ট অপারেটর হিসেবে নয়।

একইভাবে,

```text
>=
<=
!=
```

এগুলো একক টোকেন হিসেবে গণ্য হয়।

## ৩.১১ অবৈধ ক্যারেক্টার

কোনো ক্যারেক্টার যদি বৈধ কোনো টোকেনের অংশ না হয়, তাহলে তা একটি লেক্সিক্যাল ত্রুটি সৃষ্টি করে।

উদাহরণ

```kolom
ধরি x = @
```

কম্পাইলার

```text
ত্রুটি: main.ক:১:৯

অপ্রত্যাশিত ক্যারেক্টর '@'
```

লেক্সিক্যাল অ্যানালাইসিস শুধুমাত্র ত্রুটি রেকর্ড করার পরেই থামে।

বাস্তবায়নের উচিত যতটা সম্ভব স্ক্যান চালিয়ে যাওয়া, যাতে আরও লেক্সিক্যাল ত্রুটি রিপোর্ট করা যায়।

# ৪. টোকেন

## ৪.১ ওভারভিউ

লেক্সার সোর্স ক্যারেক্টারগুলোকে নিম্নলিখিত টোকেন ক্যাটাগরিতে গ্রুপ করে —

| ক্যাটাগরি | উদাহরণ |
|----------|----------|
| কীওয়ার্ড | `ধরি`, `ফাংশন`, `যদি` |
| আইডেন্টিফায়ার | `বয়স`, `যোগ`, `username` |
| সংখ্যা লিটারেল | `২৫`, `3.14159` |
| লেখা লিটারেল | `"রহিম"` |
| ক্যারেক্টার লিটারেল | `'ক'` |
| বুলিয়ান লিটারেল | `সত্য`, `মিথ্যা` |
| নাল লিটারেল | `ফাঁকা` |
| অপারেটর | `+`, `==`, `->` |
| পাংকচুয়েশন | `(`, `)`, `{`, `}`, `:`, `,` |
| নিউলাইন | লাইনের শেষ, §৩.৭ অনুযায়ী তাৎপর্যপূর্ণ |

## ৪.২ টোকেন প্রায়োরিটি

সোর্স টেক্সট একাধিক টোকেন ক্যাটাগরির সাথে মিলে যেতে পারলে, লেক্সার নিম্নলিখিত ক্রমে সমাধান করে —

১. কমেন্ট (§৩.৮) — বাতিল করা হয়, কখনো টোকেন হিসেবে প্রকাশ পায় না
২. কীওয়ার্ড (§৫) — কেবল তখনই মিলবে যখন প্রার্থী আইডেন্টিফায়ারটি ঠিক কোনো সংরক্ষিত শব্দের সমান
৩. আইডেন্টিফায়ার (§৬)
৪. লিটারেল (§৭)
৫. অপারেটর ও পাংকচুয়েশন (§৮)

কোনো প্রার্থী যদি কীওয়ার্ড ও বৈধ আইডেন্টিফায়ার — উভয়ের সাথেই মিলে যায়, তাহলে সবসময় সেটিকে কীওয়ার্ড হিসেবে টোকেনাইজ করা হয়। কীওয়ার্ডকে আইডেন্টিফায়ার হিসেবে ব্যবহার করা যায় না।

# ৬. আইডেন্টিফায়ার

## ৬.১ গ্রামার

```ebnf
Identifier =
    IdentifierStart { IdentifierPart } ;

IdentifierStart =
      BanglaLetter
    | LatinLetter
    | "_" ;

      IdentifierStart
    | Digit ;
```

`BanglaLetter` এবং `LatinLetter` যথাক্রমে বাংলা বা বেসিক ল্যাটিন অক্ষর ক্যাটাগরির যেকোনো ইউনিকোড কোড পয়েন্ট নির্দেশ করে। আইডেন্টিফায়ারে স্বাধীনভাবে স্ক্রিপ্ট মিশ্রিত করা যায়।

## ৬.২ শর্তাবলী

- একটি আইডেন্টিফায়ার সংখ্যা (digit) দিয়ে শুরু হতে পারবে না।
- একটি আইডেন্টিফায়ার কোনো সংরক্ষিত কীওয়ার্ডের (§৫) সমান হতে পারবে না।
- আইডেন্টিফায়ার কেস-সেনসিটিভ (§৩.৯): `user`, `User`, এবং `USER` ভিন্ন ভিন্ন।

## ৬.৩ উদাহরণ

```kolom
username
_মান
π
```

# ৭. লিটারেল

## ৭.১ সংখ্যা লিটারেল

```ebnf
NumberLiteral =
    Digit { Digit } [ "." Digit { Digit } ] ;

Digit =
      "০".."৯"    (* Bangla-Nagari digits *)
    | "0".."9" ;    (* ASCII digits *)
```

ভগ্নাংশ (fractional part) ছাড়া একটি সংখ্যা লিটারেলের টাইপ `সংখ্যা` (পূর্ণসংখ্যা)। ভগ্নাংশসহ একটি সংখ্যা লিটারেলের টাইপ `দশমিক`। একটি লিটারেলের মধ্যে বাংলা ও ASCII সংখ্যা মিশ্রিত করা যাবে না।

উদাহরণ:

```kolom
২৫
3.14159
১০
```

## ৭.২ লেখা লিটারেল

```ebnf
StringLiteral =
    '"' { StringCharacter } '"' ;

StringCharacter =
      UnescapedCharacter
    | EscapeSequence ;

UnescapedCharacter =
    ? unescaped `"`, `\`, বা লাইন টার্মিনেটর ছাড়া যেকোনো ইউনিকোড কোড পয়েন্ট ? ;

EscapeSequence =
    "\" EscapeCharacter ;

EscapeCharacter =
      "n"                  (* লাইন ফিড *)
    | "t"                  (* ট্যাব *)
    | "r"                  (* ক্যারেজ রিটার্ন *)
    | "\"                  (* ব্যাকস্ল্যাশ *)
    | """                  (* ডাবল কোট *)
    | "'"                  (* সিঙ্গেল কোট *)
    | UnicodeEscape ;

UnicodeEscape =
    "u{" HexDigit { HexDigit } "}" ;

HexDigit =
      "0".."9"
    | "a".."f"
    | "A".."F" ;
```

লেখা লিটারেল ডাবল কোট দিয়ে আবদ্ধ এবং এর টাইপ `লেখা`। এর ভেতরে un-escaped ডাবল কোট, ব্যাকস্ল্যাশ, বা লাইন টার্মিনেটর ছাড়া যেকোনো ইউনিকোড ক্যারেক্টার থাকতে পারে; এই ক্যারেক্টারগুলোর জন্য এস্কেপ সিকোয়েন্স (escape sequence) ব্যবহৃত হয়।

`UnicodeEscape`-এ ১–৬টি হেক্সাডেসিমাল ডিজিট থাকে এবং এর মান অবশ্যই একটি বৈধ ইউনিকোড স্কেলার ভ্যালু হতে হবে — U+10FFFF-এর বেশি নয়, surrogate নয়। অজানা এস্কেপ ক্যারেক্টার (যেমন `\q`) কম্পাইল-টাইম ত্রুটি।

উদাহরণ:

```kolom
ধরি বার্তা = "লাইন ১\nলাইন ২"

ধরি উক্তি = "তিনি বললেন, \"শুভ সকাল\"।"

ধরি ক = "\u{0995}"        // 'ক' — U+0995
```

অবৈধ:

```kolom
"\q"          // ত্রুটি: অজানা এস্কেপ সিকোয়েন্স

"\u{D800}"    // ত্রুটি: surrogate স্কেলার ভ্যালু নয়
```

## ৭.৩ ক্যারেক্টার লিটারেল

```ebnf
CharacterLiteral =
    "'" CharacterLiteralChar "'" ;

CharacterLiteralChar =
      UnescapedSingleCharacter
    | EscapeSequence ;

UnescapedSingleCharacter =
    ? unescaped `'`, `\`, বা লাইন টার্মিনেটর ছাড়া ঠিক একটি ইউনিকোড কোড পয়েন্ট ? ;
```

`CharacterLiteralChar`, `StringCharacter`-এর থেকে ইচ্ছাকৃতভাবে আলাদা নন-টার্মিনাল — দুটির un-escaped বাদ-দেওয়া (excluded) ক্যারেক্টার আলাদা, কারণ ডিলিমিটার আলাদা (`"` বনাম `'`)। §৭.২-এর এস্কেপ সিকোয়েন্সের পূর্ণ সেট উভয় লিটারেলেই বৈধ।

একটি ক্যারেক্টার লিটারেলে ঠিক একটি ইউনিকোড কোড পয়েন্ট থাকে (এস্কেপ সিকোয়েন্স একটিমাত্র কোড পয়েন্ট উৎপাদন করে) এবং এর টাইপ `অক্ষর`।

উদাহরণ:

```kolom
'ক'

'\n'

'\''

'\u{0995}'
```

## ৭.৪ বুলিয়ান লিটারেল

```ebnf
BooleanLiteral =
      "সত্য"
    | "মিথ্যা" ;
```

বুলিয়ান লিটারেলের টাইপ `বুলিয়ান`।

## ৭.৫ নাল লিটারেল

```ebnf
NullLiteral = "ফাঁকা" ;
```

নাল লিটারেলের টাইপ `ফাঁকা`।

# ৮. অপারেটর

## ৮.১ সিম্বলিক অপারেটর

| অপারেটর | অর্থ |
|----------|---------|
| `+` | যোগ (Addition); `লেখা`ও `Type[]` অপারেন্ডের ক্ষেত্রে কনক্যাটিনেশন — দেখুন `language.md` §২০ |

| `%` | মডুলো (Modulo) |
| `=` | অ্যাসাইনমেন্ট |
| `==` | ইকোয়ালিটি |
| `!=` | ইনইকোয়ালিটি |
| `<` | ছোট (Less than) |
| `>` | বড় (Greater than) |
| `<=` | ছোট অথবা সমান |
| `>=` | বড় অথবা সমান |
| `->` | ফাংশন রিটার্ন টাইপ অ্যারো |

| `,` | আর্গুমেন্ট/প্যারামিটার স্প্লিটর |

## ৮.২ কীওয়ার্ড অপারেটর

লজিক্যাল অপারেটর সিম্বলের বদলে সংরক্ষিত শব্দ, যা কলম-এর দৈনন্দিন-বাংলা দর্শনের (`language.md` §২) সাথে সামঞ্জস্যপূর্ণ —

| কীওয়ার্ড | অর্থ |
|---------|---------|
| `এবং` | লজিক্যাল AND |
| `অথবা` | লজিক্যাল OR |
| `না` | লজিক্যাল NOT |

## ৮.৩ টোকেনাইজেশন

§৩.১০ অনুযায়ী, লেক্সার সবসময় দীর্ঘতম বৈধ অপারেটরটি মেলায়: `==`, `!=`, `<=`, `>=`, এবং `->` প্রতিটিই একক টোকেন, ছোট অপারেটরের সিকোয়েন্স নয়।

# ৯. প্রোগ্রাম স্ট্রাকচার

## ৯.১ গ্রামার

```ebnf
Program =
    { ImportDeclaration | TopLevelDeclaration }
    [ AppDeclaration ] ;

TopLevelDeclaration =
      FunctionDeclaration
    | ConstantDeclaration
    | StructDeclaration ;
```

একটি সোর্স ফাইলে যেকোনো সংখ্যক ইম্পোর্ট ডিক্লারেশন, টপ-লেভেল ফাংশন, কনস্ট্যান্ট, বা `তথ্য` ডিক্লারেশন থাকতে পারে, স্বাধীনভাবে মিশ্রিত ও যেকোনো ক্রমে — একটি `ইম্পোর্ট` অন্য একটি ফাংশন বা `তথ্য` ডিক্লারেশনের পরে এলেও বৈধ।

`AppDeclaration` ঐচ্ছিক, কারণ কলম-এ দুই ধরনের সোর্স ফাইল থাকে —

- **এন্ট্রি-পয়েন্ট ফাইল** — একটি `AppDeclaration` থাকে; সরাসরি চালানো (`কলম চালাও`) বা বিল্ড করা (`কলম বিল্ড`) যায়।
- **মডিউল ফাইল** — কোনো `AppDeclaration` থাকে না; শুধু ফাংশন/কনস্ট্যান্ট এক্সপোর্ট করে এবং অন্য ফাইল থেকে `ইম্পোর্ট` (§১৪) করার জন্য বানানো, যেমন `গণিত.ক`।

গ্রামার প্রতি-ফাইল ভিত্তিতে একাধিক `AppDeclaration` প্রতিরোধ করে (কারণ `[ AppDeclaration ]` সর্বোচ্চ একবার মেলে), কিন্তু একটি সম্পূর্ণ প্রজেক্ট জুড়ে ঠিক একটি এন্ট্রি-পয়েন্ট ফাইল থাকা আবশ্যক কিনা তা যাচাই সিমান্টিক অ্যানালাইসিসের কাজ (`compiler.md` §৬), গ্রামারের নয়।

## ৯.২ App ডিক্লারেশন

```ebnf
AppDeclaration =
    "অ্যাপ"
    [ Identifier ]
    Block ;
```

`AppDeclaration` প্রোগ্রামের এন্ট্রি পয়েন্ট। ঐচ্ছিক আইডেন্টিফায়ারটি অ্যাপ্লিকেশনের নাম দেয় এবং, `language.md` §৭ অনুযায়ী, ডিফল্ট এক্সিকিউটেবল নাম হিসেবে ব্যবহৃত হয়।

উদাহরণ:

```kolom
অ্যাপ হিসাব {

}
```

# ১০. ডিক্লারেশন

## ১০.১ ভ্যারিয়েবল ডিক্লারেশন

```ebnf
VariableDeclaration =
    "ধরি"
    Identifier
    [ ":" Type ]
    "="
    Expression ;
```

## ১০.২ কনস্ট্যান্ট ডিক্লারেশন

```ebnf
ConstantDeclaration =
    "ধ্রুবক"
    Identifier
    ":" Type
    "="
    Expression ;
```

`VariableDeclaration`-এর থেকে ভিন্ন, এখানে টাইপ অ্যানোটেশন আবশ্যক, `language.md` §৯ অনুযায়ী।

## ১০.৩ ফাংশন ডিক্লারেশন

```ebnf
FunctionDeclaration =
    "ফাংশন"
    Identifier
    "(" [ ParameterList ] ")"
    "->" Type
    Block ;

ParameterList =
    Parameter { "," Parameter } ;

Parameter =
    Type Identifier ;
```

ফাংশনের প্যারামিটার ও রিটার্ন টাইপ সবসময় স্পষ্ট (explicit), `language.md` §১১ অনুযায়ী। ফাংশন বডির ভেতরে লোকাল ভ্যারিয়েবলে টাইপ ইনফারেন্স ব্যবহার করা যেতে পারে (`: Type` ছাড়া `VariableDeclaration`)।

উদাহরণ:

```kolom
ফাংশন যোগ(সংখ্যা ক, সংখ্যা খ) -> সংখ্যা {

    রিটার্ন ক + খ

}
```

## ১০.৪ ইম্পোর্ট ডিক্লারেশন

```ebnf
ImportDeclaration =
    "ইম্পোর্ট" Identifier ;
```

মডিউল রেজোলিউশন নোটের জন্য দেখুন §১৪।

## ১০.৫ স্ট্রাক্ট ডিক্লারেশন (`তথ্য`)

```ebnf
StructDeclaration =
    "তথ্য"
    Identifier
    "{"
    [ FieldList ]
    "}" ;

FieldList =
    Field { "," Field } [ "," ] ;

Field =
    Identifier ":" Type ;
```

`তথ্য` একটি নির্দিষ্ট (fixed) সেট ফিল্ড সহ একটি নতুন টাইপ ঘোষণা করে —

```kolom
তথ্য ব্যক্তি {
    নাম: লেখা,
    বয়স: সংখ্যা
}
```

ঘোষণার পর, স্ট্রাক্টের নামটি —

- **একটি `Type`** — `Type` গ্রামারের `Identifier` বিকল্পটি (§১১.১) এভাবেই রেজলভ হয়, একটি প্যারামিটার/রিটার্ন/ভ্যারিয়েবল টাইপ হিসেবে অন্য যেকোনো টাইপের মতোই ব্যবহারযোগ্য।
- **একটি কনস্ট্রাক্টর ফাংশন** — `Identifier "(" [ ArgumentList ] ")"`, `CallExpression`-এর (§১৩.১) সাধারণ কল-সিনট্যাক্স দিয়ে, ফিল্ডগুলো ঘোষণার ক্রমে পজিশনালি দিয়ে —

```kolom
ধরি প = ব্যক্তি("রহিম", ২৫)
```

আর্গুমেন্টের সংখ্যা অবশ্যই ফিল্ডের সংখ্যার সমান হতে হবে, এবং প্রতিটি আর্গুমেন্টের টাইপ তার পজিশনের ফিল্ড-টাইপের সাথে মিলতে হবে (§১১.৩-এর অ্যাসাইনমেন্ট-টাইপ নিয়ম অনুযায়ী) — এই দুটিই কম্পাইল-টাইম ত্রুটি, গ্রামারের নয়, সিমান্টিক অ্যানালাইসিসের (`compiler.md` §৬) অংশ।

ফিল্ড পড়া ও লেখা `.` মেম্বার-অ্যাক্সেস দিয়ে হয় (§১৩.১.১) —

```kolom
লেখো(প.নাম)

প.বয়স = ২৬
```

একটি `তথ্য`-এর ফিল্ড অন্য যেকোনো `তথ্য` টাইপ রেফার করতে পারে, ফাইলে পরে ঘোষিত একটি টাইপসহ (`FieldList` পার্স করার আগে সব `StructDeclaration`-এর নাম প্রি-রেজিস্টার হয়)। তবে একটি স্ট্রাক্ট নিজেকে *by value* ধারণ করতে পারে না — সরাসরি বা একাধিক ফিল্ডের চেইন দিয়ে — কারণ এমন টাইপের আকার অসীম হয়ে যেত; `শেয়ার`, অ্যারে বা `ম্যাপ` ফিল্ডের মাধ্যমে (এগুলো পয়েন্টার) নিজেকে বা একটি সাইকেল ধারণ করা বৈধ, এবং এভাবেই রিকার্সিভ ডেটা স্ট্রাকচার (লিস্ট, ট্রি) তৈরি হয়।

`ফিল্ড` স্প্লিটর হিসেবে `","` ব্যবহার করা প্রথাগত (উপরের উদাহরণের মতো), তবে একটি লাইন টার্মিনেটরও (§৩.৬) `","`-এর জায়গায় গ্রহণযোগ্য — `ParameterList`-এর (§১০.৩) বিপরীতে, যা শুধু `","` মানে।

# ১১. টাইপ

## ১১.১ গ্রামার

```ebnf
Type =
      PrimitiveType
    | ArrayType
    | SharedType
    | MapType
    | Identifier ;    (* একটি `তথ্য`-ঘোষিত স্ট্রাক্ট টাইপের নাম — §১০.৫ *)

PrimitiveType =
      "সংখ্যা"
    | "দশমিক"
    | "লেখা"
    | "বুলিয়ান"
    | "অক্ষর"
    | "ফাঁকা" ;

ArrayType =
    Type "[" "]" ;

SharedType =
    "শেয়ার" Type ;

MapType =
    "ম্যাপ" "[" Type "," Type "]" ;
```

## ১১.২ প্রিমিটিভ টাইপ

| টাইপ | বিবরণ |
|------|-------------|
| `সংখ্যা` | পূর্ণসংখ্যা (Integer) |
| `দশমিক` | দশমিক সংখ্যা (Floating point) |
| `লেখা` | UTF-8 লেখা |
| `বুলিয়ান` | বুলিয়ান |
| `অক্ষর` | ইউনিকোড ক্যারেক্টার |
| `ফাঁকা` | নাল |

## ১১.৩ টাইপ ইনফারেন্স

কলম স্বয়ংক্রিয় টাইপ ইনফারেন্সসহ স্ট্যাটিকালি টাইপড (`language.md` §৬)। `: Type` অ্যানোটেশন ছাড়া একটি `VariableDeclaration` তার ইনিশিয়ালাইজার `Expression`-এর টাইপ গ্রহণ করে। একবার নির্ধারিত হলে, একটি ভ্যারিয়েবলের টাইপ পরিবর্তন করা যায় না —

```kolom
ধরি বয়স = ২৫

বয়স = "রহিম"
```

```text
ত্রুটি

'বয়স' একটি সংখ্যা।

এখানে লেখা নির্ধারণ করা যাবে না।
```

## ১১.৪ অ্যারে টাইপ

যেকোনো টাইপের পরে `[]` যোগ করে একটি সমসত্ত্ব (homogeneous) অ্যারে টাইপ তৈরি করা যায়, `language.md` §১০ অনুযায়ী —

```kolom
ধরি সংখ্যাসমূহ: সংখ্যা[] = [১০, ২০, ৩০]

ধরি নামসমূহ = ["রহিম", "করিম"]
```

একটি `ArrayLiteral` (§১৩.১) তার এলিমেন্ট থেকে `ArrayType` ইনফার করে; প্রতিটি এলিমেন্টের টাইপ একই হতে হবে, নয়তো কম্পাইলার লিটারেলটি প্রত্যাখ্যান করবে (§১১.৩-এর অ্যাসাইনমেন্ট নিয়ম প্রতিটি এলিমেন্টে প্রযোজ্য)।

একটি খালি `ArrayLiteral` (`[]`)-এর কোনো এলিমেন্ট নেই, তাই টাইপ ইনফার করা যায় না — এক্ষেত্রে `: Type[]` অ্যানোটেশন আবশ্যক (§১০.১):

```kolom
ধরি খালি: সংখ্যা[] = []
```

অ্যানোটেশন ছাড়া একটি খালি `[]` কম্পাইল-টাইম ত্রুটি।

এলিমেন্ট অ্যাক্সেস `CallSuffix`-এর ইনডেক্স ফর্ম দিয়ে হয় (§১৩.১) —

```kolom
ধরি সংখ্যাসমূহ: সংখ্যা[] = [১০, ২০, ৩০]

লেখো(সংখ্যাসমূহ[০])

সংখ্যাসমূহ[০] = ৯৯
```

`ArrayType`, কলম ভবিষ্যতে যদি জেনেরিক কন্টেইনার যোগ করে (`language.md` §১৯-এ Generics ভবিষ্যৎ ফিচার হিসেবে তালিকাভুক্ত), তার থেকে আলাদা এবং তার দ্বারা প্রতিস্থাপিত হবে না — দুটি স্বাধীন, যেমন Java বা C#-এ অ্যারে ও জেনেরিক কালেকশন পাশাপাশি সহাবস্থান করে।

`ForEachStatement` গ্রামারে (§১২.৫) `Iterable`-এর সমাধান এভাবে করা হয়েছে: যেকোনো `Expression`, যার স্ট্যাটিক টাইপ একটি `ArrayType`। এটি একটি সিমান্টিক-অ্যানালাইসিস শর্ত (`compiler.md` §৬), সিনট্যাক্টিক নয় — গ্রামার সেই অবস্থানে যেকোনো `Expression` গ্রহণ করে, এবং টাইপ চেকিং অ্যারে-নয় এমন iterand প্রত্যাখ্যান করে।

## ১১.৫ শেয়ার্ড টাইপ (`শেয়ার`)

যেকোনো টাইপের আগে `শেয়ার` কীওয়ার্ড বসিয়ে একটি রেফারেন্স-কাউন্টেড শেয়ার্ড টাইপ তৈরি করা যায় —

```kolom
ধরি ক: শেয়ার সংখ্যা = শেয়ার_করো(৫)

ধরি খ = ক

লেখো(খ)
```

`শেয়ার Type` কলম-এর ওনারশিপ মডেলে (`language.md` §২২, `compiler.md` §১০) একমাত্র ব্যতিক্রম, যেখানে অ্যাসাইনমেন্ট মুভ না করে হ্যান্ডেল কপি করে (রেফারেন্স কাউন্ট বাড়িয়ে) — উপরের উদাহরণে `ক` অ্যাসাইনমেন্টের পরও বৈধ থাকে, যা সাধারণ `লেখা`/`Type[]`-এর ক্ষেত্রে হতো না (§১১.৪, `language.md` §২২)।

`SharedType`-এর জন্য `<>` জেনেরিক-প্যারামিটার সিনট্যাক্স ব্যবহার করা হয়নি — এটি ভবিষ্যতের সাধারণ জেনেরিক্স ফিচারের (`language.md` §১৯) পূর্বসূরি নয়, বরং `ArrayType`-এর মতোই একটি স্বতন্ত্র, হার্ডকোডেড টাইপ-কনস্ট্রাক্টর।

## ১১.৬ ম্যাপ টাইপ (`ম্যাপ`)

`MapType`-এর `[` `]` `ArrayType`-এর ইনডেক্স ব্র্যাকেটের মতো নয় — এখানে দুটি `Type` কমা দিয়ে আলাদা, key ও value —

```kolom
ধরি বয়সসমূহ: ম্যাপ[লেখা, সংখ্যা] = ম্যাপ_তৈরি()
```

key টাইপ অবশ্যই `লেখা` বা `সংখ্যা` হতে হবে — এই শর্ত সিমান্টিক অ্যানালাইসিসে (`compiler.md` §৬) যাচাই করা হয়, গ্রামারে নয়। value টাইপ যেকোনো `Type` হতে পারে।

`ArrayLiteral`-এর (§১৩.১) বিপরীতে একটি ম্যাপের কোনো লিটারেল সিনট্যাক্স নেই — একটি খালি ম্যাপ তৈরি হয় গ্লোবাল বিল্ট-ইন ফাংশন `ম্যাপ_তৈরি()` দিয়ে (`language.md` §২১), যার নিজের কোনো টাইপ তথ্য বহন করে না, তাই এটি শুধুমাত্র একটি টাইপ-টীকাযুক্ত `VariableDeclaration`-এর (§১০.১) ইনিশিয়ালাইজার হিসেবেই বৈধ — `ArrayType`-এর খালি `[]`-এর (§১১.৪) মতোই আচরণ, একই কারণে।

এন্ট্রি পড়া ও লেখা `CallSuffix`-এর ইনডেক্স ফর্ম দিয়েই হয় (§১৩.১), অ্যারের মতোই — কিন্তু একটি সিমান্টিক পার্থক্যসহ: ম্যাপে ইনডেক্স-অ্যাসাইনমেন্ট (`m[k] = v`) সবসময় বৈধ (নতুন key হলে ইনসার্ট করে, না হলে আপডেট করে), যেখানে অ্যারেতে ইনডেক্স অবশ্যই বিদ্যমান সীমার ভেতরে হতে হয়। একটি অনুপস্থিত key পড়া একটি রানটাইম ত্রুটি, যা `চেষ্টা`/`ধরো` দিয়ে ধরা যায় (§১২.৮)।

ম্যাপ-নির্দিষ্ট বিল্ট-ইন ফাংশন (`ম্যাপ_তৈরি`, `আছে_কি`, `চাবি_গুলো`, `চাবি_মুছো`) `ম্যাপ`-এর মেম্বার নয়, বরং গ্লোবাল ফাংশন — সম্পূর্ণ তালিকার জন্য দেখুন `language.md` §২১।

# ১২. স্টেটমেন্ট

## ১২.১ গ্রামার

```ebnf
Statement =
      VariableDeclaration
    | ConstantDeclaration
    | IfStatement
    | LoopStatement
    | WhileStatement
    | ForEachStatement
    | ReturnStatement
    | BreakStatement
    | ContinueStatement
    | TryCatchStatement
    | ExpressionStatement
    | Block ;

Block =
    "{"
    { Statement }
    "}" ;
```

প্রতিটি `Statement` স্বয়ংক্রিয় স্টেটমেন্ট টার্মিনেশন নিয়ম (§৩.৭) অনুযায়ী শেষ হয়, সেমিকোলন দিয়ে নয়।

## ১২.২ If স্টেটমেন্ট

```ebnf
IfStatement =
    "যদি" "(" Expression ")" Block
    [ "নাহলে" ( IfStatement | Block ) ] ;
```

উদাহরণ:

```kolom
যদি (বয়স >= ১৮) {

    লেখো("প্রাপ্তবয়স্ক")

} নাহলে {

    লেখো("নাবালক")

}
```

## ১২.৩ Loop স্টেটমেন্ট

```ebnf
LoopStatement =
    "লুপ" "(" Expression ")" Block ;
```

`Expression`-এ দেওয়া সংখ্যক বার `Block` পুনরাবৃত্তি করে, যার টাইপ অবশ্যই `সংখ্যা` হতে হবে।

## ১২.৪ While স্টেটমেন্ট

```ebnf
WhileStatement =
    "যতক্ষণ" "(" Expression ")" Block ;
```

`Expression` যতক্ষণ `সত্য` ফেরত দেয়, ততক্ষণ `Block` পুনরাবৃত্তি করে।

## ১২.৫ For-Each স্টেটমেন্ট

```ebnf
ForEachStatement =
    "প্রতি" "(" Identifier ":" Iterable ")" Block ;

Iterable =
    Expression ;
```

সিনট্যাক্টিকভাবে `Iterable` একটি সাধারণ `Expression`-এর সমতুল্য — গ্রামার এখানে কোনো বিধিনিষেধ দেয় না। `Iterable`-কে `Expression` থেকে আলাদা নাম দেওয়া হয়েছে শুধু পাঠযোগ্যতার জন্য, যাতে সিমান্টিক শর্তটি স্পষ্টভাবে বলা যায়: এর স্ট্যাটিক টাইপ অবশ্যই একটি `ArrayType` হতে হবে (§১১.৪), যা যাচাই করা হয় সিমান্টিক অ্যানালাইসিসে (`compiler.md` §৬), পার্সিংয়ে নয়।

## ১২.৬ Return, Break, Continue

```ebnf
ReturnStatement =
    "রিটার্ন" [ Expression ] ;

BreakStatement =
    "বিরতি" ;

ContinueStatement =
    "চলবে" ;
```

`ReturnStatement` শুধুমাত্র একটি `FunctionDeclaration` বডির ভেতরে বৈধ। `BreakStatement` ও `ContinueStatement` শুধুমাত্র `LoopStatement`, `WhileStatement`, বা `ForEachStatement`-এর ভেতরে বৈধ।

## ১২.৭ Expression স্টেটমেন্ট

```ebnf
ExpressionStatement =
    Expression ;
```

একটি স্বতন্ত্র এক্সপ্রেশন, যা তার সাইড এফেক্টের জন্য মূল্যায়ন করা হয় — সাধারণত একটি ফাংশন কল —

```kolom
লেখো("হ্যালো বিশ্ব")
```

## ১২.৮ Try/Catch স্টেটমেন্ট

```ebnf
TryCatchStatement =
    "চেষ্টা" Block
    "ধরো" "(" Identifier ")" Block ;
```

```kolom
ইম্পোর্ট ফাইল

চেষ্টা {

    ধরি content = ফাইল.পড়ো("নেই_এমন_ফাইল.txt")

    লেখো(content)

} ধরো(ত) {

    লেখো("ধরা হয়েছে:")

    লেখো(ত)

}
```

কলম-এ কোনো `throw`/`raise` স্টেটমেন্ট নেই — একমাত্র ব্যর্থতা যা `চেষ্টা` ধরতে পারে তা রানটাইম নিজেই তোলে (ফাইল/নেটওয়ার্ক I/O ত্রুটি, শূন্য দিয়ে ভাগ, অ্যারে ইনডেক্স সীমার বাইরে, অনুপস্থিত ম্যাপ key)। `Block`-এর ভেতরে ব্যর্থতা ঘটলে নিয়ন্ত্রণ তৎক্ষণাৎ `ধরো`-এর `Block`-এ চলে যায়, ব্যর্থতা-বার্তা `Identifier`-এ (`লেখা` টাইপ) বাউন্ড হয়ে; ব্যর্থতা না ঘটলে `ধরো`-এর `Block` চলে না। `চেষ্টা` ব্লকের বাইরে একই ব্যর্থতা প্রোগ্রাম বন্ধ করে দেয়, স্পষ্ট বাংলা বার্তাসহ (§১৯.৩)।

`TryCatchStatement` কোনো লুপের ভেতরে থাকা আবশ্যক নয় — `BreakStatement`/`ContinueStatement`-এর বিপরীতে (§১২.৬), যেগুলো একটি ঘিরে-রাখা `LoopStatement`/`WhileStatement`/`ForEachStatement` চায়।

# ১৩. এক্সপ্রেশন

## ১৩.১ গ্রামার

```ebnf
Expression =
    AssignmentExpression ;

AssignmentExpression =
      AssignmentTarget "=" AssignmentExpression
    | LogicalOrExpression ;

AssignmentTarget =
    Identifier { "[" Expression "]" } [ "." Identifier ] ;

LogicalOrExpression =
    LogicalAndExpression { "অথবা" LogicalAndExpression } ;

LogicalAndExpression =
    EqualityExpression { "এবং" EqualityExpression } ;

EqualityExpression =
    RelationalExpression { ( "==" | "!=" ) RelationalExpression } ;

RelationalExpression =
    AdditiveExpression { ( "<" | ">" | "<=" | ">=" ) AdditiveExpression } ;

AdditiveExpression =
    MultiplicativeExpression { ( "+" | "-" ) MultiplicativeExpression } ;

MultiplicativeExpression =
    UnaryExpression { ( "*" | "/" | "%" ) UnaryExpression } ;

UnaryExpression =
      ( "-" | "না" ) UnaryExpression
    | CallExpression ;

CallExpression =
    PrimaryExpression { CallSuffix } ;

CallSuffix =
      "(" [ ArgumentList ] ")"
    | "[" Expression "]"
    | "." Identifier ;

ArgumentList =
    Expression { "," Expression } ;

PrimaryExpression =
      Identifier [ "." Identifier ]
    | NumberLiteral
    | StringLiteral
    | CharacterLiteral
    | BooleanLiteral
    | NullLiteral
    | ArrayLiteral
    | "(" Expression ")" ;

ArrayLiteral =
    "[" [ ArgumentList ] "]" ;
```

`ArrayLiteral` `ArgumentList` (§১৩.১) পুনরায় ব্যবহার করে — একটি অ্যারে লিটারেল সিনট্যাক্টিকভাবে একটি ব্র্যাকেটবদ্ধ, কমা দিয়ে আলাদা করা এক্সপ্রেশন তালিকা, যা ফাংশন কল আর্গুমেন্টের মতোই, শুধু `(` `)`-এর বদলে `[` `]` দিয়ে আবদ্ধ।

`CallSuffix`-এর `"[" Expression "]"` বিকল্পটি অ্যারে/ম্যাপ ইনডেক্সিং — একটি `CallExpression` চেইনে একাধিক কল, ইনডেক্স ও ফিল্ড সাফিক্স মিশিয়ে ব্যবহার করা যায় (যেমন `যোগফল(তালিকা)[০]`, `প.বাসা.শহর`)। অ্যারে ইনডেক্সিং এক্সপ্রেশন অবশ্যই `সংখ্যা` টাইপের হতে হবে; ম্যাপ ইনডেক্সিং এক্সপ্রেশন ম্যাপের key-টাইপের হতে হবে (§১১.৬)। এই শর্তগুলো সিমান্টিক অ্যানালাইসিসে (`compiler.md` §৬) যাচাই করা হয়, গ্রামারে নয়।

অ্যাসাইনমেন্টের বাম পাশ (`AssignmentTarget`) ইচ্ছাকৃতভাবে `CallExpression`-এর চেয়ে সংকীর্ণ (narrower) — এটি একটি সাধারণ আইডেন্টিফায়ার, তার পরে এক বা একাধিক `[ Expression ]` ইনডেক্স, তার পরে (ঐচ্ছিকভাবে) একটি একক `.` ফিল্ড গ্রহণ করে (যেমন `ধরি`-করা একটি ভ্যারিয়েবল, `ম্যাট্রিক্স[i][j]`, `ম্যাপ["key"]`, বা `প.বয়স`), কিন্তু ফাংশন কলের ফলাফলে সরাসরি অ্যাসাইন করা যায় না (যেমন `যোগ(ক, খ) = ৫` অবৈধ) — ফাংশন কলের ফলাফল কোনো ভ্যালু, ঠিকানা (location) নয়। নেস্টেড ফিল্ড রাইট (যেমন `প.বাসা.শহর = "..."`, একাধিক `.` লেজ) বর্তমানে সমর্থিত নয়, যদিও রিড (`CallSuffix`-এর মাধ্যমে) সমর্থিত।

### ১৩.১.১ মেম্বার অ্যাক্সেস (`.`) — মডিউল আইটেম বনাম স্ট্রাক্ট ফিল্ড

`Identifier "." Identifier` — `PrimaryExpression`-এ একবার, অথবা `CallSuffix`-এ (ফলে `CallExpression` চেইনের যেকোনো ধাপে) — দুটি ভিন্ন জিনিস বোঝাতে পারে, যা গ্রামার নিজে আলাদা করে না —

- **মডিউল আইটেম** — বাম দিকটি একটি ইম্পোর্ট করা মডিউলের নাম হলে (`language.md` §১২): `গণিত.পাই`, `ফাইল.পড়ো(পথ)`।
- **স্ট্রাক্ট ফিল্ড** — বাম দিকটি একটি লোকাল `তথ্য`-টাইপড ভ্যারিয়েবলে রেজলভ হলে (§১০.৫): `প.নাম`, `প.বয়স`।

এই দ্ব্যর্থতা সিনট্যাক্সে অমীমাংসিত রেখে সিমান্টিক অ্যানালাইসিসে (`compiler.md` §৬) সমাধান করা হয় — বাম দিকের আইডেন্টিফায়ারটি একটি লোকাল স্ট্রাক্ট-টাইপড বাইন্ডিং হিসেবে রেজলভ হয় কিনা তা দিয়ে। এভাবেই `প.বাসা.শহর`-এর মতো একটি চেইন কাজ করে: `প.বাসা` প্রথমে (`PrimaryExpression`-এর `[ "." Identifier ]` দিয়ে) একটি মেম্বার-অ্যাক্সেসে পার্স হয়, তারপর `.শহর` (`CallSuffix`-এর `"." Identifier` দিয়ে) আরেকটি মেম্বার-অ্যাক্সেস যোগ করে — গ্রামার দুই ধাপ সমানভাবে পার্স করে, সিমান্টিক অ্যানালাইসিস প্রতিটি ধাপে নির্ধারণ করে সেটি মডিউল-আইটেম নাকি ফিল্ড।

## ১৩.২ অপারেটর প্রায়োরিটি

# ১৪. মডিউল

## ১৪.১ ওভারভিউ

`ImportDeclaration` (§১০.৪) তার মডিউল আইডেন্টিফায়ার দিয়ে একটি মডিউলের এক্সপোর্ট করা নাম স্কোপে নিয়ে আসে —

```kolom
ইম্পোর্ট গণিত

ইম্পোর্ট সময়

ইম্পোর্ট জেসন
```

## ১৪.২ সুযোগ (Scope)

এই ডকুমেন্ট শুধুমাত্র `ImportDeclaration`-এর সিনট্যাক্স নির্ধারণ করে। মডিউল রেজোলিউশন (ফাইল লুকআপ, স্ট্যান্ডার্ড লাইব্রেরি বনাম ইউজার মডিউল বনাম KPM প্যাকেজ) রানটাইম/টুলচেইন আচরণ, যা `compiler.md` §৮-এ এবং `language.md` §১২.১.৩-এ (কলম প্যাকেজ ম্যানেজার — KPM) আলোচিত হয়েছে।

# ১৫. নেটিভ UI গ্রামার

## ১৫.১ গ্রামার

```ebnf
DisplayDeclaration =
    "ডিসপ্লে" Block ;

WidgetCall =
    WidgetKeyword "(" [ ArgumentList ] ")" ;

WidgetKeyword =
      "টেক্সট"
    | "বাটন"
    | "ইনপুট"
    | "ছবি"
    | "ক্যানভাস"
    | "সারি"
    | "কলাম"
    | "কার্ড"
    | "ডায়ালগ"
    | "স্ক্রল" ;
```

`DisplayDeclaration` শুধুমাত্র একটি `AppDeclaration`-এর `Block`-এর সরাসরি ভেতরে থাকতে পারে। একটি `WidgetCall` সিনট্যাক্টিকভাবে একটি `ExpressionStatement` (§১২.৭), যার callee ইউজার আইডেন্টিফায়ারের বদলে একটি সংরক্ষিত `WidgetKeyword`; `সারি`, `কলাম`, `কার্ড`, `ডায়ালগ`, এবং `স্ক্রল` অতিরিক্তভাবে নেস্টেড উইজেটের একটি অনুগামী `Block` গ্রহণ করে, যেহেতু এগুলো কন্টেইনার।

ইভেন্ট হ্যান্ডলার (v0.৫) — `বাটন`-এর দ্বিতীয় পজিশনাল আর্গুমেন্ট ঐচ্ছিকভাবে একটি হ্যান্ডলার: শূন্য-প্যারামিটার টপ-লেভেল ফাংশনের নাম —

```kolom
বাটন("+১", বাড়াও)
```

এটি নতুন কোনো গ্রামার রুল নয় — `ArgumentList` ইতিমধ্যেই যেকোনো `Expression` গ্রহণ করে; "আইডেন্টিফায়ারটি জ্ঞাত শূন্য-প্যারামিটার ফাংশন" শর্তটি সিমান্টিক অ্যানালায়সিসের (`compiler.md` §৬) যাচাই।

কন্টেইনার ফর্ম:

```ebnf
ContainerWidgetCall =
    ContainerWidgetKeyword "(" [ ArgumentList ] ")" Block ;

ContainerWidgetKeyword =
      "সারি"
    | "কলাম"
    | "কার্ড"
    | "ডায়ালগ"
    | "স্ক্রল" ;
```

# ১৬. সম্পূর্ণ EBNF

এই অধ্যায় দ্রুত রেফারেন্সের জন্য §৬–§১৫-এ নির্ধারিত প্রতিটি গ্রামার রুল একত্র করেছে। এটি নতুন কোনো রুল সেট নয় — নিজস্ব অধ্যায়ে নির্ধারিত রুলের সাথে কখনো অমিল হলে, সেই অধ্যায়-স্তরের সংজ্ঞাই চূড়ান্ত ধরা হবে।

```ebnf
(* Program structure — §9 *)
Program =
    { ImportDeclaration | TopLevelDeclaration }
    [ AppDeclaration ] ;

TopLevelDeclaration =
      FunctionDeclaration
    | ConstantDeclaration
    | StructDeclaration ;

AppDeclaration =
    "অ্যাপ" [ Identifier ] Block ;

(* Declarations — §10 *)
VariableDeclaration =
    "ধরি" Identifier [ ":" Type ] "=" Expression ;

ConstantDeclaration =
    "ধ্রুবক" Identifier ":" Type "=" Expression ;

FunctionDeclaration =
    "ফাংশন" Identifier "(" [ ParameterList ] ")" "->" Type Block ;

ParameterList =
    Parameter { "," Parameter } ;

Parameter =
    Type Identifier ;

ImportDeclaration =
    "ইম্পোর্ট" Identifier ;

StructDeclaration =
    "তথ্য" Identifier "{" [ FieldList ] "}" ;

FieldList =
    Field { "," Field } [ "," ] ;

Field =
    Identifier ":" Type ;

(* Types — §11 *)
Type =
      PrimitiveType
    | ArrayType
    | SharedType
    | MapType
    | Identifier ;

PrimitiveType =
      "সংখ্যা" | "দশমিক" | "লেখা" | "বুলিয়ান" | "অক্ষর" | "ফাঁকা" ;

ArrayType =
    Type "[" "]" ;

SharedType =
    "শেয়ার" Type ;

MapType =
    "ম্যাপ" "[" Type "," Type "]" ;

(* Statements — §12 *)
Statement =
      VariableDeclaration
    | ConstantDeclaration
    | IfStatement
    | LoopStatement
    | WhileStatement
    | ForEachStatement
    | ReturnStatement
    | BreakStatement
    | ContinueStatement
    | TryCatchStatement
    | ExpressionStatement
    | Block ;

Block =
    "{" { Statement } "}" ;

IfStatement =
    "যদি" "(" Expression ")" Block [ "নাহলে" ( IfStatement | Block ) ] ;

LoopStatement =
    "লুপ" "(" Expression ")" Block ;

WhileStatement =
    "যতক্ষণ" "(" Expression ")" Block ;

ForEachStatement =
    "প্রতি" "(" Identifier ":" Iterable ")" Block ;

Iterable =
    Expression ;

ReturnStatement =
    "রিটার্ন" [ Expression ] ;

BreakStatement =
    "বিরতি" ;

ContinueStatement =
    "চলবে" ;

TryCatchStatement =
    "চেষ্টা" Block "ধরো" "(" Identifier ")" Block ;

ExpressionStatement =
    Expression ;

(* Expressions — §13 *)
Expression =
    AssignmentExpression ;

AssignmentExpression =
      AssignmentTarget "=" AssignmentExpression
    | LogicalOrExpression ;

AssignmentTarget =
    Identifier { "[" Expression "]" } [ "." Identifier ] ;

LogicalOrExpression =
    LogicalAndExpression { "অথবা" LogicalAndExpression } ;

LogicalAndExpression =
    EqualityExpression { "এবং" EqualityExpression } ;

EqualityExpression =
    RelationalExpression { ( "==" | "!=" ) RelationalExpression } ;

RelationalExpression =
    AdditiveExpression { ( "<" | ">" | "<=" | ">=" ) AdditiveExpression } ;

AdditiveExpression =
    MultiplicativeExpression { ( "+" | "-" ) MultiplicativeExpression } ;

MultiplicativeExpression =
    UnaryExpression { ( "*" | "/" | "%" ) UnaryExpression } ;

UnaryExpression =
      ( "-" | "না" ) UnaryExpression
    | CallExpression ;

CallExpression =
    PrimaryExpression { CallSuffix } ;

CallSuffix =
      "(" [ ArgumentList ] ")"
    | "[" Expression "]"
    | "." Identifier ;

ArgumentList =
    Expression { "," Expression } ;

PrimaryExpression =
      Identifier [ "." Identifier ]
    | NumberLiteral | StringLiteral | CharacterLiteral | BooleanLiteral | NullLiteral
    | ArrayLiteral
    | "(" Expression ")" ;

ArrayLiteral =
    "[" [ ArgumentList ] "]" ;

(* Native UI — §15 *)
DisplayDeclaration =
    "ডিসপ্লে" Block ;

WidgetCall =
    WidgetKeyword "(" [ ArgumentList ] ")" ;

ContainerWidgetCall =
    ContainerWidgetKeyword "(" [ ArgumentList ] ")" Block ;

WidgetKeyword =
      "টেক্সট" | "বাটন" | "ইনপুট" | "ছবি" | "ক্যানভাস"
    | ContainerWidgetKeyword ;

ContainerWidgetKeyword =
      "সারি" | "কলাম" | "কার্ড" | "ডায়ালগ" | "স্ক্রল" ;

(* Lexical — §6, §7 *)
Identifier =
    IdentifierStart { IdentifierPart } ;

IdentifierStart =
      BanglaLetter | LatinLetter | "_" ;

IdentifierPart =
      IdentifierStart | Digit ;

NumberLiteral =
    Digit { Digit } [ "." Digit { Digit } ] ;

Digit =
      "০".."৯" | "0".."9" ;

StringLiteral =
    '"' { StringCharacter } '"' ;

StringCharacter =
      UnescapedCharacter
    | EscapeSequence ;

UnescapedCharacter =
    ? unescaped `"`, `\`, বা লাইন টার্মিনেটর ছাড়া যেকোনো ইউনিকোড কোড পয়েন্ট ? ;

EscapeSequence =
    "\" EscapeCharacter ;

EscapeCharacter =
      "n" | "t" | "r"
    | "\" | """ | "'"
    | UnicodeEscape ;

UnicodeEscape =
    "u{" HexDigit { HexDigit } "}" ;

HexDigit =
      "0".."9" | "a".."f" | "A".."F" ;

CharacterLiteral =
    "'" CharacterLiteralChar "'" ;

CharacterLiteralChar =
      UnescapedSingleCharacter
    | EscapeSequence ;

UnescapedSingleCharacter =
    ? unescaped `'`, `\`, বা লাইন টার্মিনেটর ছাড়া ঠিক একটি ইউনিকোড কোড পয়েন্ট ? ;

BooleanLiteral =
      "সত্য" | "মিথ্যা" ;

NullLiteral =
    "ফাঁকা" ;
```

# ১৭. AST ম্যাপিং

প্রতিটি গ্রামার রুল আলাদা AST নোড টাইপে ম্যাপ হয় না — `kolom-syntax` ক্রেটের প্রকৃত `ast.rs`-এ একাধিক গ্রামার রুল প্রায়ই একটিমাত্র নোড টাইপে একীভূত (নিচের টেবিল ও তার পরের প্রোজ দেখুন), এবং `.` মেম্বার অ্যাক্সেস (§১৩.১.১) প্রেক্ষাপট অনুযায়ী দুই ভিন্ন প্রতিনিধিত্বে ম্যাপ হয়।

| গ্রামার রুল | AST নোড |
|--------------|----------|
| `Program` | `Program` |
| `AppDeclaration` | `AppDecl` |
| `VariableDeclaration` | `VarDecl` |
| `ConstantDeclaration` | `ConstDecl` |
| `FunctionDeclaration` | `FuncDecl` |
| `ImportDeclaration` | পৃথক কোনো নোড নেই — মডিউল আইডেন্টিফায়ারটি সরাসরি `Ident` হিসেবে `Program.imports`-এ জমা হয় |
| `Block` | `Block` |
| `IfStatement` | `IfStmt` |
| `LoopStatement` | `LoopStmt` |
| `WhileStatement` | `WhileStmt` |
| `ForEachStatement` | `ForEachStmt` |
| `ReturnStatement` | `ReturnStmt` |
| `BreakStatement` | পৃথক কোনো নোড নেই — `Stmt::Break(Pos)`, শুধু উৎস-অবস্থান বহন করে |
| `ContinueStatement` | পৃথক কোনো নোড নেই — `Stmt::Continue(Pos)` |
| `TryCatchStatement` | `TryCatchStmt` |
| `ExpressionStatement` | পৃথক কোনো নোড নেই — `Stmt::Expr(Expr)`, সরাসরি ভেতরের `Expr` বহন করে |
| `StructDeclaration` | `StructDecl` |
| `AssignmentExpression` | `Assign` (`LValue` ও ডান পাশের `Expr` বহন করে) |
| `LogicalOrExpression` / `LogicalAndExpression` / `EqualityExpression` / `RelationalExpression` / `AdditiveExpression` / `MultiplicativeExpression` | `Binary` — একটিমাত্র ভ্যারিয়েন্ট, যা মিলে যাওয়া অপারেটর `BinOp`-এ বহন করে; `এবং`/`অথবা`ও এর ব্যতিক্রম নয়, নিচে দেখুন |
| `UnaryExpression` | `Unary` |
| `CallExpression` | `Postfix(base, suffixes)` — কল, ইনডেক্স, ফিল্ড প্রতিটি `Suffix` enum-এর একেকটি ভ্যারিয়েন্ট (`Call`/`Index`/`Field`), পৃথক নোড টাইপ নয়; নিচে দেখুন |
| `PrimaryExpression`-এর সরাসরি সংলগ্ন `"." Identifier` লেজ | `Qualified` (মডিউল-আইটেম রেফারেন্স, অথবা — বাম দিকটি একটি লোকাল স্ট্রাক্ট-টাইপড বাইন্ডিং হলে — স্ট্রাক্ট ফিল্ড রিড; §১৩.১.১) |
| `CallSuffix`-এর `"." Identifier` ফর্ম | `Postfix`-এর একটি `Suffix::Field` উপাদান — `Qualified` নয় (§১৩.১.১, §১৮.১) |
| `AssignmentTarget`-এর `"." Identifier` লেজ | `Assign` (স্ট্রাক্ট ফিল্ড রাইট, `LValue`-এর `field` হিসেবে বহন করা) |

| `NumberLiteral` / `StringLiteral` / `CharacterLiteral` / `BooleanLiteral` / `NullLiteral` | `Lit` (`Int`/`Float`/`Str`/`Char`/`Bool`/`Null` ভ্যারিয়েন্ট) |
| `ArrayLiteral` | `Lit::Array` — পৃথক নোড টাইপ নয়, অন্য সব লিটারেলের মতোই একই `Lit` enum-এর একটি ভ্যারিয়েন্ট |
| `DisplayDeclaration` | পৃথক কোনো নোড নেই — `Stmt::Display(Block)` |
| `WidgetCall` / `ContainerWidgetCall` | `WidgetNode` |

প্রায়োরিটি-ক্লাইম্বিং রুলগুলো (`LogicalOrExpression` থেকে `MultiplicativeExpression` পর্যন্ত — `এবং`/`অথবা`সহ) একটিমাত্র `Binary` নোডে একীভূত হয়, যা মিলে যাওয়া অপারেটর `BinOp`-এ বহন করে — প্রতিটি প্রায়োরিটি লেভেলের জন্য, এমনকি লজিক্যাল বনাম অ্যারিথমেটিক/তুলনা অপারেটরের জন্যও, আলাদা নোড টাইপ নেই। গ্রামার পার্স করার জন্য এগুলো আলাদা করে, কিন্তু AST-এর তা প্রয়োজন নেই।

একইভাবে, `CallExpression`-এর গোটা postfix চেইনটি (কল, ইনডেক্স, ফিল্ড — যেকোনো ক্রমে মিশ্রিত) একটিমাত্র `Postfix` নোডে ধরা থাকে, যার `Vec<Suffix>` প্রতিটি ধাপের ধরন ও তথ্য বহন করে — গ্রামারে `CallSuffix`-এর একাধিক বিকল্প থাকলেও, AST-এ প্রতিটি ধাপের জন্য আলাদা নোড টাইপ নেই। ব্যতিক্রম শুধু `PrimaryExpression`-এর সরাসরি সংলগ্ন প্রথম `"." Identifier` লেজ, যা `Postfix`-এর বদলে একটি পৃথক `Qualified` নোড হিসেবে পার্স হয় (§১৮.১)।

# ১৮. পার্সার নোট

## ১৮.১ প্রস্তাবিত কৌশল

এই গ্রামারটি একটি টোকেন লুকঅ্যাহেড-সহ (LL(1)) রিকার্সিভ ডিসেন্ট দিয়ে পার্স করার জন্য ডিজাইন করা, এবং `Expression`-এর (§১৩) জন্য প্রায়োরিটি ক্লাইম্বিং (বা সমতুল্য একটি Pratt পার্সার)।

দ্ব্যর্থতাগুলো এভাবে সমাধান করা হয় —

- **ঐচ্ছিক টাইপ অ্যানোটেশন** (`VariableDeclaration`, §১০.১): `ধরি Identifier`-এর পর, লুকঅ্যাহেডে `:` টাইপযুক্ত ফর্ম নির্বাচন করে; `=` ইনফার করা ফর্ম নির্বাচন করে। কোনো ব্যাকট্র্যাকিং প্রয়োজন নেই।
- **`নাহলে` চেইনিং** (`IfStatement`, §১২.২): একটি অনুগামী `নাহলে`-এর পর `যদি` এলে তা আরেকটি `IfStatement`-এ রিকার্স করে; `নাহলে`-এর পর `{` এলে তা একটি সাধারণ `Block`-এর সাথে মেলে। `নাহলে`-এর পর একটি টোকেন লুকঅ্যাহেডই যথেষ্ট।
- **কন্টেইনার বনাম লিফ উইজেট** (`WidgetCall` বনাম `ContainerWidgetCall`, §১৫.১): লুকঅ্যাহেড দিয়ে নয়, বরং কোন নির্দিষ্ট `WidgetKeyword` মিলেছে তা দিয়ে নির্ধারিত হয় — `সারি`/`কলাম`/`কার্ড`/`ডায়ালগ`/`স্ক্রল` সবসময় একটি অনুগামী `Block` আশা করে।
- **অ্যাসাইনমেন্ট বনাম এক্সপ্রেশন স্টেটমেন্ট** (`AssignmentExpression` বনাম `ExpressionStatement`, §১৩.১): `CallSuffix` কল ও ইনডেক্স উভয় ফর্মকে একই পোস্টফিক্স চেইনে অনুমোদন করে বলে, পার্সার প্রথমে সাধারণভাবে পোস্টফিক্স চেইনটি পার্স করে (`Identifier` শুরু করে যত খুশি `CallSuffix`)। এরপর পরবর্তী টোকেন `=` হলে এবং পার্স করা চেইনে শুধু ইনডেক্স সাফিক্স থাকলে (কোনো কল সাফিক্স না থাকলে), এটি `AssignmentExpression` হিসেবে গৃহীত হয়; নইলে এটি `LogicalOrExpression`/`ExpressionStatement`-এ পড়ে যায়। একটি কল সাফিক্সসহ চেইনের পরে `=` এলে (যেমন `যোগ(ক, খ)[০] = ৫`) তা সিনট্যাক্স ত্রুটি, কারণ `AssignmentTarget` শুধুমাত্র বেয়ার `Identifier`, ইনডেক্স ও একটি একক ফিল্ড থেকে উদ্ভূত হয় (§১৩.১)।
- **মেম্বার অ্যাক্সেস বনাম মডিউল আইটেম** (`"." Identifier`, §১৩.১.১): উভয়ের গ্রামার অভিন্ন, কিন্তু নোড আকৃতি একই নয় — `PrimaryExpression`-এর সরাসরি `"." Identifier` লেজ একটি `Qualified` নোড তৈরি করে, আর `CallSuffix`-এর `"." Identifier` (চেইনে পরবর্তী যেকোনো ধাপ) একটি `Postfix` নোডে একটি ফিল্ড-সাফিক্স যোগ করে (§১৭)। মডিউল-আইটেম নাকি স্ট্রাক্ট-ফিল্ড তা উভয় ক্ষেত্রেই সিমান্টিক অ্যানালাইসিসে নির্ধারিত হয়, পার্সিং-এ নয়।

## ১৮.২ নিউলাইন হ্যান্ডলিং

যেহেতু কলম-এ সেমিকোলন নেই (§৩.৭), তাই লেক্সারের উচিত প্রতিটি লাইন টার্মিনেটরে একটি স্পষ্ট `NEWLINE` টোকেন উৎপন্ন করা, তবে অমিলিত `(` বা `[`-এর ভেতরে থাকলে নয়। ব্লক তথ্যের `{}`-এর ভেতরে `NEWLINE` স্বাভাবিকভাবেই উৎপন্ন হয় — কারণ সেটিই স্টেটমেন্ট বিভাজক। পার্সার তখন `Block`-এর ভেতরে `NEWLINE`-কে একটি স্টেটমেন্ট বিভাজক হিসেবে গণ্য করে (Go-তে automatic semicolon insertion-এর অনুরূপ)। এভাবে নিউলাইন দমন করার দায়িত্ব লেক্সারের থাকে, ফলে পার্সারের গ্রামারকে (§৯–§১৫) কখনো সরাসরি লাইন-ব্রেক নিয়ে ভাবতে হয় না।

## ১৮.৩ সিম্বল টেবিল

সিমান্টিক অ্যানালাইসিসের (`compiler.md` §৬) জন্য আইডেন্টিফায়ার-ভিত্তিক একটি সিম্বল টেবিল প্রয়োজন, যা পার্সিংয়ের সময় নয়, বরং AST-এর উপর একটি পাসের সময় তৈরি হয় — পার্সিং একটি সম্পূর্ণ, টাইপবিহীন AST উৎপন্ন করে; টাইপ ইনফারেন্স ও সংরক্ষিত-আইডেন্টিফায়ার চেক তার পরে ঘটে।

# ১৯. এরর রিকভারি

## ১৯.১ লেক্সিক্যাল ত্রুটি

§৩.১১ অনুযায়ী, একটি অবৈধ ক্যারেক্টার ত্রুটি হিসেবে রেকর্ড করা হয়, এবং পরবর্তী ক্যারেক্টার থেকে স্ক্যানিং চালিয়ে যাওয়া হয়, যাতে একবারের পাসে একাধিক লেক্সিক্যাল ত্রুটি রিপোর্ট করা যায়।

## ১৯.২ সিনট্যাক্স ত্রুটি

একটি সিনট্যাক্স ত্রুটিতে, পার্সার প্যানিক মোডে প্রবেশ করে —

১. ত্রুটি রেকর্ড করো (প্রত্যাশিত টোকেন বনাম প্রকৃত টোকেন, সোর্স পজিশনসহ)।
২. একটি সিঙ্ক্রোনাইজেশন পয়েন্ট না পাওয়া পর্যন্ত টোকেন বাতিল করো —
   - বর্তমান ব্লকের স্টেটমেন্ট সীমানায় একটি `NEWLINE` টোকেন, অথবা
   - একটি নতুন টপ-লেভেল তথ্য শুরু করে এমন টোকেন: `অ্যাপ`, `ফাংশন`, `ধরি`, `ধ্রুবক`, `ইম্পোর্ট`।
৩. সিঙ্ক্রোনাইজেশন পয়েন্ট থেকে স্বাভাবিক পার্সিং পুনরায় শুরু করো।

এর ফলে একটি কম্পাইলেশন রান প্রথম ত্রুটিতে থেমে না গিয়ে একাধিক স্বতন্ত্র সিনট্যাক্স ত্রুটি রিপোর্ট করতে পারে।

## ১৯.৩ ত্রুটি বার্তার ফরম্যাট

সকল ডায়াগনস্টিকের মূল পাঠ **বাংলায়** লেখা হয় — কীওয়ার্ড, আইডেন্টিফায়ার ও লিটারেল সোর্সে যেমন আছে তেমনই উদ্ধৃত থাকে; ইংরেজি কেবল উদ্ধৃত টোকেনের ভেতরে থাকতে পারে।

প্রতিটি ডায়াগনস্টিক এই কাঠামো অনুসরণ করে —

```text
ত্রুটি: <ফাইল>:<লাইন>:<কলাম>

<বার্তা>
```

লাইন ও কলাম ১-ভিত্তিক; কলাম ইউনিকোড কোড পয়েন্ট ধরে গণনা হয়। এই অবস্থান-অংশ আবশ্যক, যাতে এডিটর/LSP (সংস্করণ ২.০) সরাসরি অবস্থান চিনতে পারে।

উদাহরণ

## ২০.৩ ফাংশন

```kolom
ফাংশন যোগ(সংখ্যা ক, সংখ্যা খ) -> সংখ্যা {

    রিটার্ন ক + খ

}

অ্যাপ {

    ধরি ফল = যোগ(১০, ২০)

    লেখো(ফল)

}
```

## ২০.৪ কন্ট্রোল ফ্লো

```kolom
ফাংশন জোড়(সংখ্যা ক) -> বুলিয়ান {

    রিটার্ন (ক % ২) == ০

}

অ্যাপ {

    ধরি গণনা = ০

    যতক্ষণ (গণনা < ৫) {

        যদি (জোড়(গণনা)) {

            লেখো("জোড়")

        } নাহলে {

            লেখো("বিজোড়")

        }

        গণনা = গণনা + ১

    }

}
```
