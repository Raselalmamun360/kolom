## ১. উদ্দেশ্য

এই ডকুমেন্ট কলম-এর ডেভেলপমেন্ট মাইলস্টোন, সংস্করণ-ভিত্তিক লক্ষ্য এবং রিলিজ পরিকল্পনা ট্র্যাক করে।

এই ডকুমেন্ট ভাষার সিনট্যাক্স, গ্রামার, কম্পাইলার-অভ্যন্তরীণ কাঠামো, বা UI/ইঞ্জিন ডিজাইন নির্ধারণ করে **না** — সেগুলো নিজস্ব স্পেসিফিকেশনে বর্ণিত (দেখুন [ডকুমেন্টেশন ম্যাপ](#১২-ডকুমেন্টেশন-ম্যাপ))।

এই রোডম্যাপের কোনো চেকলিস্ট আইটেম যদি সিনট্যাক্স বা সিমান্টিক্স নির্দেশ করে, সেক্ষেত্রে `language.md` এবং `grammer.md`-ই চূড়ান্ত সিদ্ধান্তকারী — এই রোডম্যাপ নয়।

## ৮. সংস্করণ ০.৬ — প্ল্যাটফর্ম সম্প্রসারণ

**লক্ষ্য:** প্রাথমিক ডেস্কটপ টার্গেটের বাইরেও কলম নেটিভ অ্যাপ চালানো।

- [~] অ্যান্ড্রয়েড সাপোর্ট — `কলম বিল্ড main.ক android` এখন ডিফল্ট
      (Cranelift) ব্যাকএন্ডেই কাজ করে — aarch64 (arm64-v8a), স্ট্যাটিকভাবে
      Bionic-এর বিপরীতে লিংক করা। একটি real ডিভাইসে (adb দিয়ে পুশ করে)
      যাচাই করা। বিল্ড-মেশিনে Android NDK লাগে (`ANDROID_NDK_HOME`) —
      Bionic কোনো Rust টুলচেইনের সাথে বান্ডলড আসে না, musl যেমন আসে —
      তাই এখনো পুরোপুরি স্বয়ংসম্পূর্ণ নয় (bundling বাকি)। লিংকার হিসেবে
      বান্ডলড `rust-lld` নয়, NDK-র নিজস্ব `ld.lld` ব্যবহার হয় — নতুন NDK
      রিলিজের `libc.a`/`libm.a`-এর ডিবাগ ইনফো zstd দিয়ে কম্প্রেসড, যা
      `rust-lld`-এ সমর্থিত নয়। এই কাজের সময় `kl_arr_decref`/
      `kl_shared_decref`-এ দুটি real মেমরি-করাপশন বাগ ধরা পড়েছে (drop
      কলব্যাককে স্লটের ঠিকানা পাঠানো হচ্ছিল, স্লটে-রাখা পয়েন্টার নয়) —
      Windows-এর allocator নীরবে সহ্য করত, Android-এর Scudo সাথে সাথে
      ধরে ফেলে।
- [~] লিনাক্স সাপোর্ট — কনসোল প্রোগ্রাম ও Windows থেকে ক্রস-কম্পাইল সম্পূর্ণ
      (এক ফাইলের স্ট্যাটিক musl বাইনারি, WSL-এ চালিয়ে পরীক্ষিত)।
      বাকি: নেটিভ UI (X11/Wayland) — এখন কনসোল স্টাব চলে।
- [ ] macOS সাপোর্ট

## ৯. সংস্করণ ০.৭ — ইকোসিস্টেম টুলিং

**লক্ষ্য:** এডিটর সাপোর্টসহ মাল্টি-ফাইল, মাল্টি-প্যাকেজ প্রজেক্ট সাপোর্ট করা।

- [x] প্যাকেজ ম্যানেজার (KPM) — `কলম.toml`/`কলম.lock`, `kolom যোগ`/`ইনস্টল`/`মুছো`, git URL পিন করা কমিটে (`crates/kolom-pkg`)। কোয়ালিফায়েড প্যাকেজ কল (`প্যাকেজ.ফাংশন()`) — `resolve_user_modules`-এ নেমস্পেসড মার্জ, sema/ইন্টারপ্রেটার/Cranelift তিনটেতেই যাচাই করা, নাম-সংঘর্ষ না হওয়া স্পষ্টভাবে টেস্ট করা (`crates/kolom-cli/tests/kpm.rs`)। *এর আগে এই চেকবক্স ভুলভাবে `কলম নতুন` scaffold + একই-ডিরেক্টরি মডিউল রেজোলিউশনকে "প্যাকেজ ম্যানেজার" বলত — কোনো নির্ভরতা/ভার্সনিং/এক্সটার্নাল সোর্স ছিল না, ঠিক করা হলো।* বাকি: SemVer রেঞ্জ, হোস্টেড রেজিস্ট্রি/ইনডেক্স, cross-project গ্লোবাল ক্যাশ, `তথ্য`/`ধ্রুবক` নেমস্পেসিং (`language.md` §১২.১.৩)।
- [x] মডিউল সিস্টেম — ইউজার `.ক` ইম্পোর্ট (প্রতিটি মডিউলের নিজস্ব ডিরেক্টরির সাপেক্ষে resolve হয়, একটা গ্লোবাল অ্যাংকর নয়) + উপরের প্যাকেজ রেজোলিউশন
- [~] IDE এক্সটেনশন — VS Code সিনট্যাক্স হাইলাইটিং সম্পূর্ণ (`editors/vscode`),
      সব ৪০টি কীওয়ার্ড কভার করে, বাস্তব উদাহরণের বিপরীতে vscode-textmate
      দিয়ে টোকেন-বাই-টোকেন যাচাই করা। `kolom-lsp` ক্রেট (diagnostics-only,
      v1) সম্পূর্ণ — real `Content-Length`-framed JSON-RPC, lex→parse→
      module-resolve→sema পাইপলাইন চালিয়ে `textDocument/didOpen`/
      `didChange`/`didSave`/`didClose`-এ `publishDiagnostics` পাঠায়;
      Bengali ফাইল-এক্সটেনশন ও Windows ড্রাইভ-লেটার path-সহ real multi-file
      প্রজেক্টের বিরুদ্ধে যাচাই করা (`crates/kolom-lsp/tests/diagnostics.rs`)।
      এখন VS Code এক্সটেনশনে সরাসরি ক্লায়েন্ট হিসেবে wire করা
      (`editors/vscode/src/extension.ts`, `vscode-languageclient` দিয়ে) —
      `kolom-lsp` বাইনারি PATH-এর `kolom`-এর পাশে খোঁজে (`scripts/
      make-sysroot.sh` এখন দুটোই বান্ডল করে), অথবা `kolom.lspPath`
      সেটিং দিয়ে ওভাররাইড করা যায়। প্যাকেজ করে real VS Code-এ ইনস্টল
      করে যাচাই করা — ভুল প্রোগ্রামে ঠিক জায়গায় স্কুইগল/lightbulb,
      সঠিক প্রোগ্রামে কিছুই না। বাকি: hover/go-to-definition (এর জন্য
      `kolom_sema::analyze_typed`-এর `Types` টেবিল আগে থেকেই আছে, শুধু
      ব্যবহার করা বাকি)।
- [x] বিল্ট-ইন টার্মিনাল এডিটর `কলম পাতা`/`kolom edit` (`crates/kolom-cli/src/editor.rs`) —
      `crossterm`-ভিত্তিক, C কম্পাইলার-নির্ভরতা ছাড়াই (`kolom-cli` নিজেই একটা
      সাধারণ Rust বাইনারি)। টাইপ করার সাথে সাথে লাইভ ত্রুটি (একই lex→parse→
      resolve_user_modules→sema পাইপলাইন, `kolom-lsp`-এর `analyze()`-এর মতো
      কিন্তু সরাসরি এই ক্রেটে — নির্ভরতা-চক্র এড়াতে `kolom-lsp` এর উপর নির্ভর
      করে না)। Ctrl+R বর্তমান বাফার (সেভ না করা থাকলেও) `kolom-interp` দিয়ে
      সরাসরি চালায় — Cranelift/C বিল্ড ব্যাকএন্ড ছোঁয় না। বাফার-এডিটিং,
      কী-ডিসপ্যাচ, ও ডায়াগনস্টিকস লজিক টার্মিনাল-নির্ভরতা ছাড়া বিশুদ্ধ ফাংশন
      হিসেবে লেখা ও `cargo test`-এ যাচাই করা (real module resolution-সহ);
      real terminal-এ manually verify করা হয়েছে (raw mode/alt-screen enter-
      exit, লাইভ ত্রুটি হাইলাইট, সব ঠিকমতো)।
- [x] কলম কনসোল — টার্মিনাল ইমুলেটর একটি স্থির মনোস্পেস ক্যারেক্টার-গ্রিডে
      রেন্ডার করে, যা বাংলার রিঅর্ডারিং কার (ে/ো/ৌ) সঠিকভাবে দেখাতে পারে না।
      দুটো নতুন সারফেস এটি এড়িয়ে যায়: নেটিভ `kolom কনসোল <ফাইল.ক>`
      (`crates/kolom-runtime/src/console.rs`) — `ui.rs`-এর একই Uniscribe/
      USP10 শেপিং পাথ পুনর্ব্যবহার করে একটি Win32 উইন্ডোতে, স্ক্রলব্যাক ও
      পড়ো_লাইন-চালিত ইনপুট লাইনসহ — এবং VS Code এক্সটেনশনের "কলম কনসোল"
      প্যানেল/সাইডবার (`editors/vscode/src/consoleView.ts`), যা `kolom run`
      একটি real webview-তে চালায় বলে প্লেইন টেক্সট এমনিতেই ঠিকভাবে শেপ হয়,
      কোনো শেপিং লাইব্রেরি ছাড়াই।

## ১২. ডকুমেন্টেশন ম্যাপ

কলম-এর স্পেসিফিকেশন পাঁচটি ডকুমেন্টে বিভক্ত। প্রতিটির নির্দিষ্ট, অ-ওভারল্যাপিং সুযোগ (scope) আছে —

| ডকুমেন্ট | উদ্দেশ্য |
|----------|---------|
| `language.md` | ভাষার দর্শন, ফিচার ওভারভিউ ও ডিজাইন নীতি |
| `grammer.md` | ফরমাল গ্রামার ও সিনট্যাক্স স্পেসিফিকেশন (EBNF) |
| `compiler.md` | কম্পাইলার আর্কিটেকচার: লেক্সার, পার্সার, AST, সিমান্টিক অ্যানালাইসিস, কোড জেনারেশন |
| `engine.md` | নেটিভ UI ও গ্রাফিক্স ইঞ্জিন: উইজেট, স্টেট ও রি-বিল্ড, লেআউট, রেন্ডারিং, ইভেন্ট সিস্টেম |
| `roadmap.md` | এই ডকুমেন্ট — মাইলস্টোন, সংস্করণ-ভিত্তিক লক্ষ্য, রিলিজ পরিকল্পনা |
| `getting-started.md` | ব্যবহারকারীর জন্য: ইনস্টল, প্রথম প্রোগ্রাম, সাধারণ সমস্যা |

স্ট্যান্ডার্ড লাইব্রেরি ও রানটাইমের বিস্তারিত `compiler.md`-এর মধ্যেই রাখা হয়েছে, আলাদা ডকুমেন্ট হিসেবে নয় — যতক্ষণ না দুটির কোনোটি এতটাই বড় হয় যে আলাদা স্পেসিফিকেশনের প্রয়োজন হয়।

## ১৫. দীর্ঘমেয়াদি লক্ষ্য (Long-Term Vision)

কলম-এর লক্ষ্য একটি সম্পূর্ণ বাংলা সফটওয়্যার ইকোসিস্টেম হয়ে ওঠা, যার মধ্যে থাকবে —

- কলম ভাষা (Kolom Language)
- কলম কম্পাইলার
- কলম রানটাইম
- কলম স্ট্যান্ডার্ড লাইব্রেরি
- কলম গ্রাফিক্স ইঞ্জিন
- কলম UI ফ্রেমওয়ার্ক
- কলম প্যাকেজ ম্যানেজার
- কলম IDE এক্সটেনশন
- কলম ডকুমেন্টেশন
- কলম প্লেগ্রাউন্ড
- কলম কমিউনিটি প্যাকেজ

স্ট্যান্ডার্ড লাইব্রেরির `ম্যাট্রিক্স` মডিউল (২D ম্যাট্রিক্স/ভেক্টর, `দশমিক[][]`-এর উপর) ইতিমধ্যে বাস্তবায়িত (§১৭.১)। এর বাইরে দুটো সম্পর্কিত কিন্তু আলাদা-স্কেলের দীর্ঘমেয়াদি সম্ভাবনা, ইচ্ছাকৃতভাবে এই মডিউলের সাথে মেশানো হয়নি —

- **First-class ফাংশন/ক্লোজার** — কলমে এখনো ফাংশন-ভ্যালু বলে কিছু নেই (`গ্রাফিক্স.টিক`-এর হ্যান্ডলার প্যারামিটারও শুধু zero-param নামের একটি বিশেষ-কেস, সাধারণ ফাংশন-ভ্যালু নয়)। এটা ছাড়া সাধারণ `f(x)=0` সমাধান, সিম্বলিক ডেরিভেটিভ, বা যেকোনো ব্যবহারকারী-দেওয়া ফাংশনের উপর নিউমেরিক্যাল ইন্টিগ্রেশনের মতো কিছুই সম্ভব নয় — এগুলো স্ট্যান্ডার্ড লাইব্রেরি সংযোজন নয়, বরং একটা আলাদা ভাষাগত ফিচার, যা আগে দরকার।
- **N-মাত্রিক টেনসর ইঞ্জিন (PyTorch/TensorFlow-ধাঁচের)** — বর্তমান `দশমিক[][]` রিপ্রেজেন্টেশন (রেফারেন্স-কাউন্টেড, প্রতি-এলিমেন্ট বক্সড পয়েন্টার) real training workload-এর জন্য অনুপযুক্ত — দরকার contiguous `f32`/`f64` বাফার, stride-ভিত্তিক broadcasting, ও একটা autograd ইঞ্জিন। এটা একটা নতুন রানটাইম টাইপ ও সম্ভবত নিজস্ব ক্রেট (`kolom-tensor`) দাবি করে — স্কেলে Cranelift ব্যাকএন্ডের কাজের কাছাকাছি, স্ট্যান্ডার্ড লাইব্রেরির একটা মডিউলের চেয়ে অনেক বড়।
