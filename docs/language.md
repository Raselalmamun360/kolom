# ১. ভূমিকা

কলম (Kolom) একটি আধুনিক, স্ট্যাটিকালি টাইপড, কম্পাইলড প্রোগ্রামিং ভাষা, যা মূলত বাংলাভাষী ডেভেলপারদের জন্য তৈরি।

কলম আধুনিক প্রোগ্রামিং ভাষার সরলতাকে প্রতিদিনের বাংলার পরিচিতির সাথে একত্র করে, যাতে ডেভেলপাররা স্বাভাবিক ও সহজপাঠ্য সিনট্যাক্স ব্যবহার করে পেশাদার সফটওয়্যার লিখতে পারেন।

কলম ডিজাইন করা হয়েছে —

- নেটিভ ডেস্কটপ অ্যাপ্লিকেশনের জন্য
- কমান্ড-লাইন অ্যাপ্লিকেশনের জন্য
- ক্রস-প্ল্যাটফর্ম ডেভেলপমেন্টের জন্য
- ব্যাকএন্ড সার্ভিসের জন্য
- ভবিষ্যতের মোবাইল ও ওয়েব সাপোর্টের জন্য

কলম কোনো অনূদিত (translated) প্রোগ্রামিং ভাষা নয়।

এটি শুরু থেকেই বাংলাভাষীদের জন্য ডিজাইন করা একটি ভাষা।

# ২. ভাষার দর্শন (Language Philosophy)

কলম একটি সহজ নীতি অনুসরণ করে —

> **আধুনিক দৈনন্দিন বাংলা ব্যবহার করো।**

ভাষাটি ইচ্ছাকৃতভাবে এমন শব্দ ব্যবহার করে, যা বাংলাভাষীরা দৈনন্দিন জীবনে স্বাভাবিকভাবেই ব্যবহার করেন।

একটি কীওয়ার্ড আসতে পারে —

- বাংলা থেকে
- ইংরেজি থেকে
- আরবি থেকে
- ফার্সি থেকে
- সংস্কৃত থেকে
- অন্য যেকোনো ভাষা থেকে

যদি বাংলাভাষীরা স্বাভাবিকভাবে শব্দটি ব্যবহার করেন, তাহলে সেটি গ্রহণযোগ্য।

উদাহরণ

| এড়িয়ে চলুন | ব্যবহার করুন |
|--------|---------|
| কেদারা | চেয়ার |
| দূরভাষ | ফোন |
| গণনাযন্ত্র | কম্পিউটার |
| চলভাষ | মোবাইল |

ভাষাগত বিশুদ্ধতা (Language purity) কলম-এর লক্ষ্য **নয়**।

সহজপাঠ্যতা, পরিচিতি এবং ডেভেলপার প্রোডাক্টিভিটিই মূল লক্ষ্য।

# ৩. ডিজাইন নীতি (Design Principles)

কলম নিম্নলিখিত নীতির ভিত্তিতে ডিজাইন করা হয়েছে।

- সরল (Simple)
- নিরাপদ (Safe)
- দ্রুত (Fast)
- সহজপাঠ্য (Readable)
- সামঞ্জস্যপূর্ণ (Consistent)
- ব্যবহারিক (Practical)

# ৬. টাইপ সিস্টেম

কলম হলো —

> **স্বয়ংক্রিয় টাইপ ইনফারেন্সসহ স্ট্যাটিকালি টাইপড (Statically Typed with Automatic Type Inference)**

প্রতিটি ভ্যালুর একটি নির্দিষ্ট টাইপ থাকে।

বেশিরভাগ লোকাল ভ্যারিয়েবলের জন্য স্পষ্ট টাইপ অ্যানোটেশনের প্রয়োজন হয় না।

কম্পাইলেশনের সময় টাইপ যাচাই করা হয়।

ঘোষণার পর ভ্যারিয়েবলের টাইপ পরিবর্তন করা যায় না।

সংখ্যা ও দশমিক-এর মধ্যে গাণিতিক ও তুলনা অপারেশনে স্বয়ংক্রিয় প্রমোশন (promotion) অনুমোদিত — ফলাফল 'দশমিক'। কিন্তু অ্যাসাইনমেন্ট, প্যারামিটার পাসিং ও রিটার্নে টাইপ হুবহু মিলতে হয় — কোনো রূপান্তর হয় না।

উদাহরণ

```kolom
ধরি বয়স = ২৫

বয়স = "রহিম"
```

কম্পাইলার

```
ত্রুটি

'বয়স' একটি সংখ্যা।

এখানে লেখা নির্ধারণ করা যাবে না।
```

# ৭. প্রোগ্রাম স্ট্রাকচার

প্রতিটি এক্সিকিউটেবল অ্যাপ্লিকেশন শুরু হয় এভাবে —

```kolom
}
```

```kolom
}
```

অ্যাপ্লিকেশন নামটি ডিফল্ট এক্সিকিউটেবল নাম হিসেবে ব্যবহৃত হয়।


# ১০. প্রিমিটিভ টাইপ

| টাইপ | বিবরণ | আকার ও মানসীমা |
|------|-------------|----------------|
| সংখ্যা | পূর্ণসংখ্যা (Integer) | ৬৪-বিট স্বাক্ষরিত: −৯২২৩৩৭২০৩৬৮৫৪৭৭৫৮০৮ … ৯২২৩৩৭২০৩৬৮৫৪৭৭৫৮০৭ |
| দশমিক | দশমিক সংখ্যা (Floating Point) | ৬৪-বিট IEEE 754 double |
| লেখা | UTF-8 লেখা (String) | `দৈর্ঘ্য` গণনা ইউনিকোড স্কেলার ভ্যালু ধরে |
| বুলিয়ান | বুলিয়ান (Boolean) | সত্য / মিথ্যা |
| অক্ষর | ইউনিকোড ক্যারেক্টার | একটি ইউনিকোড স্কেলার ভ্যালু (২১-বিট) |
| ফাঁকা | নাল (Null) | মানহীন |

সীমা-সংক্রান্ত নিয়ম —

- লিটারেল তার টাইপের মানসীমার বাইরে গেলে কম্পাইল-টাইম ত্রুটি।
- রানটাইমে পূর্ণসংখ্যা ওভারফ্লো, শূন্য দিয়ে ভাগ (`/` বা `%`), এবং অ্যারের সীমার বাইরে ইনডেক্স — প্রতিটিই স্পষ্ট বাংলা বার্তাসহ রানটাইম ত্রুটি; ফলাফল কখনো নীরবে মুড়ানো (wrap) হয় না।

যেকোনো টাইপের পরে `[]` যোগ করে অ্যারে টাইপ তৈরি করা যায়। অ্যারে সমসত্ত্ব (homogeneous) — প্রতিটি এলিমেন্টের টাইপ একই হতে হয়।

উদাহরণ

```kolom
ধরি সংখ্যাসমূহ: সংখ্যা[] = [১০, ২০, ৩০]

ধরি নামসমূহ = ["রহিম", "করিম"]
```

একটি অ্যারে লিটারেলে ভিন্ন ভিন্ন টাইপ মিশ্রিত করলে তা কম্পাইল-টাইম ত্রুটি হিসেবে ধরা হয়, যা কলম-এর স্ট্যাটিক টাইপিং নীতির (§৬) সাথে সামঞ্জস্যপূর্ণ।

# ১১. ফাংশন

ফাংশন ঘোষণা করা হয় এভাবে —

```kolom
ফাংশন
```

উদাহরণ

```kolom
ফাংশন যোগ(সংখ্যা ক, সংখ্যা খ) -> সংখ্যা {

    রিটার্ন ক + খ

}
```

ফাংশনের প্যারামিটার ও রিটার্ন টাইপ স্পষ্টভাবে উল্লেখ করা আবশ্যক।

লোকাল ভ্যারিয়েবলে টাইপ ইনফারেন্স ব্যবহার করা যেতে পারে।

# ১২. মডিউল

মডিউল ইম্পোর্ট করা হয় এভাবে —

```kolom
ইম্পোর্ট গণিত

ইম্পোর্ট সময়

ইম্পোর্ট json
```

## ১২.১ মডিউল সিস্টেম

কলম মডিউল সিস্টেম দুটি ধরনের মডিউল সমর্থন করে:

### ১২.১.১ স্ট্যান্ডার্ড লাইব্রেরি মডিউল
এগুলো কলম কম্পাইলারের সাথে বিল্ট-ইন আসল, নেটিভ (Rust) বাস্তবায়ন রয়েছে। এগুলোকে ইম্পোর্ট করতে হয়:

| মডিউল | উদ্দেশ্য | সংস্করণ |
|--------|----------|---------|
| `গণিত` | গাণিতিক ফাংশন (ট্রিগনোমেট্রি, Констан্ট, ইউটিলিটি) | ০.৩ |
| `লেখা` | লেখা ম্যানিপুলেশন, এনকোডিং, সার্চ | ০.৩ |
| `ফাইল` | স্ট্যান্ডার্ড ইনপুট/আউটপুট, ফাইল I/O, বাফারিং | ০.৩ |
| `ফাইলসিস্টেম` | পাথ ম্যানিপুলেশন, ডিরেক্টরি অপারেশন, মেটাডেটা | ০.৩ |
| `জেসন` | পার্স, সিরিয়ালাইজ, ডোম | ০.৩ |
| `সময়` | ডেটটাইম, ডিউরেশন, ফরম্যাটিং | ০.৩ |
| `র‍্যান্ডম` | PRNG, ডিস্ট্রিবিউশন | ০.৩ |
| `নেটওয়ার্ক` | TCP/UDP, অ্যাসিঙ্ক্রোনাস | ০.৩ |

### ১২.১.২ ইউজার মডিউল
ইউজার-লিখিত মডিউল সাধারণ `.ক` ফাইল। এগুলোতে `অ্যাপ` ডিক্লারেশন থাকে না, শুধু টপ-লেভেল ফাংশন ও কনস্ট্যান্ট থাকে যা এক্সপোর্ট হয়।

মডিউল রেজোলিউশন: `ইম্পোর্ট helper` → একই ডিরেক্টরিতে `helper.ক` খোঁজা হয়। নেস্টেড ইম্পোর্ট (মডিউলের ভেতরের ইম্পোর্ট) স্বয়ংক্রিয়ভাবে resolve হয়।

### ১২.২ ইম্পোর্ট নিয়ম

```kolom
ইম্পোর্ট মডিউল_নাম
```

- ইম্পোর্টগুলো ফাইলের শুরুতে থাকতে হয় (ইম্পোর্টের পর কনস্ট্যান্ট/ফাংশন)
- একই মডিউল একাধিকবার ইম্পোর্ট করা যাবে না
- স্ট্যান্ডার্ড লাইব্রেরি মডিউল বা ইউজার মডিউল — উভয়ই একই সিনট্যাক্স

### ১২.৩ এক্সপোর্ট নিয়ম

ফাইল/নেটওয়ার্ক I/O ত্রুটিতে রানটাইম ত্রুটি ছোঁড়ে, যা `চেষ্টা`/`ধরো` দিয়ে ধরা যায় (§ত্রুটি হ্যান্ডলিং) — ইন্টারপ্রেটার ও নেটিভ (Cranelift) ব্যাকএন্ড দুটোতেই। `র‍্যান্ডম` একই seed-এ একই ক্রম দেয় *একই ব্যাকএন্ডে* — ইন্টারপ্রেটার ও নেটিভ ব্যাকএন্ড আলাদা জেনারেটর ব্যবহার করে, তাই দুইয়ের ক্রম এক নয়। প্রোগ্রামের সঠিকতা যেন নির্দিষ্ট ক্রমের উপর নির্ভর না করে।

# ২০. অপারেটর

গাণিতিক অপারেটর (`+`, `-`, `*`, `/`, `%`) `সংখ্যা` ও `দশমিক`-এর উপর কাজ করে।

`+` অপারেটর ওভারলোডেড — অপারেন্ডের টাইপ অনুযায়ী এর অর্থ পরিবর্তিত হয় —

| অপারেন্ড টাইপ | `+`-এর অর্থ |
|----------------|--------------|
| `সংখ্যা` + `সংখ্যা` | সাংখ্যিক যোগ |
| `দশমিক` + `দশমিক` | সাংখ্যিক যোগ |
| `লেখা` + `লেখা` | লেখা কনক্যাটিনেশন (জোড়া লাগানো) |
| `Type[]` + `Type[]` (একই `Type`) | অ্যারে কনক্যাটিনেশন |

উদাহরণ

```kolom
ধরি বার্তা = "হ্যালো, " + "বিশ্ব"

লেখো(বার্তা)
```

```kolom
ধরি ক = [১, ২]

ধরি খ = [৩, ৪]

ধরি গ = ক + খ

লেখো(গ)
```

দুটি ভিন্ন টাইপের (যেমন `সংখ্যা` ও `লেখা`) মধ্যে `+` ব্যবহার করলে তা কম্পাইল-টাইম ত্রুটি — কলম টাইপ কনভার্সন স্বয়ংক্রিয়ভাবে করে না (§৬)।

তুলনা অপারেটর (`==`, `!=`, `<`, `>`, `<=`, `>=`) এবং লজিক্যাল অপারেটর (`এবং`, `অথবা`, `না`)-এর সম্পূর্ণ তালিকা ও প্রায়োরিটির জন্য দেখুন `grammer.md` §৮ ও §১৩.২।

# ২১. বিল্ট-ইন ফাংশন

নিম্নলিখিত ফাংশনগুলো সবসময় উপলব্ধ — এগুলো ব্যবহার করতে কোনো `ইম্পোর্ট` লাগে না, `লেখো`-এর মতোই (§১৪)। এগুলো §১৭-এর স্ট্যান্ডার্ড লাইব্রেরি মডিউল থেকে আলাদা, যেগুলোর জন্য `ইম্পোর্ট` প্রয়োজন।

| ফাংশন | বিবরণ |
|--------|-------|
| `লেখো(x)` | কনসোলে লেখে (§১৪) |
| `দৈর্ঘ্য(x)` | `লেখা`-এর ক্যারেক্টার সংখ্যা, `Type[]`-এর এলিমেন্ট সংখ্যা, বা `ম্যাপ`-এর এন্ট্রি সংখ্যা ফেরত দেয় |
| `কপি(x)` | একটি `লেখা` বা `Type[]`-এর স্বাধীন (independent) কপি তৈরি করে, উৎসকে অক্ষত রেখে (§২২) |
| `শেয়ার_করো(x)` | `x`-কে একটি রেফারেন্স-কাউন্টেড `শেয়ার Type` হ্যান্ডেলে রূপান্তর করে (§২২) |
| `মান(x)` | `শেয়ার Type` সেলের ভেতরের বর্তমান মান ফেরত দেয় (`শেয়ার T` → `T`) |
| `বসাও(x, v)` | `শেয়ার T` সেলে নতুন মান বসায় (`x`: `শেয়ার T`, `v`: `T`; ফেরত `ফাঁকা`) |
| `লেখায়(x)` | যেকোনো প্রিমিটিভ মান `লেখা`-তে রূপান্তর করে (UI/কনসোল প্রদর্শনের জন্য) |
| `পড়ো_লাইন()` | স্ট্যান্ডার্ড ইনপুট থেকে একটি লাইন পড়ে (`লেখা` ফেরত দেয়) |
| `ম্যাপ_তৈরি()` | একটি খালি `ম্যাপ[K, V]` তৈরি করে (§২৪) — `: ম্যাপ[K, V]` টাইপ-টীকা আবশ্যক |
| `আছে_কি(m, key)` | `key`, `m`-এ আছে কিনা ফেরত দেয় (`বুলিয়ান`) |
| `চাবি_গুলো(m)` | `m`-এর সব key-এর একটি অ্যারে ফেরত দেয় |
| `চাবি_মুছো(m, key)` | `m` থেকে `key` (থাকলে) মুছে দেয় |

`মান` ও `বসাও` একসাথে `শেয়ার` সেলের অভ্যন্তরীণ পরিবর্তনযোগ্যতা (interior mutability) দেয় — বাইন্ডিং অপরিবর্তনীয় থাকলেও সেলের ভেতরের মান বদলায়। ইভেন্ট হ্যান্ডলার (§১৫, `engine.md` §৭) এভাবেই UI স্টেট আপডেট করে।

উদাহরণ

```kolom
লেখো(দৈর্ঘ্য("রহিম"))

লেখো(দৈর্ঘ্য([১, ২, ৩]))
```

# ২২. ওনারশিপ ও মেমরি মডেল

কলম কোনো গার্বেজ কালেক্টর (GC) ব্যবহার করে না। এর বদলে, একটি সহজ **ওনারশিপ ও মুভ (move)**-ভিত্তিক মডেল ব্যবহার করা হয়, যা মেমরি নিরাপত্তা নিশ্চিত করে predictable, deterministic পারফরম্যান্সসহ — Rust-এর ওনারশিপ ধারণা থেকে অনুপ্রাণিত, কিন্তু Rust-এর borrow checker বা lifetime অ্যানোটেশন ছাড়াই, যাতে ভাষাটি সহজপাঠ্য ও শেখার উপযোগী থাকে।

## ২২.১ কপি টাইপ বনাম মুভ টাইপ

| ধরন | টাইপ | আচরণ |
|------|------|--------|
| কপি (Copy) | `সংখ্যা`, `দশমিক`, `বুলিয়ান`, `অক্ষর`, `ফাঁকা` | অ্যাসাইনমেন্টে সবসময় কপি হয়; দুটি বাইন্ডিংই বৈধ থাকে |
| মুভ (Move) | `লেখা`, `Type[]` | অ্যাসাইনমেন্টে ওনারশিপ স্থানান্তরিত হয়; উৎস বাইন্ডিং আর ব্যবহারযোগ্য থাকে না |
| শেয়ার্ড (Shared) | `শেয়ার Type` (§১১.৫) | অ্যাসাইনমেন্টে হ্যান্ডেল কপি হয় (রেফারেন্স কাউন্ট বৃদ্ধি পায়); উভয় বাইন্ডিংই বৈধ থাকে |

## ২২.২ মুভ সিমান্টিক্স

একটি মুভ-টাইপ ভ্যালু আরেকটি ভ্যারিয়েবলে অ্যাসাইন করলে, উৎস ভ্যারিয়েবলটি আর ব্যবহার করা যায় না —

```kolom
ধরি ক = "রহিম"

ধরি খ = ক

লেখো(ক)
```

```text
ত্রুটি

'ক' ইতিমধ্যে 'খ'-তে মুভ হয়ে গেছে।

মুভ হওয়ার পর 'ক' ব্যবহার করা যাবে না।
```

স্বাধীন কপি প্রয়োজন হলে `কপি(x)` ব্যবহার করুন —

```kolom
ধরি ক = "রহিম"

ধরি খ = কপি(ক)

লেখো(ক)
লেখো(খ)
```

## ২২.৩ ফাংশন কল-এ ওনারশিপ

একটি ফাংশনে আর্গুমেন্ট হিসেবে ভ্যালু পাঠালে ওনারশিপ স্থানান্তরিত হয় **না** — কলার (caller) সবসময় কল শেষে তার ভ্যারিয়েবলের ওনারশিপ ফেরত পায়। এর ফলে সাধারণ ফাংশন কল (যেমন `দৈর্ঘ্য(নাম)`) কখনো `নাম`-কে অকার্যকর করে না, এবং প্রোগ্রামারকে borrow-এর মতো কোনো সিনট্যাক্স মনে রাখতে হয় না —

```kolom
ফাংশন দেখাও(লেখা বার্তা) -> ফাঁকা {

    লেখো(বার্তা)

}

অ্যাপ {

    ধরি নাম = "রহিম"

    দেখাও(নাম)

    লেখো(নাম)

}
```

## ২২.৪ শেয়ার্ড ওনারশিপ (`শেয়ার`)

একাধিক দীর্ঘস্থায়ী মালিকানা সত্যিকারে প্রয়োজন হলে (যেমন — একই স্টেট একাধিক UI উইজেট বা কলব্যাক থেকে ব্যবহার করা), `শেয়ার Type` ব্যবহার করুন —

```kolom
ধরি গণনা: শেয়ার সংখ্যা = শেয়ার_করো(০)

ধরি অন্য_নাম = গণনা

লেখো(অন্য_নাম)
```

স্টেট প্যাটার্ন (UI হ্যান্ডলারসহ পূর্ণ উদাহরণ — `engine.md` §৫) —

```kolom
ধ্রুবক গণনা: শেয়ার সংখ্যা = শেয়ার_করো(০)

ফাংশন বাড়াও() -> ফাঁকা {
    বসাও(গণনা, মান(গণনা) + ১)
}

অ্যাপ {
    ডিসপ্লে {
        টেক্সট(লেখায়(মান(গণনা)))
        বাটন("+১", বাড়াও)
    }
}
```

বাইন্ডিং `ধ্রুবক` হলেও সেলের ভেতরটা `বসাও` দিয়ে বদলায় — এটিই UI স্টেটের সরকারি প্যাটার্ন।

বিস্তারিত গ্রামারের জন্য দেখুন `grammer.md` §১১.৫। রানটাইমে `শেয়ার Type` কীভাবে বাস্তবায়িত হয় তার জন্য দেখুন `compiler.md` §১০।

# ২৩. তথ্য (Custom Types)

`তথ্য` একটি নির্দিষ্ট সেট ফিল্ড সহ নিজস্ব টাইপ ঘোষণা করে —

```kolom
তথ্য ব্যক্তি {
    নাম: লেখা,
    বয়স: সংখ্যা
}
```

**তৈরি করা** — স্ট্রাক্টের নামই কনস্ট্রাক্টর, ফিল্ডগুলো ঘোষণার ক্রমে পজিশনালি দিয়ে —

```kolom
ধরি প = ব্যক্তি("রহিম", ২৫)
```

আর্গুমেন্টের সংখ্যা ও প্রতিটির টাইপ অবশ্যই মিলতে হবে, নয়তো কম্পাইল-টাইম ত্রুটি।

**পড়া ও লেখা** — `.` দিয়ে —

```kolom
লেখো(প.নাম)

প.বয়স = ২৬
```

**ফাংশনে ব্যবহার** — একটি `তথ্য`-এর নাম অন্য যেকোনো টাইপের মতোই প্যারামিটার বা রিটার্ন টাইপ হতে পারে —

```kolom
ফাংশন সরাও(বিন্দু প, সংখ্যা দূরত্ব) -> বিন্দু {

    রিটার্ন বিন্দু(প.ক + দূরত্ব, প.খ + দূরত্ব)

}
```

**নেস্টেড স্ট্রাক্ট** — একটি ফিল্ড অন্য একটি `তথ্য` টাইপ হতে পারে, এবং `.` চেইন করে গভীরের ফিল্ড পড়া যায় —

```kolom
তথ্য ঠিকানা { শহর: লেখা, কোড: সংখ্যা }

তথ্য ব্যক্তি { নাম: লেখা, বাসা: ঠিকানা }

অ্যাপ {

    ধরি প = ব্যক্তি("রহিম", ঠিকানা("ঢাকা", ১২০৭))

    লেখো(প.বাসা.শহর)

}
```

একটি স্ট্রাক্ট নিজেকে সরাসরি বা একাধিক ফিল্ডের চেইন দিয়ে *by value* ধারণ করতে পারে না — সেই টাইপের আকার তখন অসীম হয়ে যেত। `শেয়ার`, অ্যারে, বা `ম্যাপ` ফিল্ডের মাধ্যমে নিজেকে ধারণ করা বৈধ (এগুলো পয়েন্টার), আর এভাবেই লিংকড লিস্ট বা ট্রি-র মতো রিকার্সিভ তথ্য তৈরি হয় —

```kolom
তথ্য নোড {
    মান: সংখ্যা,
    পরের: শেয়ার নোড
}
```

সম্পূর্ণ গ্রামারের জন্য দেখুন `grammer.md` §১০.৫।

# ২৪. ম্যাপ (Maps)

`ম্যাপ[K, V]` key থেকে value-এ ম্যাপিং রাখে। কোনো লিটারেল সিনট্যাক্স নেই — একটি খালি ম্যাপ তৈরি হয় `ম্যাপ_তৈরি()` দিয়ে, যার নিজের কোনো টাইপ তথ্য বহন করে না বলে টাইপ-টীকা আবশ্যক —

```kolom
ধরি বয়সসমূহ: ম্যাপ[লেখা, সংখ্যা] = ম্যাপ_তৈরি()
```

key টাইপ অবশ্যই `লেখা` বা `সংখ্যা` হতে হবে; value যেকোনো টাইপ হতে পারে।

**লেখা ও পড়া** — `[]` দিয়ে, অ্যারের মতোই —

```kolom
বয়সসমূহ["রহিম"] = ২৫

লেখো(লেখায়(বয়সসমূহ["রহিম"]))
```

অ্যারের বিপরীতে, ম্যাপে ইনডেক্স-অ্যাসাইনমেন্ট সবসময় বৈধ — নতুন key হলে ইনসার্ট করে, বিদ্যমান হলে আপডেট করে। একটি অনুপস্থিত key পড়া একটি রানটাইম ত্রুটি — `চেষ্টা`/`ধরো` দিয়ে ধরা যায় (§২৫)।

**অন্যান্য অপারেশন** —

```kolom
লেখো(লেখায়(দৈর্ঘ্য(বয়সসমূহ)))

লেখো(লেখায়(আছে_কি(বয়সসমূহ, "রহিম")))

ধরি keys = চাবি_গুলো(বয়সসমূহ)

চাবি_মুছো(বয়সসমূহ, "রহিম")
```

`দৈর্ঘ্য`, `আছে_কি`, `চাবি_গুলো`, `চাবি_মুছো` — সবই গ্লোবাল বিল্ট-ইন ফাংশন (§২১), `ম্যাপ`-এর মেম্বার নয়।

সম্পূর্ণ গ্রামারের জন্য দেখুন `grammer.md` §১১.৬।

# ২৫. ত্রুটি হ্যান্ডলিং (`চেষ্টা` / `ধরো`)

কলম-এ কোনো `throw`/`raise` স্টেটমেন্ট নেই — প্রোগ্রামার নিজে কোনো ত্রুটি তৈরি করতে পারে না। যা `চেষ্টা` দিয়ে ধরা যায় তা সম্পূর্ণভাবে রানটাইম নিজে তোলে —

- ফাইল বা নেটওয়ার্ক I/O ব্যর্থতা
- শূন্য দিয়ে ভাগ (`/` বা `%`)
- অ্যারে ইনডেক্স সীমার বাইরে
- অনুপস্থিত `ম্যাপ` key পড়া

```kolom
ইম্পোর্ট ফাইল

অ্যাপ {

    চেষ্টা {

        ধরি content = ফাইল.পড়ো("নেই_এমন_ফাইল.txt")

        লেখো(content)

    } ধরো(ত) {

        লেখো("ধরা হয়েছে:")

        লেখো(ত)

    }

}
```

`চেষ্টা`-র `Block`-এর ভেতরে একটি ব্যর্থতা ঘটলে, নিয়ন্ত্রণ তৎক্ষণাৎ `ধরো(...)`-এর `Block`-এ চলে যায় — ব্যর্থতার বার্তা কোষ্ঠবন্ধনীর ভেতরের নামে (`লেখা` টাইপ) বাউন্ড হয়ে। ব্যর্থতা না ঘটলে `ধরো` ব্লক চলেই না।

`চেষ্টা` ব্লকের বাইরে একই ব্যর্থতা প্রোগ্রাম বন্ধ করে দেয়, স্পষ্ট বাংলা বার্তাসহ — যেমন অনির্দিষ্টভাবে ধরা ছাড়া প্রতিটি রানটাইম ত্রুটির ক্ষেত্রেই হয়।

`চেষ্টা` কোনো লুপের ভেতরে থাকা আবশ্যক নয় — `বিরতি`/`চলবে`-এর বিপরীতে (§১৩)।

সম্পূর্ণ গ্রামারের জন্য দেখুন `grammer.md` §১২.৮।
